## Graphify

### v0.8.20 -> v0.8.21

版本结论：`ENTRYPOINT.md` 当前版本为 `v0.8.20`，GitHub Releases 当前最新稳定版为 `v0.8.21`。

Release 汇总：

- `graphify update` 的 ghost node 修复：全量重新抽取现在会按磁盘状态协调图谱，并清理已删除文件对应的节点，不再需要依赖 `--changed` 标志处理这类清理。
- OpenCode `--project` 路径修复：Graphify skill 现在写入 `.opencode/skills/graphify/SKILL.md`，不再写入错误的 `.config/opencode/skills/`。
- post-commit hook 循环修复：当只有 `graphify-out/` 文件变化时，hook 会跳过；可用 `GRAPHIFY_SKIP_HOOK=1` 做一次性跳过；重建日志改为追加而不是覆盖。
- 确定性输出：边排序，并在 hook 中使用 `PYTHONHASHSEED=0`，减少 `graphify-out/` 在重复运行时的无意义 churn。
- 查询修复：搜索会剥离标点，类似 `what calls extract?` 的查询可以正确匹配 `extract` 节点。
- 内置函数节点修复：`String()`、`Number()`、`Boolean()`、`print()`、`len()` 等内置函数不再累积伪造调用边。
- 新增 Amp 平台支持：`graphify amp install/uninstall` 会写入 `.amp/skills/graphify/SKILL.md`。
- 新增 SystemVerilog header 支持：`.svh` 会与 `.v`、`.sv` 一起抽取。

破坏性变更：release notes 未标记破坏性变更。OpenCode skill 的目标路径修复可能影响此前依赖错误 `.config/opencode/skills/` 路径的本地安装，需要重新安装或手动迁移到 `.opencode/skills/graphify/SKILL.md`。

迁移说明：按 release notes 执行 `pip install --upgrade graphifyy` 或 `uv add graphifyy`。如果项目使用 OpenCode 或 Amp 平台集成，升级后检查生成的 skill 路径是否符合新的平台目录；如果项目使用 post-commit hook，遇到一次性重建循环可用 `GRAPHIFY_SKIP_HOOK=1` 跳过并检查 hook 日志。

对 agent harness workflow 的影响分析：本地关键词扫描命中 `agents/AGENTS.project.md` 的 Graphify 规则。本轮已最小化更新该项目模板，使真实项目在维护 Graphify 图谱时明确使用 `graphify update .` 做删除协调，遇到 hook 循环时使用一次性环境变量处理，并把 `.svh` 纳入 HDL 抽取范围。根 `AGENTS.md`、`agents/AGENTS.global.md` 和 `skills/**/SKILL.md` 没有需要同步修改的 Graphify 操作规则。

- https://github.com/safishamsi/graphify/releases
