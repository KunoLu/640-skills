## Trellis

### v0.6.6 -> v0.6.7

- 最新 stable 判定：GitHub Releases 仍为空；GitHub tags 最新 stable 为 `v0.6.7`；npm `@mindfoldhq/trellis` 的 `latest` dist-tag 为 `0.6.7`。
- prerelease 观察：npm `beta` 仍为 `0.6.0-beta.23`，`rc` 仍为 `0.6.0-rc.0`；由于当前版本是 stable 且策略为 `stable-only`，本轮忽略 beta / rc 通道。
- release 汇总：`v0.6.7` 是非 breaking patch，核心主题是 filesystem-safety 和状态持久化加固：Channel / worker 名称增加 safe path segment 校验并跳过旧非法目录；生成文件、template hashes、registry config、task state、session pointer 改为 atomic write；模板 overwrite 改为先下载到 temp 再替换；uninstall 保留 `AGENTS.md` 中 Trellis managed block 外的用户内容，并在 scripted `--yes` 删除 `.trellis/` 前检查未提交 spec / task / workspace 数据；`task.py archive` 拒绝移动非 task 目录；legacy traces-to-journal rename 不覆盖已存在 journal；rename-dir 仅自动移动 manifest 能证明由 Trellis 创建的目录；Pi mem 支持项目级 `.pi/settings.json` 与相对 `sessionDir`。
- 补充证据：GitHub release body 缺失；GitHub compare `v0.6.6...v0.6.7` 显示 20 commits，涉及 `.trellis/scripts/common/io.py`、`task_store.py`、`task_utils.py`、`packages/cli/src/utils/atomic-write.ts`、`template-fetcher.ts`、`template-hash.ts`、`uninstall.ts`、`update.ts`、Channel path helpers、Pi mem paths，以及新增 filesystem-safety spec 和多组回归测试；`packages/cli/src/migrations/manifests/0.6.7.json` 存在，标记 `breaking: false`、`recommendMigrate: false`、`migrations: []`，notes 要求升级后运行 `trellis update` 刷新生成脚本和 filesystem-safety 行为；npm metadata 确认 tarball、bin、fileCount 和 integrity；`npm pack --dry-run` 确认发布包包含 `dist/utils/atomic-write.*`、`dist/templates/trellis/scripts/common/io.py`、`dist/templates/trellis/scripts/common/task_store.py`、`dist/templates/trellis/scripts/common/task_utils.py` 等生成资产。
- 破坏性变更：manifest 标记非 breaking；没有要求 `trellis update --migrate`，但升级后应运行普通 `trellis update` 刷新生成脚本和安全 guard。
- 迁移说明：不执行 `trellis update --migrate`，除非项目另有 migration manifest / conflict 提示；已有 `.trellis/` 的项目升级 CLI 后先运行 `trellis update` 并复核 diff，再依赖 `task.py`、Channel、update 或 uninstall 行为。
- 对 agent harness workflow 的影响分析：本轮扫描了 `atomic`、`path traversal`、`channel name`、`worker name`、`uninstall`、`dirty`、`task archive`、`template overwrite`、`traces`、`journal`、`rename-dir`、`Pi session`、`sessionDir`、`filesystem safety`、`trellis update`、`trellis uninstall` 等关键词。现有模板已有 `trellis update` 升级刷新规则和部分 Channel 缺失 agent 定义处理，但未明确 filesystem-safety / destructive-op guard 边界；因此本轮最小化更新了 `AGENTS.global.md`、`AGENTS.project.md`、`trellis-workflow` Skill、`trellis-channel` Skill，以及同步展示用 `README.md` / `README.html`。其中全局模板保留完整通用边界，项目级模板只保留对全局 Trellis filesystem-safety 规则的项目级承接，Skill 承接具体 runbook，沉淀为长期通用规则：升级后刷新生成脚本和 safety guard；不要绕过 dirty-data、manifest ownership、safe-name guard；Channel / worker 名称使用安全路径片段。
