## Trellis

### v0.6.0-beta.18 -> v0.6.0-beta.20

本次 `ENTRYPOINT.md` 基线为 `v0.6.0-beta.18`，版本通道策略为 `same-prerelease-channel`。GitHub Releases 页面没有正式 release；联网查询 GitHub tags 确认同一 `v0.6.0-beta.x` 通道存在 `v0.6.0-beta.19` 与 `v0.6.0-beta.20`，因此本次比较终点为 `v0.6.0-beta.20`。

破坏性变更：如果项目直接依赖 Pi 扩展中旧名 `subagent`，需要切换到 `trellis_subagent`。本仓库当前没有 `.trellis/`、`.trellis/workflow.md` 或 Pi 扩展配置，因此未检测到需要本地迁移的文件。

迁移说明：升级 Trellis beta 后，如项目实际启用 `.trellis/`，应运行官方建议的 `trellis update` 并检查生成的 Channel/Pi 扩展文件；每日自动化不主动初始化或修改 `.trellis/`。

依据：GitHub Releases `mindfold-ai/Trellis` 无 release；GitHub tags 存在 `v0.6.0-beta.20`；GitHub compare API `v0.6.0-beta.18...v0.6.0-beta.20`。

## Graphify

### v0.8.13 -> v0.8.14

本次 `ENTRYPOINT.md` 基线为 `v0.8.13`，版本通道策略为 `stable-only`。GitHub Releases 页面显示 `0.8.14` 为 Latest，因此本次比较终点为 `v0.8.14`。

Release 汇总：`0.8.14` 修复 wiki 在 dedup 或重新抽取后遇到过期 node ID 时崩溃的问题；当没有 `.graphifyignore` 时，现在会回退遵守 `.gitignore`，两者同时存在时 `.graphifyignore` 仍优先；新增 `--exclude` CLI 参数，可在运行时追加 gitignore 风格排除规则；`.worktrees/` 目录不再被索引为重复源码；修复 IPv6-only 网络下 NAT64 地址被误判为保留地址导致的 SSRF false positive。

破坏性变更：未发现破坏性变更。忽略规则优先级需要注意：存在 `.graphifyignore` 时仍以 `.graphifyignore` 为准；没有时才回退 `.gitignore`。

迁移说明：如果本仓库后续运行 `graphify extract .` 或 `graphify update .`，可依赖 `.gitignore` 回退排除 `.gitnexus/`、`.trellis/` 等目录；临时排除项优先使用 `--exclude`，避免为了单次任务修改长期忽略文件。

对 agent harness workflow 的影响分析：Graphify 更新后的忽略规则更适合当前仓库，因为 `.gitignore` 明确包含 `.gitnexus/` 与 `.trellis/`。本次据此最小化更新项目 Graphify 使用规则，不修改 `ENTRYPOINT.md` 版本字段。

依据：GitHub Releases `safishamsi/graphify`，`0.8.14` 标记 Latest，Release notes 列出 wiki crash、`.gitignore` fallback、`--exclude`、`.worktrees/` skip 和 NAT64 SSRF false-positive 修复。
