## Graphify
### v0.8.17 -> v0.8.18

来源：

- GitHub Releases: https://github.com/safishamsi/graphify/releases
- GitHub Tags: https://github.com/safishamsi/graphify/tags

Release 汇总：

- 最新稳定 release 为 `v0.8.18`。
- 修复 post-commit hook 在 delete-only commit 后更新图谱时被 shrink-guard 阻止的问题；当 changed paths 包含显式删除时会绕过 shrink-guard。
- 修复 `graphify export` 在缺少 `.graphify_analysis.json` 时退化为 `Single community` 的问题；现在会从 `graph.json` 的每个节点 `community` 属性回退读取社区信息。
- `references` 边新增语义上下文标签，覆盖 Python / JS / TS / C# / Java 的 `parameter_type`、`return_type`、`generic_arg`、`attribute`、`field`。
- C# / Java 继承关系进一步拆分为 `inherits` / `implements`。
- 破坏性变化：Java `extends` 边被重命名为 `inherits`；筛选 Java 节点 `relation="extends"` 的查询需要更新。
- constrained query expansion 会先提取真实图谱词汇，再约束 LLM 只能从该词汇集选择扩展 token；同时修复 Unicode regex，能捕获 Cyrillic / CJK labels。

破坏性变更：

- Java 继承关系查询存在明确破坏性变化：旧的 `relation="extends"` 过滤条件应改为 `relation="inherits"`，并按场景区分 `implements`。

迁移说明：

- 使用 Graphify 查询 Java 继承关系时，不要再假设 `extends` 是稳定 relation；应先通过 query/export 检查图谱实际 relation vocabulary，再使用 `inherits` / `implements`。
- 如果 workflow 或自动化依赖 `graphify export` 的 community 结果，可以接受没有 `.graphify_analysis.json` 时的新 fallback 行为，但仍应在重要结论前核对 `graph.json`。
- 依赖 `references` 边做影响分析时，应优先读取可用的语义上下文标签，区分参数类型、返回类型、泛型参数、属性和字段引用。

对 agent harness workflow 的影响分析：

- 本地关键词扫描命中 `agents/AGENTS.project.md` 的 Graphify 使用规则；未命中根 `AGENTS.md`、`agents/AGENTS.global.md` 或 `skills/**/SKILL.md` 中需要同步修改的 Graphify 查询细则。
- 已最小化更新 `agents/AGENTS.project.md`：补充 Graphify 查询时应以实际 relation vocabulary 为准、区分 `inherits` / `implements`，以及使用 `references` 语义上下文标签辅助影响分析。
- 不修改 `ENTRYPOINT.md` 中 Graphify 的当前版本；该写回只能由用户手动输入 `更新` 或 `update` 触发。
