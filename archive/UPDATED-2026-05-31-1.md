## Graphify

### v0.8.22 -> v0.8.26

版本结论：`ENTRYPOINT.md` 当前记录为 `v0.8.22`，策略为 `stable-only`。GitHub Releases 显示最新稳定版为 `v0.8.26`，因此本次区间固定为 `v0.8.22 -> v0.8.26`。GitHub Tags 中还存在 `v1.0.0` 标签，但它没有对应 GitHub Release，且指向 2026-04-05 的旧提交，不作为本次 release 线终点。

Release 汇总：

- `v0.8.23`：为 Swift、Kotlin、PHP、Rust、Go 增加跨语言 `references` 类型引用边，并带有 `parameter_type`、`return_type`、`generic_arg`、`field`、`attribute` 等上下文；同时把继承关系拆成 `inherits` 与 `implements`。开发和 CI 流程转向 `uv`，并提交 `uv.lock` 以提高可复现性。
- `v0.8.24`：继续扩展 ObjC、Julia、C、C++、Scala、Fortran、PowerShell 的 `references` 类型引用边；修复 `claude-cli` 空流/空 JSON/缺少 result/空 result 等 hollow response 循环；修复无向图构建时双向节点对导致 `calls` 边方向翻转；修正多平台 Skill 中 `.graphify_python` 路径，并让 Skill 优先用 `uv tool run graphifyy python` 检测解释器。
- `v0.8.25`：修复 JS/TS/TSX 中箭头函数回调里的 `const`/`let` 被误建成节点、Markdown fenced code block 产生无语义 `codeblock_N` 节点、Lua `require("pkg.sub")` 文件解析、Windows `claude-cli` 命令选择、快速连续提交导致 post-commit hook 静默丢失 changed paths，以及 Antigravity install path。README 也将 Mac/Windows 上的 `pip install` 环境错配风险写明，并推荐 `uv tool install` / `uv tool upgrade` 作为主路径。
- `v0.8.26`：`GRAPH_REPORT.md` 新增 `Import Cycles` 区段，用文件级 import graph 和 Johnson 算法列出循环依赖，并提供 `find_import_cycles(G)` 程序接口；新增 `graphify provider add/list/show/remove` 自定义 OpenAI-compatible provider registry，配置保存在 `~/.graphify/providers.json`，并按检测优先级避免覆盖已配置的付费 key；`extract_files_direct(backend=None)` 改为调用 `detect_backend()`，不再静默默认到 kimi；修复 `pnpm-workspace.yaml` 单包根目录导致 JS/TS 文件被跳过的问题，新增 `GRAPHIFY_DEBUG=1` 输出完整 traceback；修复 `.graphifyignore` 中锚定规则误匹配深层目录的问题。

破坏性变更：

- 未看到需要立即迁移本仓库文件结构的破坏性变更。
- 对已有 Graphify 图谱而言，旧版本可能已包含 JS/TS phantom nodes、Markdown orphan nodes、Lua import 错误、`calls` 边方向错误、缺少新的 `references` 上下文，或没有 `Import Cycles` 循环依赖区段。涉及这些关系的旧图谱结论需要重建或用源码交叉验证。

迁移说明：

- 安装或升级 Graphify 时，优先采用 `uv tool upgrade graphifyy`；新装可采用 `uv tool install graphifyy`。如果使用 `pipx`，也应确认 CLI、hook 和 Skill 运行在同一解释器环境。
- 在 Mac/Windows 上不应默认用裸 `pip install` 作为唯一安装路径，以免 Python 环境错配造成 `ModuleNotFoundError`。
- 如果项目已维护 `graphify-out/`，升级后应运行 `graphify update .` 或按当前 CLI help 执行强制重建，再使用图谱结论做影响分析。
- 如果需要自定义 Graphify LLM provider，使用 `graphify provider add/list/show/remove` 管理；不要把 `~/.graphify/providers.json`、API key 或本地 provider 配置写入仓库。
- 如果抽取过程只给出简短 warning、JS/TS 工作区文件异常缺失，或 `.graphifyignore` 锚定规则行为不符合预期，先用 `GRAPHIFY_DEBUG=1` 和源码/文件列表交叉验证。
