# UPDATE

## Codex

### v0.137.0 -> v0.138.0

来源与版本判断：

- GitHub Releases 显示稳定版 [`rust-v0.138.0`](https://github.com/openai/codex/releases/tag/rust-v0.138.0) 已发布，release 名称为 `0.138.0`，`prerelease=false`，发布时间为 `2026-06-08T23:00:27Z`。
- GitHub 同时存在 `rust-v0.139.0-alpha.1` 等预发布版本；由于 `ENTRYPOINT.md` 对 Codex 的策略是 `stable-only`，本次只比较稳定版。
- npm metadata 中 `@openai/codex` 的 `latest` dist-tag 为 `0.138.0`，与 GitHub 稳定 release 一致；`alpha` dist-tag 为 `0.139.0-alpha.1`，按策略忽略。
- 对比区间为 [`rust-v0.137.0...rust-v0.138.0`](https://github.com/openai/codex/compare/rust-v0.137.0...rust-v0.138.0)。

Release 汇总：

- CLI 到桌面端的衔接增强：`/app` 命令现在可以把当前 CLI thread 交接到 macOS 和原生 Windows 的 Codex Desktop，Windows workspace 也可以直接通过 Desktop 打开。
- 本地图片附件和独立图片生成会把已保存文件路径暴露给模型，后续图片编辑、文件引用和继续处理更可靠。
- reasoning effort 选择更灵活：TUI 增加终端漏掉 `Alt` 绑定时的 fallback 快捷键，并按模型声明顺序呈现模型定义的 effort levels。
- app-server / auth 能力增强：集成方可以读取账号 token usage，CLI 与 app-server auth 支持 v2 personal access tokens。
- plugin 自动化输出更完整：plugin add/remove 与 marketplace 命令支持 `--json`，plugin list JSON 包含 marketplace source，plugin detail 暴露 default prompts、remote MCP servers 和 unavailable app templates。
- `/goal` 行为更稳定：`/goal edit` 多行粘贴不会提前提交，Plan mode 中不会触发 idle auto-turn，terminal turn 失败后 goal 不再自动继续。
- TUI 与启动可靠性改进：streaming 时减少额外空行，取消的 prompt 会恢复到末尾光标；config 写入失败会显示底层原因；启动路径支持 `/usr/bin/bash`、更短 Linux proxy socket path，并会在启动前刷新过期的 OAuth-backed MCP credentials。
- workspace 指令加载更准确：远程和 symlink workspace 下会更一致地拾取正确的 `AGENTS.md`。
- 维护类改进包括刷新 CLI README、复用 plugin discovery 结果降低 TUI 启动开销、`resume --last` 优先通过 state DB 找最新 session，以及优化大型 MCP/Ollama stream 和长历史消息扫描。

破坏性变更：

- release notes 未标明显式 breaking change。
- 本次包含内部协议、plugin、app-server、permission / sandbox、goal runtime 等多处改动，但 release body 未要求用户修改现有配置或迁移项目文件。

迁移说明：

- 普通用户按既有 Codex 升级流程升级即可。
- 如果已有脚本解析 Codex plugin 命令输出，可以考虑改用新的 `--json` 输出以降低文本解析风险；这属于可选改进，不是本仓库当前自动化的必需迁移。
- 如果使用 v2 personal access tokens、Codex Desktop handoff 或 app-server account token usage，需要按实际产品环境验证 auth、Desktop 和 app-server 集成行为；本仓库没有保存相关凭据或 app-server 配置。

对 agent harness workflow 的影响分析：

- 命中扫描：本次用 `/app`、`app-server`、`personal access`、`reasoning effort`、`plugin`、`marketplace`、`--json`、`AGENTS.md`、`workspace instruction`、`goal`、`remote-control`、`MCP`、`OAuth`、`resume --last`、`permission profile`、`sandbox`、`multi-agent` 等关键词扫描了 `AGENTS.md`、`agents/AGENTS.global.md`、`agents/AGENTS.project.md` 和 `skills/**/SKILL.md`。
- 处理决定：现有长期规则已经覆盖 AGENTS 优先级、MCP 可用性判断、权限 / sandbox 审慎使用、plugin / connector 安装边界、Trellis / GitNexus / TestSprite 可用性判断等行为；Codex 本次改进不要求修改这些通用规则。
- `plugin --json` 是值得后续脚本优先采用的能力，但本仓库当前没有维护 Codex plugin 自动化脚本，因此不新增长期规则，避免把 release 细节写入可复用模板。
- `/app` 桌面 handoff、v2 personal access tokens、account token usage 和图片路径暴露都是可选能力或可靠性改进，不改变每日版本检查自动化、同步流程或本仓库 Skill 使用边界。
- 因此本次只刷新 `UPDATE.md`，不修改 `AGENTS.md`、`agents/AGENTS.global.md`、`agents/AGENTS.project.md` 或 `skills/**/SKILL.md`。
