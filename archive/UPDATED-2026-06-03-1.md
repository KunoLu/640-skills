## Graphify

### v0.8.28 -> v0.8.30

#### 版本结论

- `ENTRYPOINT.md` 当前版本为 `v0.8.28`，版本通道策略为 `stable-only`。
- GitHub latest stable release 为 `v0.8.30`，发布时间为 2026-06-02T23:26:30Z。
- 本次跨越稳定版本 `v0.8.29` 和 `v0.8.30`，已汇总两个版本的 release notes。

#### Release 汇总

`v0.8.29`：

- Graphify Skill 安装形态改为 progressive-disclosure：常用 `SKILL.md` 变为更轻的核心文件，按需引用 `references/` sidecar；多个平台的 Skill 和 sidecar 由同一生成源维护，并通过 CI guard 校验切片一致性。
- 修复 `graphify install --platform gemini` 后 `SKILL.md` 中 `references/` 指针失效的问题，安装时会复制所需 sidecar。
- 安全行为变更：项目本地 `./.graphify/providers.json` 不再自动加载；如确实依赖项目本地 provider 配置，必须显式设置 `GRAPHIFY_ALLOW_LOCAL_PROVIDERS=1`。
- provider 安全加强：非 `http(s)` 的 `base_url` 会被拒绝，明文 HTTP 会警告；`OLLAMA_BASE_URL` 指向 link-local 或云 metadata 地址时会失败关闭。
- Office / PDF 输入解析前增加大小与流式解压上限，降低 zip bomb 造成内存耗尽的风险。
- Fortran C-preprocessor 步骤改用绝对路径，避免语料文件名被解释为 `cpp` 选项。

`v0.8.30`：

- 修复 `graphify install --project --platform antigravity`：项目级安装现在会写入 Antigravity always-on layer，包括 `.agents/rules/graphify.md` 和 `.agents/workflows/graphify.md`，而不只是安装 Skill。
- 新增 Read / Glob 相关 `PreToolUse` nudge：当项目已有 `graphify-out/graph.json` 且读取源文件或文档时，会提示优先使用 `graphify query`；该提示不阻塞执行。
- 新增 `anthropic` optional extra，并纳入 `[all]`；使用 claude backend 时可通过 `uv tool install "graphifyy[anthropic]"` 安装依赖，backend 缺包错误也会指向 isolated-venv 的 `uv tool install "graphifyy[<extra>]"` 路径。

#### 破坏性变更

- `v0.8.29` 对项目本地 provider 配置有行为变更：`./.graphify/providers.json` 默认不再自动加载。依赖项目本地 provider 的场景需要显式设置 `GRAPHIFY_ALLOW_LOCAL_PROVIDERS=1`，并重新确认数据驻留和 API key 发送目标。
- provider `base_url` 的协议和目标地址校验更严格；指向 link-local 或云 metadata 地址的 `OLLAMA_BASE_URL` 会被拒绝。

#### 迁移说明

- 如果使用项目本地 `.graphify/providers.json`，应优先迁移到用户级 `~/.graphify/providers.json`；确需项目本地配置时，显式设置 `GRAPHIFY_ALLOW_LOCAL_PROVIDERS=1` 并审查 `base_url`。
- 如果使用 claude / Anthropic backend，使用 `uv tool install "graphifyy[anthropic]"` 或 `[all]` 重新安装，避免 backend 包缺失。
- 如果使用 Antigravity 项目级安装，重新执行安装后确认 always-on layer 与 Skill 都存在。
- 如果检查已安装 Graphify Skill，看到核心 `SKILL.md` 旁边的 `references/` sidecar 属于预期结构；缺失 sidecar 时应重新安装或重新生成。

#### 对 agent harness workflow 的影响分析

- 本地规则扫描范围：`AGENTS.md`、`agents/AGENTS.global.md`、`agents/AGENTS.project.md`、`skills/**/SKILL.md`。
- 命中情况：`agents/AGENTS.project.md` 已包含 Graphify 的安装、provider、自定义 backend、optional extra、hook 和安装平台边界；未发现仓库内自维护 Graphify Skill。
- 处理决定：最小化更新 `agents/AGENTS.project.md` 的 Graphify 规则，补充项目本地 provider opt-in、安全校验、progressive references、Anthropic extra、Read / Glob 非阻塞 nudge，以及 Antigravity project install always-on layer 校验。
- `AGENTS.md` 与 `agents/AGENTS.global.md` 只保留高层启用边界，本次不写入 Graphify 细节。
- `skills/**/SKILL.md` 中没有 Graphify Skill，本次不修改。
