# UPDATE

## Codex

### v0.141.0 -> v0.142.0

#### 版本来源

- GitHub Release：<https://github.com/openai/codex/releases/tag/rust-v0.142.0>
- GitHub Compare：<https://github.com/openai/codex/compare/rust-v0.141.0...rust-v0.142.0>
- npm `@openai/codex`：`latest = 0.142.0`，`alpha = 0.143.0-alpha.3`。本仓库策略为 `stable-only`，因此忽略 `0.143.0-alpha.*`。

#### Release 汇总

- `/usage` 增加 earned usage-limit reset credits 的展示与兑换流程，并包含确认、重试和刷新可用状态。
- `/plugins` 将远程插件整理为 OpenAI Curated、Workspace、Shared with me 三类，并允许符合条件的 turn 推荐和安装相关插件。
- 增加可配置 rollout token budgets，可跨 agent threads 追踪预算、提醒剩余量，并在预算耗尽时终止 turn。
- App-server client 可在线程和 turn 级别配置 multi-agent delegation：禁用、仅显式请求、或主动模式。
- 增加 indexed web-search mode：允许 live search，同时把直接页面访问限制在 server-approved URL 范围内。
- Codex 可接收 scheduled UTC time reminders，也能通过 client-provided app-server clock 查询当前时间。
- 修复 Linux TUI `Ctrl+Z` / `fg` 恢复后的渲染问题；改进 exec-server 与 stdio MCP session 在断连、signed URL 刷新、stdin 重试时的恢复能力。
- Remote environments 现在更可靠地保留 executor-native path、shell、`AGENTS.md` discovery 和 sandbox 行为。
- Plugin loading / installation 增强了 root marketplace layout、manifest fallback、多 skill path、下载错误和工具即时刷新处理。
- Parent agent 现在能收到 terminal subagent errors，避免把失败的子任务误视为空成功。
- Goal-first threads 恢复持久化，并可通过 `thread/list` 与 `thread/search` 返回。

#### 破坏性变更

- Release notes 未标记破坏性变更。
- 需要注意的行为变化主要是 plugin 推荐 / 安装能力、multi-agent delegation 模式、rollout budget、indexed web search 与 time reminder 这些新能力会影响 agent harness 的可用工具面和状态管理。

#### 迁移说明

- 普通升级按 Codex 发布渠道更新即可；本仓库每日自动化不写回 `ENTRYPOINT.md`。
- 如果运行环境使用 Codex 的插件推荐 / 安装能力，仍需遵守当前 harness 的明确授权边界：不要把推荐视为已安装，不要为相邻能力静默安装插件或连接器。
- 如果开启 rollout token budget 或 app-server multi-agent mode，需要把预算 / delegation 模式当作运行时策略输入，不要让 Codex 内置 sub-agent dispatcher 替代项目 Trellis / Channel 工作流。

#### 对 agent harness workflow 的影响分析

- 本地扫描关键词：`plugin`、`rollout`、`token budget`、`multi-agent`、`web search`、`time reminder`、`exec-server`、`remote environment`、`AGENTS.md`、`subagent`。
- 命中处理：
  - 现有全局规则已经要求不要假设可选工具可用，并明确“不让 Codex 内置 sub-agent dispatcher 替代项目工作流”。
  - 插件安装在当前运行时由工具层要求“用户明确请求具体插件 / 连接器并匹配后才建议安装”，本仓库模板不需要新增通用安装流程。
  - Remote environment、exec-server、`AGENTS.md` discovery 属于 Codex runtime 内部修复；不改变本仓库模板路径或同步策略。
- 本节未修改 `AGENTS.md`、agent 模板、README、onboard 脚本或 Skill 模板；只记录版本分析。

## Trellis

### v0.6.3 -> v0.6.4

#### 版本来源

- GitHub Releases：<https://github.com/mindfold-ai/trellis/releases> 为空，本次未使用 release body 作为唯一依据。
- GitHub Tags：`v0.6.4` 已存在，且 npm `@mindfoldhq/trellis` 的 `latest = 0.6.4`。
- 官方英文 changelog：<https://raw.githubusercontent.com/mindfold-ai/docs/main/changelog/v0.6.4.mdx>
- 官方中文 changelog：<https://raw.githubusercontent.com/mindfold-ai/docs/main/zh/changelog/v0.6.4.mdx>
- GitHub Compare：<https://github.com/mindfold-ai/trellis/compare/v0.6.3...v0.6.4>，显示 16 个 commit。
- Migration manifest：<https://raw.githubusercontent.com/mindfold-ai/trellis/v0.6.4/packages/cli/src/migrations/manifests/0.6.4.json>
- npm metadata：`@mindfoldhq/trellis@0.6.4` 的 package metadata 指向 `bin/trellis.js`，依赖 `@mindfoldhq/trellis-core@0.6.4`，tarball `fileCount = 727`。

#### Release 汇总

- 这是补丁版本，包含两个核心 bug 修复，不需要 `--migrate`。
- `filterCommands(ctx)` 不再因为 `agentCapable` 为真就无条件过滤 `start`，而是收紧为 `agentCapable && hasHooks`。这修复了 Codex、ZCode、OpenCode、Reasonix 这类 agent-capable 但无 session-start / per-turn hooks 平台缺失 `trellis-start` skill 或 `/trellis:start` command 的问题。
- Codex 过去的一次性 `resolveCodexTrellisStartSkill` helper 被删除，改由标准 `resolveAllAsSkillsNeutral` / `resolveCommands` 路径产出。官方说明 Codex 产物字节一致，因此 `trellis update` 不应误报 user-modified。
- `workflow.md` 平台矩阵补齐 ZCode 与 Reasonix，覆盖 Active Task Routing、Research、Configure context、Completion criteria、Quality check 和 class-2 pull-based implement 区块。
- Kiro 主会话获得确定性 workflow activation：新增 `.kiro/agents/trellis.json` 主 agent，接入 `userPromptSubmit -> inject-workflow-state.py`、`agentSpawn -> session-start.py`，并把 `workflow.md` 作为 always-loaded resource。
- Kiro IDE 新增 `.kiro/hooks/trellis-workflow-state.kiro.hook`，通过 `promptSubmit -> runCommand` 注入 workflow state。
- `inject-workflow-state.py` 与 `session-start.py` 增加 Kiro 专属 plain stdout 输出分支；其他平台保持隔离。

#### 破坏性变更

- Manifest 标记 `breaking: false`，`recommendMigrate: false`，`migrations: []`。
- 但已有 Kiro、ZCode、OpenCode、Reasonix 项目如果不运行 `trellis update`，仍可能缺失新生成物或显式 workflow 启动入口。

#### 迁移说明

- 升级命令：`npm install -g @mindfoldhq/trellis@latest`。
- Kiro 用户运行 `trellis update` 后应获得新的主会话 agent、IDE hook 和共享 hook 脚本。
- ZCode / OpenCode / Reasonix 用户运行 `trellis update` 后应获得此前缺失的 `trellis-start` skill 或 `/trellis:start` command。
- Codex 用户无可观察行为变化，但仍可用 `trellis update` 让生成路径回到标准 resolver。

#### 对 agent harness workflow 的影响分析

- 本地扫描关键词：`Kiro`、`ZCode`、`Reasonix`、`OpenCode`、`trellis-start`、`agentCapable`、`hasHooks`、`userPromptSubmit`、`promptSubmit`、`workflow.md`、`trellis update`。
- 修改了 `kuno-workflow-onboard-skills/templates/skills/trellis-workflow/SKILL.md`，新增长期通用规则：
  - 对 agent-capable 但没有 session-start / per-turn hooks 的平台，`trellis update` 后必须确认仍有显式 workflow 启动入口，例如 `trellis-start` skill 或 `/trellis:start` command。
  - 对同时支持 CLI agent hooks 和 IDE hook 文件的平台，更新后分别复核主会话 agent、sub-agent、per-turn prompt hook、session-start hook 和 workflow resource 注入。
- 未修改根 `AGENTS.md` 或 agent 模板；这些细节属于 Trellis workflow Skill 的专项执行规则，不是所有真实项目都需要常驻在 AGENTS 模板中的硬性摘要。
- README / README.html 评估：本次不改变本仓库主工作流、工具职责边界、验证工具栈、同步路径或 onboard 行为，因此无需同步更新。
