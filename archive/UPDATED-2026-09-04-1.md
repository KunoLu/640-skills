### 发布汇总

`v0.152.0 -> v0.152.1`（独立 patch；依据本轮 Release body、完整 compare 12 文件与 tagged 源码）：

- 既有能力修复：Guardian 审批 review 现在尊重模型 metadata 提供的 Node REPL policy（`#41919`）。`v0.152.0` 的 `GuardianNodeReplPolicy` 始终使用 bundled `assets/guardian/node_repl_policy.md`；`v0.152.1` 优先使用 `auto_review.node_repl_policy`，缺失才回退同一 bundled 文件。
- 该政策只作用于 Guardian 对 Node REPL 的 auto-review 开发者政策片段（content kind `guardian.node_repl_policy`），不是新的用户配置键、MCP 安装命令或 Trellis dispatch。
- Chores / patch stamping 不进入本仓库长期规则。

`v0.152.1 -> v0.153.0`（依据 Release body 与 tagged 源；compare 文件列表截断，不以该清单为完整 diff）：

- 新功能：Vim 模式支持 `u` undo 与 `Ctrl+R` redo，保留完整草稿（含粘贴内容和附件）。
- 新功能：plugin CLI 可以从 remote marketplace 列出、安装和移除 plugin（`codex plugin list/add/remove`）。这是 CLI 能力扩展，不是默认安装策略变化。
- 新功能：`tui.auto_recap = false` 可关闭自动 recap，手动 `/recap` 仍可用。schema / 源码默认仍为 `true`。
- 新功能：TUI history 显示完整 patch、后台终端输入和单条已完成命令。
- 新功能：Plus / Team 用户在约五小时用量窗口剩余不足一半时更早预警。
- 既有能力修复：TUI 在外部 app-server 连接断开后重连，保留草稿和 transcript；不确定或排队的提交保持暂停待审。
- 既有能力修复：Full Access 跳过仅需确认动作的 Guardian review；User approval mode 跳过后台 Guardian scoring 和 prewarming；敏感动作检查与用户输入请求保持原处理。
- 既有能力修复：Guardian review history 在 compaction、重启和用户 fork 后保留，遵守 rollback 边界并隔离 subagent history。
- 既有能力修复：记住的 MCP tool 审批按所选 app account 作用域；macOS 上相对 MCP 可执行路径启动更可靠。
- 既有能力修复：rollout compression 包含 shared histories；`codex exec resume` 能处理按工作目录选择的 compressed rollouts；thread fork 支持符号链接 session root。
- 配置 / API：app-server thread metadata 增加可空 `model` 与 `reasoningEffort`；模型 catalog 启用时支持结构化异步问题 `request_user_input_async`。
- 配置：`tui.disable_paste_burst` 取代顶层同名设置，顶层仍作为 fallback。
- 配置：新增默认关闭的 `features.context_management.experimental_mode`。仅在符合条件的 ChatGPT Plus / Pro / Pro Lite、且使用 Codex backend 时启用 token-budget context、history notes 和 `new_context` tool。API-key、自定义 provider 和临时 structured thread 排除在外。
- `#42110`：对照 `v0.152.1` 基线，executor plugin hook admission 在 patch 中已存在（硬编码 allowlist + `allowlisted_source()`）。`v0.153.0` 把准入实现改为 `is_allowlisted_bundled_cleanup_hook`，并把 bundled cleanup hooks 当作 built-in 过滤。这是既有 admission 的实现调整，不是 hook 系统首次引入，也不是新的用户 hook schema。
- `v0.153.0` 的 `guardian_node_repl_policy.rs` 与 `v0.152.1` 字节相同（size=1150，blob SHA `c05ed242f1a2ade4606596c1402053012504575c`），因此 `#41919` 的源码也出现在 `v0.153.0`；`v0.152.1` 仍作为区间内独立 release 保留。0.153.1 / 0.153.2 完整 compare 均未改该文件。
- Chores / analytics / voice helper / Bazel schema 不进入本仓库长期规则。

`v0.153.0 -> v0.153.1`（独立 patch；依据完整 compare 11 文件、Release body 与 tagged 源码）：
