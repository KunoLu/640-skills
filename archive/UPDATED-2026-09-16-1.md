### 发布汇总

本区间只跨越一个 minor：`v18.2.0`。进入 `@oh-my-pi/pi-coding-agent` 的变化如下。

- 破坏性变更 / 库契约：`Settings.getGroup()` 改为返回浅冻结快照，在有效设置变化前复用。删除 `parseSSE`、`MCPToolsResponse`、`MCPCallResponse`；`callMCP()` 改为返回共享 `JsonRpcResponse`，result 为 `unknown`。这是 coding-agent 库 / 扩展 API，不是 Trellis / Channel / 本仓库工作流命令。
- 功能首次引入：`ollama` Web Search provider（`POST https://ollama.com/api/web_search`，凭据 `OLLAMA_CLOUD_API_KEY`）；`readUrl` 支持 Ollama 模型页；`@upstream` 路由选择器接受分层 OpenRouter slug，`omp bench` 给路由模型打 upstream 标签；composer 中 `/skill:<name>` 成为原子 skill chip；gateway 若实际提供与请求不同的 Claude 模型，transcript 在首次受影响 turn 下显示一次替换警告。
- 默认值 / 性能变化：编译二进制改为预编译 bytecode，`omp` 冷启动约 30 ms（此前约 250 ms）；交互启动先画 speculative frame，再加载 session runtime；status-line 重绘复用未变 segment。
- 既有能力修复：process 族 `hub wait` 超时现在报告实际阻塞条件（process exit、`pattern` 或 readiness），不再一律引用 start readiness log pattern。这是既有 `hub wait` 超时文案的 bug fix，不是删除 `timeout` 参数，也不是再引入 `timeoutMs`。
- 既有能力修复：Ask 超时大于 1000 秒保留配置时长；自动重试等待超过 32-bit timer 上限时完整等待；JS eval 在两个 isolated runtime 都失败时报告启动失败，不再在 host 线程执行不可取消代码；Exa MCP 在 notification 后仍能选中匹配响应；Esc-Esc rewind / `/copy` / `/tree` 用户过滤把用户调用的 skill / collab prompt 当作 user turn；`/skill:<name>` 后换行会真正调用 skill；`openrouter/<vendor>/<model>@upstream` 在 first-party provider 捆绑同 id 时能解析；subagent `yield` 保持直接函数调用，不经 `xd://` 挂载；Git TUI staging 遵守 `.gitattributes` `text`/`eol` 与 clean filter；`app.path` 启动到 omp-owned profile 不再触发 macOS Safe Storage 钥匙串对话框；Hugging Face `/raw` `/resolve` `/blob` `/tree` 返回文件而不是 model card；目录 `read` 不再追加虚假 `[1 results limit reached. Use limit=2 for more]`（`read` 无 `limit`）。
- 进入 runtime 的配套（非独立 CLI 版本）：`pi-ai` 增加 `upstreamModel`；OpenCode Go `Resets in …` 配额窗口解析修复。catalog 的 `getCatalogProviderEntry` / `CATALOG_PROVIDERS` 删除、`pi-utils` 的 `globPaths` 等删除，只作为依赖进入 runtime，不单独写成 OMP CLI 版本。

### 破坏性变更 / 迁移
