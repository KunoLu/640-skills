## Codex

### v0.138.0 -> v0.139.0

**版本判断**

- `ENTRYPOINT.md` 当前基线为 `v0.138.0`，策略为 `stable-only`。
- GitHub Releases 最新稳定版为 `rust-v0.139.0` / `0.139.0`，发布时间为 2026-06-09 20:13 UTC；npm `@openai/codex` 的 `latest` dist-tag 也指向 `0.139.0`。
- npm / GitHub 已出现 `0.140.0-alpha.*` prerelease；按 `stable-only` 策略忽略，不推进本次比较终点。

**Release 汇总**

- Code mode 现在可以直接调用 standalone web search，包括嵌套 JavaScript tool call 内部的调用，并接收纯文本搜索结果。
- Tool / connector input schema 对 `oneOf`、`allOf` 和大型 schema 的浅层结构保留更完整，提高复杂 MCP tool 的兼容性。

- Plugin marketplace 自动化增强：`codex plugin marketplace list --json` 输出 marketplace source，插件列表可以先返回缓存 catalog，再后台刷新。
- `codex resume --last "..."` 和 `codex fork --last "..."` 会把尾随参数识别为初始 prompt，而不是误判为 session id。
- MCP subagent 启动告警会保留在所属 thread，避免父 thread 重复告警和 TUI startup spinner 卡住。
- 图片编辑会使用明确引用的图片文件路径，不再从历史对话中猜测输入图片。
- TUI 对路径含 `~` 的裸 URL linkify 更完整。
- `/new`、`/clear`、`/fork` 等 thread reset 不再丢失 cloud-managed requirements 或 feature flags。
- Sandbox execution 会更稳定地保留已批准的 escalation decision，并更一致地执行 proxy-only networking 配置。

- Sandbox / proxy 行为更严格可能暴露本地网络代理配置问题；这属于运行环境配置风险，不要求本仓库修改长期规则。

- 若后续排查 Codex 本地环境问题，可以优先参考 `codex doctor` 新增的 editor / pager 环境报告；注意 JSON 输出仍会隐藏原始值。

## GitNexus

### v1.6.6 -> v1.6.7

**版本判断**

- `ENTRYPOINT.md` 当前基线为 `v1.6.6`，策略为 `stable-only`。
- GitHub Releases 最新稳定版为 `v1.6.7`，发布时间为 2026-06-09 21:05 UTC；npm `gitnexus` 的 `latest` dist-tag 也指向 `1.6.7`。
- npm `rc` dist-tag 已到 `1.6.7-rc.13`；按 `stable-only` 策略忽略 rc，仅比较稳定版 `v1.6.6 -> v1.6.7`。

**Release 汇总**

- 新增 toolchain-free tree-sitter install：`c`、`dart`、`proto`、`kotlin`、`swift` grammar 随包提供多平台预构建 native binary，降低新安装对 C/C++ toolchain 的依赖；部分 grammar 仍保留无匹配 prebuild 时的源码构建 fallback。
- 新增 `gitnexus uninstall`：按目标反向移除 `gitnexus setup` 写入的 MCP server 配置、Skill 目录和 hook；默认 dry-run，需要 `--force` 才实际应用。
- GitNexus MCP `list_repos` 新增 `limit` / `offset` 分页，结果形状变为 `{ repositories, pagination }`，需要翻页直到 `pagination.hasMore` 为 false。
- C++ receiver member lookup 改为通过 inheritance lattice 解析，处理 dominance hiding、ambiguous-base suppression、virtual diamond deduplication 和 overload ranking。
- 新增 taint / PDG substrate 的基础 graph schema 和 pipeline seams；release 明确说明目前为 additive and inert，默认 `analyze` 不会生成新节点或关系。
- Optional grammars 改为 lazy-loaded，缺少 Swift / Dart / Kotlin 等可选 grammar 不再让 `analyze`、MCP server、`doctor` 或 auto-reindex 在模块加载阶段崩溃；`GITNEXUS_SKIP_OPTIONAL_GRAMMARS` 在 runtime 生效。
- `tree-sitter-kotlin` optional grammar 安装在缺少 C/C++ toolchain 时改为 soft fail，输出清晰 warning 并退出 0。
- CLI Docker image 内置 FTS extension，containerized `serve` 的离线 keyword search 不再静默降级为 vector-only。
- MCP `query` 的 symbol enrichment 改为批量查询，减少 N+1 round-trip，输出保持等价。

**破坏性变更**

- Release notes 未显式标注破坏性变更。
- 但 MCP `list_repos` 的返回形状从未分页数组变为带 `pagination` 的对象；依赖旧形状的脚本或 agent 判断需要适配。

**迁移说明**

- 使用 GitNexus MCP 枚举仓库时，必须通过 `limit` / `offset` 翻页直到 `pagination.hasMore` 为 false。
- 需要撤销 GitNexus 集成时，先查看 `gitnexus uninstall` dry-run 结果；只有用户确认后才使用 `--force`。
- 可选 grammar 缺失或 toolchain fallback 现在更可能表现为 warning / coverage gap，而不是安装或分析硬失败；自动化结论仍需标注相关语言覆盖风险。
- 每日自动化不得把 `ENTRYPOINT.md` 写回 `v1.6.7`。

**对 agent harness workflow 的影响分析**

- 已用 `list_repos`、pagination、optional grammar、tree-sitter、`GITNEXUS_SKIP_OPTIONAL_GRAMMARS`、FTS、uninstall、taint / PDG、MCP 等关键词扫描 `AGENTS.md`、`agents/AGENTS.global.md`、`agents/AGENTS.project.md` 和 `skills/**/SKILL.md`。
- 本次 release 影响 GitNexus MCP 仓库枚举方式、卸载命令安全边界和 optional grammar 覆盖风险判断；已最小化更新 `agents/AGENTS.global.md` 与 `agents/AGENTS.project.md`。
- `skills/**/SKILL.md` 中没有 GitNexus 专属 Skill；Trellis 相关 Skill 不受本次 GitNexus release 直接影响。
- 结论：不修改 `ENTRYPOINT.md`；只更新可复用 AGENTS 模板中的 GitNexus 通用使用规则。
