# UPDATE

## Codex

### v0.131.0 -> v0.132.0

来源：

- GitHub Releases: https://github.com/openai/codex/releases
- 完整变更对比: https://github.com/openai/codex/compare/rust-v0.131.0...rust-v0.132.0

更新摘要：

- TUI 和 app 命令对当前权限配置的传递更一致，app-server 协议中的权限配置处理也做了简化。
- 远程执行能力增加了基于认证的 remote executor 注册，以及 websocket keepalive 支持。
- Python SDK 增加或完善了登录支持、turn 结果句柄、字符串输入和辅助逻辑清理。
- 多 agent 能力增加了 v2 tool namespace 的可配置行为，并收紧了模型可见描述，模型数量上限为 5 个。
- Memory 和 goal 内部机制有调整，包括更紧凑的版本化 memory summary，以及更清晰的 goal pause/resume/update 事件。
- `codex exec resume` 增加了 `--output-schema` 支持。
- TUI 修复了粘贴处理、turn error 后的 stream 清理、session picker、重命名线程 resume 提示，以及非 OpenAI 状态显示等问题。
- plugin 和 extension 相关能力增加了 installed-plugin mention API、异步生命周期 hook 和 extension event sink 能力。

破坏性变更：

- release notes 没有标出普通 CLI 使用场景下的明确破坏性变更。
- app-server 内部协议有一处 API surface 移除了 `PermissionProfile`，如果本地有自定义实验性 app-server 协议集成，需要在升级前单独检查。

迁移建议：

- 如果用户手动确认升级，可按当前环境使用的安装渠道升级 Codex 到 `v0.132.0`。
- 如果本地自动化依赖 `codex exec resume`，需要结构化 resume 输出时可以评估新增的 `--output-schema`。
- 如果项目使用自定义 remote executor 或 plugin 集成，升级后需要冒烟测试认证注册、websocket keepalive 和 installed-plugin mention 相关行为。

对 agent harness workflow 的影响：

- `codex exec resume --output-schema` 对自动化和后台线程恢复有价值，但不要求当前项目立即修改工作流。
- 权限配置传播和 TUI 权限可见性降低了 sandbox/approval 场景的歧义，但不改变本项目已有的 `rtk`、不自动 commit、不自动 push 规则。
- 多 agent namespace 可配置能力只在项目明确启用多 agent 或 Channel 工作流时相关；本项目仍要求用户明确提出后才启用 Channel 或 sub-agent 分发。
- 本次 release notes 没有要求必须修改 AGENTS 或 skill 工作流规则。
