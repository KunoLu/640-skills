## GitNexus

### v1.6.7 -> v1.6.8

资料来源：

- GitHub Release `v1.6.8`：`https://github.com/abhigyanpatwari/GitNexus/releases/tag/v1.6.8`
- GitHub compare：`https://github.com/abhigyanpatwari/GitNexus/compare/v1.6.7...v1.6.8`
- npm metadata：`https://registry.npmjs.org/gitnexus`

Release 汇总：

- `v1.6.8` 是 stable release，发布时间为 2026-06-20；npm `latest` dist-tag 已指向 `1.6.8`。
- 新增 opt-in 的 PDG-backed impact analysis：`impact` 可使用 PDG 模式做 statement-level / inter-procedural program slicing；默认 call-graph 模式保持不变。
- 新增跨语言 Program Dependence Graph 基础能力，包含 CFG、reaching definitions、control dependence；这些能力需要显式启用，例如 `--pdg`。
- 新增 taint analysis，包含 PDG 上的 intra-procedural taint tracking 和通过 resolved `CALLS` edges 传播的 inter-procedural summaries。
- 新增 multi-branch indexing / branch-scoped querying，每个 branch 使用独立存储目录，primary branch 布局不变。
- 私有仓库支持增强：可通过 PAT clone private GitHub repositories，并支持 Azure DevOps Server remotes。
- MCP 增加 `trace` tool，用于两个 symbol 之间的 shortest call path；MCP server 增加 `gitnexus mcp --http` Streamable HTTP transport，并保留 legacy SSE。
- 新增 Java Spring route annotations 到 `Route` nodes 的抽取，并持久化 HTTP method。
- `gitnexus analyze` 新增 circular import cycle check、custom embeddings provider flags，以及 setup 时选择 coding-agent integration 的能力。
- 修复了 impact / route_map under-reporting、MCP `query` / `cypher` 参数兼容、large-repo analyze crash、vendored tree-sitter grammar CWD 解析、registry transient I/O wipe、Docker image 缺运行时 assets 等问题。
- 最新可见的 `v1.6.9-rc.4` 是 prerelease，npm `rc` dist-tag 也是 `1.6.9-rc.4`；本次 `stable-only` 忽略该 RC。

破坏性变更：

- Release notes 未标记必须迁移的破坏性变更。
- 需要注意的是 PDG、taint、multi-branch indexing 和 MCP HTTP transport 都是新增能力或 opt-in 模式；不能把它们当成默认 analyze / 默认 MCP 配置行为。

迁移说明：

- 如果项目希望使用 PDG / taint 相关分析，需要确认索引生成时启用了对应能力，并在查询或影响分析中显式记录模式。
- 如果项目使用多分支索引，需要在分析、查询和变更检测时明确 branch / 默认分支。
- 如果项目想切换 MCP HTTP transport，应按当前 Agent / IDE 的 MCP 配置能力显式选择；每日自动化不应静默改写项目或用户级 MCP 配置。

对 agent harness workflow 的影响分析：

- 已用 release 关键字扫描 `AGENTS.md`、`kuno-workflow-onboard-skills/SKILL.md`、`REFERENCE.md`、`scripts/onboard.py`、Agent 模板和 Skill 模板。
- 已最小化更新 `kuno-workflow-onboard-skills/templates/agents/AGENTS.global.md` 与 `AGENTS.project.md`：补充 multi-branch branch 约束、PDG / taint / trace 显式 opt-in、MCP transport 不静默改写配置。
- 已更新 `kuno-workflow-onboard-skills/REFERENCE.md` 和 `scripts/onboard.py` 的 GitNexus MCP setup 指引：配置时按客户端选择 stdio、Streamable HTTP 或 legacy SSE，不复制用户未选择的 transport-specific config。
- 由于模板 GitNexus 使用边界发生变化，已同步更新 `README.md` 和 `README.html` 的 GitNexus 边界说明。

## Playwright

### latest -> v1.61.0

资料来源：

- GitHub Release `v1.61.0`：`https://github.com/microsoft/playwright/releases/tag/v1.61.0`
- GitHub compare：`https://github.com/microsoft/playwright/compare/v1.60.0...v1.61.0`
- npm metadata：`https://registry.npmjs.org/@playwright/test`

Release 汇总：

- `ENTRYPOINT.md` 中 Playwright 当前使用版本记录为 `latest`，本次解析 npm `latest` dist-tag 和 GitHub stable release 得到 `v1.61.0`。
- 新增 WebAuthn passkeys 支持：`browserContext.credentials` 可创建、安装和复用虚拟 authenticator，用于 passkey 注册 / 登录测试，不依赖真实硬件 key。
- 新增 Web Storage API：`page.localStorage` 和 `page.sessionStorage` 可直接读写当前 origin 的 storage。
- 新增网络、CDP attach、screencast、video modes、`expect.soft.poll(...)`、`fullConfig.argv`、`fullConfig.failOnFlakyTests`、`testInfo.errors` aggregate handling、`-G` grep-invert shorthand 等 API / runner 能力。
- 其他改进包括 Ubuntu 26.04 支持、HAR / trace 中包含 WebSocket requests、浏览器版本更新到 Chromium 149、Firefox 151、WebKit 26.5。
- npm `next` / alpha 通道存在 `1.62.0-alpha-*`，但本工具策略为 `stable-only`，本次忽略。

破坏性变更：

- Release notes 未标记明确 breaking changes。
- WebAuthn、storage、artifact/video modes 等能力是新增测试能力；不改变本仓库现有“Playwright CLI 是项目级 E2E 执行器、Playwright MCP 只做探索和 locator 辅助”的职责边界。

迁移说明：

- 项目若要使用 passkey 测试，应优先放入项目级 Playwright suite，并避免写入真实账号、密钥或 PII。
- 需要使用新 video retain modes 或 CDP artifacts 目录时，应按项目配置显式变更，不由本仓库模板静默启用。

对 agent harness workflow 的影响分析：

- 已扫描 Web / Mobile 验证模板、`project-validation`、README 和 onboard 文档。现有规则已经要求 Playwright CLI 作为项目内 Web E2E 执行器、MCP 不替代 CLI、真实凭据不得进入测试资产；本次无需修改长期规则。
