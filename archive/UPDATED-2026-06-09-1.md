## Trellis

### v0.6.0-beta.22 -> v0.6.0-beta.23

来源：

- GitHub Releases：`https://github.com/mindfold-ai/Trellis/releases`，当前 release 列表为空。
- GitHub Tags：`https://github.com/mindfold-ai/Trellis/tags`，同一 beta 通道最新 tag 为 `v0.6.0-beta.23`；同时存在较新的 `v0.6.0-rc.0`，但按 `same-prerelease-channel` 策略不跳转到 rc。
- GitHub Compare：`https://github.com/mindfold-ai/Trellis/compare/v0.6.0-beta.22...v0.6.0-beta.23`，区间为 104 commits、120 files。
- 官方 docs index：`https://docs.trytrellis.app/llms.txt`，当前索引未列出 `v0.6.0-beta.23` changelog 页面。
- npm metadata：`@mindfoldhq/trellis@0.6.0-beta.23` 存在，`beta` dist-tag 指向 `0.6.0-beta.23`，`rc` dist-tag 指向 `0.6.0-rc.0`。
- npm tarball dry-run：`@mindfoldhq/trellis@0.6.0-beta.23` 包含 `dist/templates/trellis/agents/check.md`、`dist/templates/trellis/agents/implement.md`、`dist/templates/reasonix/*`、`dist/templates/common/bundled-skills/trellis-session-insight/*`、`dist/utils/registry-config.*` 等发布文件。
- Migration manifest：`packages/cli/src/migrations/manifests/0.6.0-beta.23.json`。

Release 汇总：

- `trellis init` / `trellis update` 会写入 `.trellis/agents/{check,implement}.md`，避免 channel-driven workflow 在缺少 channel runtime agent 定义时出现 `Agent 'check' not found`。
- `trellis update` 支持刷新 registry-backed `.trellis/spec` 模板，并沿用已有 hash / conflict 处理流程；`trellis init --template <id>` 会在 `.trellis/config.yaml` 中持久化 spec source/template。
- 新增 Reasonix（DeepSeek-Reasonix）平台支持，入口为 `trellis init --reasonix`；其 subagent skills 使用 `runAs: subagent` frontmatter。
- 新增 bundled skill `trellis-session-insight`，用于引导 AI 在合适场景使用 `trellis mem` 回忆 Claude Code / Codex 历史会话。
- `trellis workflow --template <id>` 与 `trellis init --workflow <id>` 在 workflow 引用缺失的 `.trellis/agents/<name>.md` 时会输出 stderr warning，并提示运行 `trellis update`。
- 修复 bundled skill 目录拼写：`trellis-spec-bootstarp` 更名为 `trellis-spec-bootstrap`。

破坏性变更：

- Manifest 标记 `breaking: false`。

迁移说明：

- Manifest 标记 `recommendMigrate: true`。
- 需要运行 `trellis update --migrate`，将已安装平台目录中的 `trellis-spec-bootstarp/` 重命名为 `trellis-spec-bootstrap/`；未配置的平台目录会被静默跳过。
- 普通 `trellis update` 也会安装新的 `trellis-session-insight` bundled skill 和 `.trellis/agents/{check,implement}.md` channel runtime 文件。

对 agent harness workflow 的影响分析：

- 本地规则扫描命中 `trellis-workflow`、`trellis-channel`、项目级 Trellis / Channel 目录策略。
- 已最小化更新：
  - `skills/trellis-workflow/SKILL.md`：补充 `trellis update` / `trellis update --migrate`、registry-backed spec 刷新和缺失 `.trellis/agents` 排障。
  - `skills/trellis-channel/SKILL.md`：补充 Channel agent 定义缺失时运行 `trellis update`，并区分 `.trellis/agents/` 定义文件与 runtime 日志。
  - `agents/AGENTS.project.md`：补充 Trellis upgrade/migrate、registry spec review、`.trellis/agents/` 提交策略和 Channel 缺失 agent 排障。

## GitNexus

### V1.6.5 -> v1.6.6

来源：

- GitHub Releases：`https://github.com/abhigyanpatwari/GitNexus/releases/tag/v1.6.6`
- GitHub Compare：`https://github.com/abhigyanpatwari/GitNexus/compare/v1.6.5...v1.6.6`
- npm metadata：`gitnexus` 的 `latest` 为 `1.6.6`，`rc` 为 `1.6.6-rc.159`。

Release 汇总：

- `v1.6.6` 是稳定版，release body 明确说明相对 `v1.6.5` 约 190 个 PR，主题是规模和语言覆盖。
- Scope resolution 迁移到统一 registry-primary engine，覆盖 Rust、JavaScript、Ruby、Swift、Vue SFC、Dart、COBOL、Kotlin，并让 Java 达到 100% parity；旧 resolution DAG / heritage processor / shadow-mode parity harness 被删除。
- `gitnexus analyze` 增强大仓库能力：parallel worker-pool parse、indexed finalize、RAM-aware memory wall、scope-capture 线性化、C++ ADL lookup 索引化。
- 新增跨服务 API call graph 能力，覆盖 Spring、OpenFeign、FastAPI、gRPC 和 frontend HTTP clients。
- 新增 `.gitnexusrc` project config 与 `gitnexus analyze --default-branch`。
- Impact 工具增加 `--uid` / `--file` / `--kind` disambiguation flags，`limit` / `offset` / `summaryOnly` 分页，以及 `byDepth` 的 per-symbol `processes` 字段。
- 新增 `gitnexus analyze --repair-fts`，并增强 `detect-changes` 的 git-worktree 支持。
- Web viewer、wiki provider、本地 Claude/Codex/opencode provider、`gitnexus wiki --lang <lang>`、DeepSeek V4、Windows / LadybugDB / MCP 可靠性均有改进。

破坏性变更：

- Release body 标明 no breaking changes，属于 drop-in upgrade。

迁移说明：

- 官方建议 `npm i -g gitnexus@1.6.6` 后重新运行 `gitnexus analyze`，以获取更准确的 resolution 和更低内存/更快的索引。
- 对已索引项目，可按需要使用 `.gitnexusrc`、`gitnexus analyze --default-branch` 或 `gitnexus analyze --repair-fts`。

对 agent harness workflow 的影响分析：

- 本地规则扫描命中 `agents/AGENTS.global.md` 和 `agents/AGENTS.project.md` 的 GitNexus 使用规则。
- 已最小化更新：
  - `agents/AGENTS.global.md`：补充 `.gitnexusrc` / `--default-branch`、影响分析 disambiguation / pagination、跨服务 API graph 与大仓库/FTS 结果复核的通用规则。
  - `agents/AGENTS.project.md`：补充同类项目级 GitNexus 使用边界。
- 不修改 `ENTRYPOINT.md` 中 GitNexus 当前版本号。
