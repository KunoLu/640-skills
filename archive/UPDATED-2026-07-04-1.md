## GitNexus

### v1.6.8 -> v1.6.9

**版本结论**：`ENTRYPOINT.md` 当前基线为 `v1.6.8`。GitHub Tags 已出现稳定 tag `v1.6.9`，并指向 release commit；GitHub Release API 对 `v1.6.9` 仍返回 404，npm `gitnexus` 的 `latest` 仍为 `1.6.8`，且 npm metadata 暂无 `1.6.9` 稳定包。因为本任务以 GitHub 仓库 releases / tags 为主，且 `gitnexus/package.json` 在 tag 中已标记 `1.6.9`，本次区间记为 `v1.6.8 -> v1.6.9`，同时保留 npm 未发布稳定包的风险说明。

**依据来源**：

- GitHub tag：`https://github.com/abhigyanpatwari/GitNexus/tree/v1.6.9`
- GitHub compare：`https://github.com/abhigyanpatwari/GitNexus/compare/v1.6.8...v1.6.9`
- GitHub release by tag：`https://api.github.com/repos/abhigyanpatwari/GitNexus/releases/tags/v1.6.9`，本次返回 404
- npm metadata：`https://registry.npmjs.org/gitnexus`
- GitNexus migration guide：`https://raw.githubusercontent.com/abhigyanpatwari/GitNexus/v1.6.9/MIGRATION.md`
- GitNexus package metadata：`https://raw.githubusercontent.com/abhigyanpatwari/GitNexus/v1.6.9/gitnexus/package.json`

**Release 汇总**：官方 release body 缺失。本次用 compare、commit 列表、migration guide、package metadata 和 npm metadata 补充分析。`v1.6.8...v1.6.9` 共 66 个 commit，主要包括：

- PDG / taint / trace：新增 Python 与 Java source / sink model，新增 cross-repo call trace using PDG。
- HTTP route / consumer 识别：增强 Kotlin / Java Spring HTTP consumer、Django route、FastAPI APIRouter prefix、跨文件 HTTP handler、inline provider handler、同 URL 多 verb route 的 `api_impact` 形状稳定性。
- 搜索与索引：doc comments 可搜索，FTS stemmer 可配置，新增 opt-in CJK bigram segmentation，向量距离阈值可配置，embedding 文本更偏向 description。
- 存储与稳定性：LadybugDB 升级到 `0.18.0`，修复 read-only `@group` reopen、single-writer contention retry、多 label Cypher 兼容问题。
- 元数据文件：索引 metadata 主文件从 `.gitnexus/meta.json` 改为 `.gitnexus/gitnexus.json`，并保留 dual-write / fallback 兼容。
- 分支行为：flat workspace index follows the checked-out branch。
- 文档：新增 Kilo Code + GitNexus MCP setup guide，并重构 / 校验 README。

**破坏性变更**：未发现需要立即迁移的破坏性变更。`MIGRATION.md` 明确说明 `meta.json -> gitnexus.json` 是文件名主从变化，不需要手工迁移；运行新版 `analyze` 会同时写入两份 metadata，旧版回滚仍可读取 `meta.json`。但 npm `latest` 尚未发布 `1.6.9`，通过 `npm install gitnexus` 可能仍安装 `1.6.8`，这是本次剩余风险。

**迁移说明**：

- 如果手工查看索引 metadata，优先检查 `.gitnexus/gitnexus.json`；同时把 `.gitnexus/meta.json` 当作兼容镜像，不要仅因其中一个文件不存在就判断索引缺失。
- 分支索引下同理关注 `branches/<branch>/gitnexus.json` 与 `branches/<branch>/meta.json`。
- 现有仓库无需手工改文件；需要刷新时仍按项目约定运行 `gitnexus analyze`，并结合 `gitnexus status` 或 MCP 输出确认。

**对 agent harness workflow 的影响分析**：本地规则命中 `PDG`、`taint`、`trace`、多分支、HTTP route、FTS、MCP 和 GitNexus 索引相关内容。现有全局模板已要求高级图分析显式 opt-in、跨服务 route / consumer 结论回到源码交叉核对、多分支索引明确目标 branch、FTS / 大仓库风险需修复后再依赖。唯一需要沉淀的新长期规则是 metadata 文件名兼容，因此已更新 `kuno-workflow-onboard-skills/templates/agents/AGENTS.global.md` 的 GitNexus 规则。未修改 `ENTRYPOINT.md`，未改写项目级模板和 Skill 模板；README / README.html 评估后无需同步，因为这次变化是低层 GitNexus metadata 检查规则，不改变 README 中的主流程、工具职责边界或最终验证工具栈。
