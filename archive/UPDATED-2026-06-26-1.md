# UPDATE

## Codex

### v0.142.0 -> v0.142.2

**检测结论**

- 最新可接受版本：`v0.142.2`，对应 GitHub release `rust-v0.142.2`，npm `@openai/codex` 的 `latest` dist-tag 为 `0.142.2`。
- 策略判断：`ENTRYPOINT.md` 当前版本是稳定版，版本通道策略为 `stable-only`；`0.143.0-alpha.25` 及更高 alpha tag 属于 prerelease / alpha 通道，本次忽略。
- 区间来源：GitHub releases `rust-v0.142.1`、`rust-v0.142.2`，GitHub compare `rust-v0.142.0...rust-v0.142.2`，npm metadata。

**Release 汇总**

- `v0.142.1` 新增 opt-in Windows system proxy authentication 支持，覆盖 PAC、WPAD、静态代理和 bypass rules。
- `v0.142.2` 让 MCP tools 在支持时默认使用 tool search，改善工具发现并保留旧模型 / provider 兼容性。
- `v0.142.2` 新增 macOS authentication client 在启用 `respect_system_proxy` 时读取 system proxy、PAC 和 WPAD。
- `v0.142.2` 为 plugin manifest / remote catalog 增加 dark-mode logo metadata，App safety-buffering UI 可展示服务端 visibility 和 faster-model metadata。
- bug fix 包括 remote plugin catalog featured ranking、Bedrock 过期凭据的可操作提示、remote stdio MCP 接受远端平台格式的绝对 cwd、remote HTTP(S) image 输入返回模型可见校验错误、PowerShell AST 未可检查区域需要 approval、Code Mode 缺少 model metadata 时提示。
- chores 包括 bundled OpenSSL / esbuild patched release 更新，以及 formatter 成功时静默、失败时仍输出诊断。

**破坏性变更**

- 未发现 release note 标注的破坏性变更。
- system proxy 相关能力是 opt-in；MCP tool search default 保留旧模型 / provider 兼容性。

**迁移说明**

- 本仓库不写回 `ENTRYPOINT.md`，因此当前使用版本仍保持 `v0.142.0`；只有用户手动输入 `更新` / `update` 后才允许写回。
- 依赖企业代理认证的 Windows / macOS 环境，升级 Codex 后可按上游能力验证 PAC / WPAD / 静态代理 / bypass 行为；本仓库没有需要同步的固定代理配置模板。

**对 agent harness workflow 的影响分析**

- 本地规则扫描关键词：`tool_search`、`tool search`、`MCP tools`、`system proxy`、`PAC`、`WPAD`、`PowerShell`、`remote stdio`、`dark-mode`、`Bedrock`、`remote images`、`safety buffering`。
- 命中结果主要是已有 MCP 可见性人工检查、GitNexus MCP 说明和认证 / registry 文案；未发现本仓库模板要求直接使用已过时的 MCP discovery API，也未发现 Codex system proxy、PowerShell AST 或 remote image 规则需要长期固化。
- 处理决定：不修改 `AGENTS.md`、`kuno-workflow-onboard-skills/templates/agents/AGENTS.global.md`、`kuno-workflow-onboard-skills/templates/agents/AGENTS.project.md`、onboard 脚本或 README。`tool_search` 属于当前 Codex app / harness 的工具发现能力，现有模板只要求确认 MCP 工具可见，不复制 MCP 配置。
- README 同步评估：无需更新 `README.md` / `README.html`，因为本次 Codex release 不改变本仓库记录的主工作流、工具职责边界、验证工具栈、onboard 行为、模板路径或用户可见文档入口。

**检测结论**

- 策略判断：`ENTRYPOINT.md` 当前版本是稳定版，版本通道策略为 `stable-only`；旧 `v0.6.0-rc.0` 和 `v0.6.0-beta.*` 不是更新的稳定版本，本次忽略。
- 区间来源：GitHub tags、GitHub compare `v0.6.4...v0.6.5`、migration manifest `packages/cli/src/migrations/manifests/0.6.5.json`、npm metadata 和 `npm pack @mindfoldhq/trellis@0.6.5` 包结构。
- 官方 docs / changelog 对应版本条目：在仓库 tag 中未找到直接可读的 `v0.6.5` changelog 文件；本次记录为缺失，并用 compare、manifest、npm metadata / tarball 内容补足依据。

**Release 汇总**

- 新增 Trae IDE 平台支持；`trellis init --trae` / `trellis uninstall --trae` 管理 `.trae/commands/`、`.trae/skills/`、`.trae/agents/`、`.trae/hooks/` 和 `.trae/hooks.json`，Trae 主会话使用 shared SessionStart / UserPromptSubmit hooks，sub-agent 使用 pull-based prelude。
- Pi 平台新增 `tools` frontmatter 支持，并修复 sub-agent tool 名称大小写和死路径；Pi startup context 通过首次 `before_agent_start` 事件注入，同时保留手动 start prompt fallback。
- Channel 修复 Windows npm `.cmd` shim 到 `.exe` 的 spawn 解析，避免 `.exe` 路径解析失败。
- shared Python hooks 在 stdin 为空时不再阻塞。
- workflow 修复 class-2 implement dispatch，将 Codex sub-agent、Gemini、Qoder、Copilot、ZCode、Reasonix、Trae 等 pull-based 平台保留在 pull-based block，避免误归入 hook auto-handles。
- workflow 新增 curated `implement.jsonl` / `check.jsonl` gate，seed-only task context 不再被视为 implementation-ready。
- brainstorm 规划新增 lossless PRD convergence gate，防止 brainstorm 更新丢失已有 requirements。
- ZCode 命令 fallback 保留在 `.zcode/commands/trellis/`，避免与 shared `.agents/skills/` 漂移。
- npm tarball 确认包含 `dist/migrations/manifests/0.6.5.json`、`dist/templates/trae/**`、`dist/templates/pi/**`、`dist/templates/shared-hooks/**`、`dist/templates/trellis/workflow.md`、`dist/commands/channel/**` 等发布文件。

**破坏性变更**

- migration manifest 标注 `breaking: false`。
- manifest 标注 `recommendMigrate: false`，`migrations: []`。
- 虽无 breaking migration，但 generated workflow / platform templates 有实际变化；旧项目升级后应运行 `trellis update` 获取生成文件修复。

**迁移说明**

- 不修改 `ENTRYPOINT.md`；只有用户手动输入 `更新` / `update` 后才允许将 `v0.6.5` 写回。
- 升级 Trellis 后运行 `trellis update`。
- Trae 新项目可运行 `trellis init --trae`；已有 Trellis 项目应运行 `trellis update`。
- Pi 用户应运行 `trellis update`，以获取 generated start prompt、extension startup-context 更新和 sub-agent tools frontmatter 修复。

**对 agent harness workflow 的影响分析**

- 本地规则扫描关键词：`Trae`、`Pi`、`.pi`、`implement.jsonl`、`check.jsonl`、`lossless`、`PRD convergence`、`pull-based`、`class-2`、`session_start`、`SessionStart`、`.cmd`、`.exe`、`spawn`。
- 命中结果显示现有模板已有部分 Trellis update / platform / `check.jsonl` 提示，但缺少 lossless PRD convergence、JSONL real-entry gate、pull-based class-2 路由、Trae / Pi 平台更新复核和 Windows Channel spawn 排障规则。
- 处理决定：已最小化更新 `kuno-workflow-onboard-skills/templates/skills/trellis-workflow/SKILL.md`，加入 PRD convergence pass、`implement.jsonl` / `check.jsonl` 真实上下文 gate、pull-based class-2 平台路由、Trae / Pi 类平台更新复核规则。
- 处理决定：已最小化更新 `kuno-workflow-onboard-skills/templates/skills/trellis-channel/SKILL.md`，加入 Windows worker spawn / `.cmd` shim 排障边界，要求先升级 / `trellis update`、验证 provider CLI，不用任意 `shell: true` wrapper 绕过。
- 未修改 `AGENTS.md` 或 agents 模板：这些细节属于 Trellis workflow / Channel Skill 的延迟加载专项流程，不是所有项目常驻规则。
- README 同步评估：无需更新 `README.md` / `README.html`，因为本次修改不改变本仓库展示的顶层工作流主线、工具职责边界、Web / Mobile 验证栈、onboard init/reset 行为、模板路径或用户可见文档入口。
