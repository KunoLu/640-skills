# UPDATE

## Codex

### v0.143.0 -> v0.144.0

**版本来源**

- GitHub Release：`rust-v0.144.0`，发布时间 `2026-07-09T16:47:12Z`，地址：`https://github.com/openai/codex/releases/tag/rust-v0.144.0`。
- npm：`@openai/codex` 的 `latest` dist-tag 为 `0.144.0`，发布时间 `2026-07-09T16:50:26.998Z`。
- GitHub compare：`rust-v0.143.0...rust-v0.144.0`，`ahead_by=80`，地址：`https://github.com/openai/codex/compare/rust-v0.143.0...rust-v0.144.0`。

**Release 汇总**

- 新增 usage-limit reset credits 的类型、过期时间和 redeem 选择展示。
- 新增 `writes` app-approval mode：允许声明为只读的 action 直接执行，对写入 action 再提示审批。
- MCP tools 可以默认发起交互式 authentication request，不再需要实验性 opt-in。
- App-server host 可以在 runtime 提供 Codex auth，并把登录成功重定向到 hosted page。
- Codex diagnostics / updates 能检测由 `pnpm` 管理的全局安装。
- Ultra reasoning 在高 multi-agent concurrency 下会提示用量可能快速增加。
- 修复 retired model compaction resume、Intel macOS release binary crash、Windows sandbox writable root 删除、TUI terminal control sequence、`codex_apps` connector auth refresh、Responses WebSocket proxy / custom CA 等问题。
- 优化 remote executor plugin namespace loading、`/review` branch picker、auto review 行为和模型显示名。

**破坏性变更**

- Release notes 未标记 breaking change。
- `writes` approval mode、MCP auth elicitation 和 hosted auth 是能力 / runtime 行为扩展，不要求本仓库调整项目配置格式。

**迁移说明**

- 未发现必须迁移步骤。
- 如果使用高 reasoning / Ultra 模型同时运行多个 worker，应把用量风险纳入 Channel preflight，而不是直接提高 worker 并发。

**对 agent harness workflow 的影响分析**

- 本地关键词扫描范围：`AGENTS.md`、`kuno-workflow-onboard-skills/SKILL.md`、`kuno-workflow-onboard-skills/REFERENCE.md`、`kuno-workflow-onboard-skills/scripts/onboard.py`、`kuno-workflow-onboard-skills/templates/agents/AGENTS.global.md`、`kuno-workflow-onboard-skills/templates/agents/AGENTS.project.md`、`kuno-workflow-onboard-skills/templates/skills/**`。
- 扫描命中：`AGENTS.global.md` 已覆盖 ChatGPT-hosted MCP / OAuth / session authentication / connector token 边界；`REFERENCE.md` 已覆盖系统 proxy / PAC / WPAD 作为 runtime 环境行为；`trellis-channel` 已覆盖 Channel worker guard 和 Windows `.cmd` shim。
- 处理决定：根据 Ultra + multi-agent concurrency 的 release 依据，已在 `trellis-channel` Skill 的 worker guard 中补充高 reasoning / Ultra 多 worker 并发的用量风险 preflight 规则，并同步 `README.md` / `README.html` 的发布风险说明。
- 未处理为长期规则：`writes` approval mode、hosted auth、pnpm install detection、review picker 和 plugin namespace loading 均属于 Codex runtime / CLI 内部能力，本仓库现有工具可用性、认证和 proxy 边界已覆盖，无需新增模板规则。

**版本来源**

- npm：`@mindfoldhq/trellis` 的 `latest` dist-tag 为 `0.6.6`，发布时间 `2026-07-09T08:49:05.237Z`。
- GitHub compare：`v0.6.5...v0.6.6`，`ahead_by=51`，地址：`https://github.com/mindfold-ai/trellis/compare/v0.6.5...v0.6.6`。
- npm tarball：`https://registry.npmjs.org/@mindfoldhq/trellis/-/trellis-0.6.6.tgz`，包含 `dist/migrations/manifests/0.6.6.json` 和 OMP / ZCode / Codex / Trellis templates。
- 官方 docs / changelog：未发现单独 `CHANGELOG.md` 或 `docs/releases/0.6.6.md`；`README.md` 可读取但不是版本变更条目。

**Release 汇总**

- GitHub release body 缺失，本节基于 compare、commit list、npm metadata、tarball 文件结构和 `packages/cli/src/migrations/manifests/0.6.6.json` 汇总。
- 新增 Oh My Pi / OMP 平台支持：`trellis init --omp` 写入 `.omp/agents/`、`.omp/commands/`、`.omp/skills/`、`.omp/extensions/trellis/`，并纳入 Trellis workflow / sub-agent context。
- 修复 Pi / OMP context injection：保持 Pi `systemPrompt` 跨 turn 字节稳定，并通过 hidden message 传递 workflow / session / task 更新，降低 provider prefix cache 被破坏的风险。
- 修复 ZCode layout：新版本写入 `.zcode/skills/` 和 `.zcode/agents/`，并补齐 `trellis-research`。
- 修复 Channel worker：Windows npm `.cmd` / node-script shim 会在 spawn 前解析为可执行目标；stdout event append 串行化，避免并发输出破坏 event records。
- 修复 task CLI：忽略 stale `task.json.branch`、防止 `task.py create --slug` 重复日期前缀、支持 `--no-start` 只创建 backlog 而不移动 session pointer。
- 修复 Codex inline：只有显式配置 `codex.dispatch_mode: sub-agent` 时才 seed `implement.jsonl` / `check.jsonl`，inline mode 不再生成 seed-only JSONL。
- 修复 Copilot instructions 和 shared hook failure handling：保留 repo-authored `.github/copilot-instructions.md` 内容，只管理 Trellis block；hook failure 保持 fail-open。

**破坏性变更**

- Migration manifest 标记 `breaking: false`。
- 对已使用 ZCode `0.6.3-0.6.5` 初始化且存在 `.zcode/cli/agents/` 的项目，有一次性目录迁移需求。

**迁移说明**

- 新安装不需要 `--migrate`。
- 升级后建议运行 `trellis update` 刷新 scripts、hooks、platform templates 和 task workflow guidance。
- ZCode 用户如果项目内存在 `.zcode/cli/agents/`，应运行 `trellis update --migrate`，把 legacy sub-agents 迁移到 `.zcode/agents/`。
- Oh My Pi 用户可在尚未存在 `.omp/` 的项目中运行 `trellis init --omp`；已有 OMP 项目运行 `trellis update`。

**对 agent harness workflow 的影响分析**

- 本地关键词扫描命中：`kuno-workflow-onboard-skills/SKILL.md` 和 `REFERENCE.md` 已记录 `oh-my-pi` / `omp` 平台；`trellis-channel` Skill 已记录 Windows `.cmd` shim worker spawn 排障；`trellis-workflow` Skill 已记录当上游 migration manifest 建议迁移时运行 `trellis update --migrate`。
- 处理决定：现有模板已覆盖 OMP、Windows Channel spawn 和 migration-manifest-driven update/migrate 的长期规则，本轮没有再修改 Trellis 规则。
- 未读取 / 未修改旧路径：未使用已删除的根目录旧 `AGENTS.global.md`、旧 `AGENTS.project.md`、顶层 `agents/` 或顶层 `skills/`。
