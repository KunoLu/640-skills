### 发布汇总

- 功能首次引入（opt-in 存储）：`GITNEXUS_STORAGE_PATH` 把单个仓库的 graph、metadata、parse caches、locks、branch indexes 写到任意绝对目录；`GITNEXUS_STORAGE_ROOT` 给多个仓库共享根，槽位为 `<repo-basename>-<canonical-path-hash>/`。两者都设时 `GITNEXUS_STORAGE_PATH` 优先。未设置时仍写 `<repo>/.gitnexus/`。
- 功能首次引入（opt-in 保留层级）：`GITNEXUS_CONTENT_RETENTION=full|symbol|none` 在生成时选择持久化多少源码派生文本。图导向 CLI / MCP / UI 工作流不变；各表面会明确说明 retention 或缺失 checkout 正在隐藏文件正文，而不是返回空白。
- 功能首次引入：Objective-C 成为支持语言（vendored `tree-sitter-objc`）。
- 功能首次引入：`analyze --skip-fts` / `GITNEXUS_SKIP_FTS=1` 显式跳过 FTS。
- 既有能力增强：`gitnexus embeddings` 原地给已有索引补向量，成功 batch 可续跑，不重建结构图；超时由 `GITNEXUS_EMBEDDING_RETRY_TIMEOUTS` 重试。外源 embedding identity 或向量宽度漂移 fail-closed。
- 既有能力修复：staleness 不再把 `rev-list` 失败塌缩成 `fresh`；状态为 `current` / `behind` / `diverged` / `unknown`。`GET /api/repos` 与 `GET /api/repo` 暴露 indexed branch、`lastCommit` 和落后程度。`doctor` 区分 vector 能力与仓库索引状态。
- 既有能力修复：MCP 拒绝未知 tool 参数并尊重 `depth`；MCP `tools/list` 不再按仓库 spawn git。
- 语言解析修复：Dart / Zig / Go / TypeScript / Ruby / COBOL / Python 等符号解析变化；升级后既有索引不会自动带上新边。
- 耐久性：无法 reset 的 parse-cache generation 被退役；file-lock 回收加守卫；LadybugDB 固定 `@ladybugdb/core@0.18.3`。

### 破坏性变更 / 迁移

- Release 声明无 breaking changes。
- 升级命令：`npm install -g gitnexus@1.6.12` 或已有全局安装上的 `gitnexus update`。
- 建议重新 `gitnexus analyze`：本区间加入 Objective-C，并改变多种语言的符号解析；既有索引不会自动带上那些边。这与本仓库已有「解析语义升级后先重新 analyze」规则一致。
- 采用 `GITNEXUS_STORAGE_PATH` / `GITNEXUS_STORAGE_ROOT` / `GITNEXUS_CONTENT_RETENTION` 无需手工迁移；兼容元数据会持久化，profile 变化时下次 analyze 重建该索引。

### 平台调度核验

本区间不涉及 Trellis、Codex dispatch、sub-agent、hook 或 Channel。不形成平台调度规则。

### 影响分析

扫描关键词：`GITNEXUS_STORAGE_PATH`、`GITNEXUS_STORAGE_ROOT`、`GITNEXUS_CONTENT_RETENTION`、`GITNEXUS_SKIP_FTS`、`analyze --skip-fts`、`gitnexus embeddings`、`commitsBehind`、`fresh`、`diverged`、`unknown`、Objective-C、`LadybugDB`。

命中结果：

- `AGENTS.global.md`：命中「存在 `.gitnexus/`」作为索引强证据；手工元数据默认 `.gitnexus/gitnexus.json`；过期判定写 `stale`、`commitsBehind > 0`、「索引落后 HEAD」。未覆盖外部存储路径，也未把 `unknown` / `diverged` 当成非 current。这会让 agent 在 relocatable index 或 `rev-list` 失败时误判。
- `AGENTS.project.md`：只写「stale 或解析语义升级后先按项目约定用 CLI 刷新」，足够通用，不复制全局细则。默认不提交 `.gitnexus/` 仍是 in-repo 产物忽略，不是发现规则。
- `AGENTS.md`、版本检查 prompt、`ENTRYPOINT.md`：命中既有 GitNexus 监控与 `gitnexus analyze --embeddings`。`ENTRYPOINT.md` 不由本次自动化修改。
- `README.md` / `SKILL.md` / `REFERENCE.md`：写的是「全局 CLI + 项目内默认 `.gitnexus/` 状态」，不是索引发现门。opt-in 外部存储不改变 Onboard 安装落点，故不同步这些入口。
- `onboard.py` / `install.sh` / `catalog.json` / `tests/**`：未命中新的 storage / retention 环境变量。

处理决定：最小化更新 `AGENTS.global.md` 的 GitNexus 使用边界。外部存储强证据必须是 `gitnexus status --repo <已注册仓库别名或路径> --json` 的 `storagePath`（文本 `Index storage` 只在带 `--repo` 时输出；checkout 内的 `gitnexus status --json` 成功响应不含 `storagePath`）所解析路径实际存在且含索引产物，不能把环境变量已设置当成已建立索引；`status --repo` 只确认注册索引与存储位置，不证明 checkout 新鲜度，工作树新鲜度由 checkout 内 `gitnexus status --json` 的 `up-to-date` / `stale` 单独判定，`up-to-date` 不触发刷新或重建。同时对齐 MCP staleness 状态枚举 `current` / `behind` / `diverged` / `unknown`、retention 隐藏正文、以及 `gitnexus embeddings` 原地补向量。不写版本号。不修改 `AGENTS.project.md`。不同步 README / 版本化 prompt。`CHANGELOG.md` 记录这次规则对齐。
