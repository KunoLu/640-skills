## Codex v0.144.6 -> v0.145.0

### 证据

- GitHub stable release：[`rust-v0.145.0`](https://github.com/openai/codex/releases/tag/rust-v0.145.0)，发布于 2026-07-21；其发布说明包含完整变更摘要和 `rust-v0.144.0...rust-v0.145.0` 的上游 compare 链接。
- GitHub tags 列表确认存在稳定标签 `rust-v0.145.0`；`v` 前缀差异仅为标签命名，不改变版本比较结果。

### 发布汇总

- 新增实验性的分页线程历史：恢复、搜索、持久化名称、sub-agent 支持和 memories。
- `/import` 扩展为可迁移 Cursor / Claude Code 的设置、MCP server、plugins、sessions、commands 及项目级 memories。
- 新增实验性的 Amazon Bedrock 登录、自定义 endpoint / authentication，以及对应的默认模型调整；加入音频输入、tool outputs 与实时流式对话能力。
- opt-in multi-agent V2 进入稳定化阶段，支持配置 sub-agent 模型、reasoning level、并发度、恢复角色和更好的 agent 导航。
- 改进 MCP 启动与 OAuth：启动超时、避免阻塞 discovery、串行化 refresh，并安全复用工具目录；同时降低 skill/plugin discovery 与 remote compaction 的启动、长上下文开销。
- 修复 macOS code-mode 安装、Windows sandbox、长对话 TUI 响应、安全审批和强制删除检测等问题。

### 破坏性变更与迁移

官方说明未声明破坏性变更。`/import` 是显式调用的迁移能力，不应由本仓库自动运行；本次没有迁移用户配置、MCP 配置、sessions、plugins 或 memories。

### 对 agent harness workflow 的影响分析

已以 release 关键词扫描允许维护的本地规则源：

- `AGENTS.md` 与版本化 automation prompt：没有将新功能误当作已配置能力；现有“仅在当前会话有强证据时视为工具可用”和“不得静默改写 MCP / 用户级配置”边界继续适用。
- `catalog.json`、`catalog.schema.json`、Onboard 的 `SKILL.md` / `REFERENCE.md` / `scripts/onboard.py`：仅有既有 Codex、Cursor、Claude Code 与 MCP 安装路径说明；没有依赖 `/import`、Bedrock、audio、thread history 或 code-mode 的过时约定。
- 全局 / 项目 AGENTS 模板：既有 OAuth、plugin / connector 受控使用规则保持有效。
- bundled Skills：`trellis-channel` 已明确 Codex built-in multi-agent 不能替代 Trellis Channel，且不得自动开启；`trellis-workflow` 已要求 sub-agent context manifest 真实完整。新版本没有要求改变这两个更保守的长期边界。

结论：无需修改 AGENTS、Onboard 模板或 Skill。新能力应在实际 runtime 明确暴露且用户要求后，才按现有边界使用。

## Maestro cli-2.6.1 -> cli-2.7.0

### 证据

- GitHub stable release：[`cli-2.7.0`](https://github.com/mobile-dev-inc/Maestro/releases/tag/cli-2.7.0)，发布于 2026-07-20。release body 仅链接 changelog，不能单独说明行为。
- 官方 [`CHANGELOG.md` 的 2.7.0 条目](https://raw.githubusercontent.com/mobile-dev-inc/maestro/main/CHANGELOG.md) 提供功能与修复依据。
- GitHub compare [`cli-2.6.1...cli-2.7.0`](https://github.com/mobile-dev-inc/Maestro/compare/cli-2.6.1...cli-2.7.0) 显示该区间 ahead 59 commits，并给出具体 commits 与变更文件列表。
- release assets 包含 `checksums_sha256.txt` 与 `maestro.zip`；没有 migration / upgrade manifest，也没有 npm package 发布物可作为额外迁移依据。

### 发布汇总

- 每个 flow 的运行产物改为更精简的扁平 bundle，包含 structured manifest、可读步骤名、device logs、crash / ANR reports；每一步前捕获 screenshot，并在失败时配对 view hierarchy。
- Maestro MCP 新增 `describe_cloud_run`；`maestro chat` 停用并指向 Maestro MCP。
- Android 增加 Unicode 输入、延长 screen recording、识别 native crash；Web / WebView 修复 selector、Flutter semantics identifier、DevTools hang 与瞬态 JavaScript error。
- iOS 改进 `scrollUntilVisible` 后的 tap、hierarchy 获取、iPad iOS 26 home-screen hierarchy、app launch / stop timeout、orientation、driver 清理和瞬态 accessibility 错误恢复。
- CLI 改进 ANSI 配置、日志捕获、debug log archive 容错和带 slash flow name 的 AI HTML report 文件名。

### 破坏性变更与迁移

唯一明确的使用边界变化是停用 `maestro chat`，应改用可用的 Maestro MCP；没有发布配置、flow YAML 或 report path 的强制迁移 manifest。本仓库当前没有 `maestro chat` 引用，也没有执行升级或迁移。

### 对 agent harness workflow 的影响分析

已以 release 关键词扫描允许维护的本地规则源：

- `AGENTS.md`、版本化 automation prompt、catalog / schema、Onboard 文档与安装脚本：没有 `maestro chat`、`describe_cloud_run` 或对旧每-flow artifact layout 的直接依赖。
- 全局 / 项目 AGENTS 模板、`project-validation` 与 `maestro-mobile-e2e`：已有 view hierarchy、正式 report、artifact、失败证据、原生 `maestro test` 与 CLI/MCP 分工规则；它们不解析 Maestro 内部 runtime bundle，故 2.7.0 的扁平 artifact layout 不会改变现有 report 契约。
- `maestro-mobile-e2e` 的 iOS real-device lesson 保持针对 2.6.1 已知症状的按需处理；2.7.0 未声明已覆盖该 lesson 的全部触发条件，不能据此删除或放宽该安全边界。

结论：不新增对当前 runtime 未暴露的 `describe_cloud_run` 的硬依赖；不修改既有 CLI/MCP 分工、report path 或 iOS 排障规则。实际升级后，涉及下游解析 Maestro runtime artifact 的项目应单独验证其 manifest / 平铺输出兼容性。
