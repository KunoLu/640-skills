## Graphify

### v0.8.27 -> v0.8.28

来源：

- GitHub Releases：`safishamsi/graphify` 已发布 `v0.8.28`，页面标记为 Latest，发布时间为 2026-06-01。
- GitHub tag 校验：`v0.8.28` 指向 `efda79a3b149a51262b88d403bccd84ec4589285`。
- Release notes 指向 PyPI `graphifyy/0.8.28`；本次 release body 足够完整，因此没有依赖 npm 包 metadata 作为 Graphify 版本判断来源。
- 版本策略：`ENTRYPOINT.md` 中当前版本是稳定版且策略为 `stable-only`，因此本次比较到最新稳定版 `v0.8.28`。

Release 汇总：

- 新增 Kilo Code 支持：`graphify install --platform kilo` 可安装原生 skill、`/graphify` command 和 `.kilo` 的 `tool.execute.before` plugin；已有 `.kilo/kilo.jsonc` 会被读取但不重写，plugin registration 写入 `kilo.json` 以保留用户注释。
- Dart extractor 现代化：支持 comment stripping、`part of` redirection、嵌套泛型感知的 `extends` / `with` / `implements` 解析、泛型类型参数映射和泛型 call 检测。
- 安装修复：默认 `uv tool install graphifyy` / `pip install graphifyy` 不再因为 `tree-sitter-dm` 只提供 Windows wheel 而在 Linux/macOS 上要求本机 C 工具链或 `python3-dev`；DreamMaker AST 支持改为 optional extra。
- 社区 ID 稳定性修复：community ID 按总序 `(-size, sorted node IDs)` 分配，相同分组跨运行保持相同 ID，减少纯整数标签 churn。

破坏性变更：

- 未标记通用破坏性变更。
- 兼容性注意：依赖 DreamMaker `.dm` / `.dme` AST extraction 的用户需要使用 `graphifyy[dm]` 或 `graphifyy[all]` 重新安装；`.dmi` / `.dmm` / `.dmf` parsing 不受影响。

迁移说明：

- Kilo Code 用户使用 `graphify install --platform kilo` 或当前 CLI help 中的等价命令安装，不要手工重写保留注释的 Kilo JSONC 配置。
- DreamMaker AST 用户按 release note 选择 optional extra 重新安装。
- 依赖 Dart / Flutter 图谱结论、社区 ID 或 graph diff 稳定性的项目，应升级后重新建图或运行 `graphify update .`，再回到源码和局部 query/path/explain 交叉验证。

对 agent harness workflow 的影响分析：

- 已扫描 `AGENTS.md`、`agents/AGENTS.global.md`、`agents/AGENTS.project.md` 和 `skills/**/SKILL.md`，Graphify 规则主要维护在 `agents/AGENTS.project.md`。
- `agents/AGENTS.project.md` 已增加版本无关规则：Kilo platform install/config 边界、Dart/Flutter 抽取信号、DreamMaker optional extra 安装要求，以及社区 ID 稳定性在 graph diff 中的使用边界。
- `AGENTS.md`、`agents/AGENTS.global.md` 和 `skills/**/SKILL.md` 无需修改；Graphify 仍是用户明确触发且确认安装后才使用的可选工具。
- `ENTRYPOINT.md` 只作为固定起点读取，本次没有写回当前版本。
