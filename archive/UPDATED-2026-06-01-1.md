## Graphify

### v0.8.26 -> v0.8.27

#### 版本选择依据

- `ENTRYPOINT.md` 当前使用版本为 `v0.8.26`，版本通道策略为 `stable-only`。
- GitHub Releases 显示最新稳定版本为 `v0.8.27`，发布时间为 2026-05-31。
- raw changelog 的 `0.8.27` 条目与 GitHub Release 内容一致。

#### Release 汇总

- standalone CLI 现在会在已配置 backend 时自动为社区命名，避免裸 CLI 运行只留下 `Community N` 占位名；新增 `graphify label <path>` 子命令，可重新生成社区名称，`--no-label` 可跳过命名，`--backend=<name>` 可覆盖自动检测。
- AST 文件级 node ID 修正为符合 Skill 规范的 `{parent_dir}_{stem}`，避免 AST 与 semantic subagent 输出出现断开的 ghost node。
- 根目录文件的 symbol-level node ID 同步修正，`raw_calls` caller ID 也会按 `source_file` 做 canonicalize。
- TypeScript `interface A extends B` 和同文件 `class X extends Y` 会正确产出 `inherits` / `implements` 边。
- `graphify export obsidian` 对超长 node label 的文件名改为按 UTF-8 字节截断并追加 hash，降低长标签和 CJK 标签导致的路径错误。
- `graph.json` 输出改为跨运行确定性排序，减少同一输入重复建图产生的非语义 churn。
- Windows 控制台启动时重新配置 stdout / stderr 为 UTF-8，并把部分非 ASCII 打印字符换成 ASCII，避免非 UTF-8 code page 崩溃。

#### 破坏性变更

- 未声明破坏性变更。
- 但 node ID 规范修正、TypeScript 继承边修复和确定性输出会影响旧图谱中的节点匹配、边关系和 diff 形态；依赖旧图谱结论时应重新生成或更新后再判断。

#### 迁移说明

- 使用当前推荐安装路径时，可运行 `uv tool upgrade graphifyy` 升级。
- 已有 `graphify-out/` 图谱如果依赖社区名称、文件 / symbol node ID、TypeScript `inherits` / `implements` 边或 `graph.json` diff 稳定性，应运行 `graphify update .` 或重新建图后再继续分析。
- 如果历史图谱存在大量 `Community N` 占位名，可在启用 Graphify 且 backend 可用时用 `graphify label <path>` 刷新社区命名。

#### 对 agent harness workflow 的影响分析

- 本地规则扫描范围：`AGENTS.md`、`agents/AGENTS.global.md`、`agents/AGENTS.project.md`、`skills/**/SKILL.md`。
- 命中结果：`agents/AGENTS.project.md` 已有 Graphify 使用边界、`graphify update .`、`references` / `inherits` / `implements`、旧图谱重建等规则；但尚未覆盖社区命名、`graphify label`、node ID 修正和确定性输出对旧图谱可信度的影响。
- 处理决定：最小化更新 `agents/AGENTS.project.md` 的 Graphify 规则，加入 `graphify label` 的使用边界，并扩大升级后需要重建 / update 的判断条件；不修改 `AGENTS.md`、`agents/AGENTS.global.md` 或 `skills/**/SKILL.md`。
- `ENTRYPOINT.md` 只作为固定比对基线读取，本次不写回 `v0.8.27`。
