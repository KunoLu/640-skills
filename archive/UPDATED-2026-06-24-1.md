## Playwright

### v1.61.0 -> v1.61.1

#### 版本来源

- GitHub Release：<https://github.com/microsoft/playwright/releases/tag/v1.61.1>
- npm `@playwright/test`：`latest = 1.61.1`，`next = 1.62.0-alpha-2026-06-23`，`beta = 1.61.1-beta-1782139553000`。
- 本仓库策略为 `stable-only`，因此接受 `v1.61.1`，忽略 `next` 与 `beta` 预发布通道。

#### Release 汇总

- `v1.61.1` 是补丁版本，release notes 只列出 bug fixes。
- 修复同一个 `expect` instance 中自定义 matcher 与默认 matcher 同名时，默认 matcher 实现会被自定义 matcher 覆盖的问题。
- 修复 Playwright UI mode 中 `apiRequestContext._wrapApiCall` 报告 unexpected number of bytes，而 headed mode 可通过的差异。
- 修复 Trace Viewer 中 WebSocket message time 被错误按 1000 倍缩小的问题。
- 修复 Node 22.15 上 sync loader 抛出 `context.conditions?.includes is not a function` 的回归。
- 修复 sync ESM loader `registerHooks` 在 pnpm workspace symlink 场景下解析 extensionless `.ts` subpath import 失败的问题。

#### 破坏性变更

- Release notes 未标记破坏性变更。
- 这是对 `v1.61.0` 的补丁修复，不改变 Playwright CLI / Playwright MCP 的职责边界。

#### 迁移说明

- 项目如需升级，可把项目级 `@playwright/test` 更新到 `1.61.1`，并按项目既有策略运行 `npx playwright install` 或浏览器缓存检查。
- 如果项目使用 Node 22.15、pnpm workspace symlink、extensionless TypeScript subpath import、Playwright UI mode API request、Trace Viewer WebSocket 分析，建议优先采用该补丁版本。
- 本轮每日自动化不写回 `ENTRYPOINT.md`；只有用户手动输入 `更新` / `update` 才能推进当前版本基线。

#### 对 agent harness workflow 的影响分析

- 本地扫描关键词：`Playwright`、`playwright`、`WebSocket`、`websocket`、`Trace viewer`、`apiRequestContext`、`expect.extend`、`Node 22`、`ESM loader`、`pnpm`。
- 命中处理：
  - 本仓库已有 Playwright CLI / MCP 职责边界、项目级安装询问、Web UI 测试资产路径和状态枚举规则。
  - `v1.61.1` 的修复点是运行时 bug fix，不要求改动模板中的命令、配置、fallback 或使用时机。
