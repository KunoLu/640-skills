### 发布汇总

本区间跨越两个 patch：`v18.1.21`、`v18.1.22`。进入 `@oh-my-pi/pi-coding-agent` 的变化如下。

`v18.1.21`：

- 既有能力修复：Flatpak Chromium 启动器（含 `com.google.Chrome`、`org.chromium.Chromium`、`io.github.ungoogled_software.ungoogled_chromium`）把 `app.path` 当作浏览器，走受管 Chromium profile。
- 既有能力修复：规范化 `--user-data-dir <dir>` 与相对 profile 路径为绝对 `--user-data-dir=...`。
- 既有能力修复：浏览器自动化可与已运行的 Chrome 并存，使用隔离 profile，不杀死被复用的浏览器进程。
- 既有能力修复：首次安装 Chromium 与浏览器操作不再消耗 Eval runtime timeout，也不再因此重置 Eval kernel。
- 既有能力修复：启动失败后复用已成功的 system-Chrome fallback，不再在同一次 open 中重试不可用的下载。
- 既有能力修复：OMP 自有标签在后台时点击等交互不再卡住，含 worker timeout 恢复后。
- 进入 runtime 的配套：`getBrowserProfilesDir()` 默认 `~/.omp/browser-profiles`（XDG：`$XDG_STATE_HOME/omp/browser-profiles`）。
- compare 补证（coding-agent changelog 未单列）：status-line 将 subagent badge 收成图标和计数；`pi-vcs` 将 git hook lookup 失败视为 missing hooks。二者进入 CLI/runtime，不是 Trellis hook / role subagent。

`v18.1.22`：

- 破坏性变更 / 默认值变化：Hub message/job `wait` 一律使用自适应窗口（5s，连续 wait 升到 5m）；删除 `timeoutMs` 参数和 `async.pollWaitDuration` 设置。process 族带 `name` 的 `timeout`（秒）未删。
- 功能首次引入（TUI）：`omp git` / `/git` 增加 `delete`，二次确认后丢弃所选文件或目录的变更；未跟踪文件删除，已暂存文件 reset 到 HEAD。
- 既有能力增强：`/btw` 复制成功后显示确认；BTW history 可用 `Ctrl+/` 切换 pane。
- 既有能力修复：Eval `tool.todo(...)` 写入会持久化到 session，resume / rewind / fork 后仍在，不再误触发 incomplete-todo 提醒。
- 既有能力修复：`/debug` memory report 改为数值统计，不再附带可能含 provider / MCP 凭据的原始 heap snapshot；报告含隐私警告。
- 既有能力修复：自动 session title 不再取自 canned prompt 示例；本地 Ollama 标题模型把输出预算花在 reasoning 时不再保持 unnamed。
- 既有能力修复：多步登录把输入框移到最新 prompt 下。
- 既有能力修复：原生后台 security scan 接受 provider-owned AWS auth（Amazon Bedrock / Bedrock Mantle），不强制已存储 OAuth 账号。
- 进入 runtime 的配套：400 debug dump 按 header 名红acted provider auth（`x-goog-api-key`、`x-amz-security-token` 以及名称含 key/token/secret 的头）。

### 破坏性变更 / 迁移

- `v18.1.22` Release 与 tagged changelog 明确列出 Breaking Changes：message/job `hub wait` 不再接受 `timeoutMs`，也不再读取 `async.pollWaitDuration`。调用方不得再传该参数或依赖该设置；窗口由 runtime 自适应阶梯决定。这是 OMP CLI/runtime 工具契约，不是 Trellis Channel，也不是第二写入执行者。
- `irc.timeoutMs` 仍只用于 awaited send，默认 120s；不要把它和 message/job wait 窗口混为一谈。
- `omp git` / `/git` `delete` 是交互 TUI，不是工作流命令，不要求本仓库安装器迁移。
- 本机仍安装 `omp/18.1.21`；升级本机 CLI 不属于本次自动化范围。

### 平台调度核验

- `.codex/**`：不可得。`contents/.codex?ref=v18.1.22` HTTP 404；recursive tree 无 `.codex/**`。

- 当前 host vs 已配置平台目录：静态 tag 工件不得选择运行时。本仓库无 `.trellis/`，也无生成的 `.codex/**` / `.omp/**`。

分类：

- Hub adaptive wait：既有 OMP `hub` 工具的默认值变化 / 破坏性契约收紧。`docs/tools/hub.md` 写明 message/job 窗口为 `[5s, 10s, 30s, 1m, 5m]`，无 per-call 覆盖。不是 Channel，不是第二写入执行者。
- `status-line` subagent badge：compare 文件 `packages/coding-agent/src/modes/components/status-line/component.ts` 与相关测试。coding-agent changelog 未单列。属于 TUI 展示 bug fix，不是 Trellis role subagent / Channel。

- `omp git delete`、`/btw` 复制确认：TUI，不是平台调度。

处理决定：6.1 所需 Trellis 配置 / workflow / migration / 生成平台集成均在目标 tag 上不可得或明确不是 Trellis 资产，不得形成或更新平台调度规则。既有规则继续有效：`.trellis/**` 只定义共享 workflow gate；Codex `dispatch_mode` / Inline fallback 仅适用于 Codex host；OMP 使用生成的 `task` worker；Channel 保持显式确认。
