### Release 汇总

`v0.6.1` 是模板与文档层面的 workflow 简化：

- 移除冗余的 Phase 3.1 `Quality verification`，把最终全量质量检查要求合并到 Phase 2.2 的最后一次 check，把 spec-sync 提醒合并到 Phase 3.4 的 commit 前置检查。
- 保留 Phase 3 的后续编号，避免外部文档和引用因为 3.2 / 3.3 / 3.4 / 3.5 重新编号而失效。
- 将 Phase 1.3 `Configure context` 的标签统一为 required，并说明仅 sub-agent-dispatch 平台需要，inline 平台跳过。
- 同步更新 marketplace 的 `native`、`tdd`、`channel-driven-subagent-dispatch` workflow variants。
- 同步更新 bundled `trellis-meta` 的 workflow 切换参考，以及 Copilot `finish-work` prompt 的 Phase 3 流程说明。

`v0.6.2` 是跟进修复：

- `/continue` 命令的 resume-routing table 仍把 `status=in_progress + check passed` 指向已删除的 3.1；现在改为路由到 3.3 spec update，再到 3.4 commit。
- 官方内部同步矩阵增加对裸编号路由的扫描，避免未来只 grep `Phase 3.1` 而漏掉 `→ **3.1**` 这类写法。
- `0.6.1.json` 与 `0.6.2.json` migration manifest 均标记 `breaking: false`、`recommendMigrate: false`、`migrations: []`。

### 破坏性变更

未标记破坏性变更。两个 migration manifest 都明确不需要 `--migrate`。实际影响集中在 Trellis 生成的 workflow、command、bundled skill 和 prompt 模板刷新。

### 迁移说明

建议升级 Trellis 后运行：

```bash
npm install -g @mindfoldhq/trellis@latest
trellis update
```

无需运行 `trellis update --migrate`，除非项目还跨越更早版本且对应 manifest 另有迁移要求。更新后应重新读取 `.trellis/workflow.md`，并复核 `/continue` 命令、workflow variants、bundled skill 参考和平台 prompt 中的 phase / routing 是否与当前 workflow 一致。
