## Graphify

### v0.8.14 -> v0.8.17

**版本结论**：`ENTRYPOINT.md` 中当前使用版本为 `v0.8.14`，版本通道策略为 `stable-only`。GitHub Releases 显示最新稳定版为 `v0.8.17`，因此本次比较区间为 `v0.8.14 -> v0.8.17`。区间内可追溯 release notes 包括 `v0.8.16` 和 `v0.8.17`；GitHub Releases 页面未展示独立的 `v0.8.15` release notes。

**Release 汇总**：

- `v0.8.16` 修复 CJK / Unicode 标签归一化问题，避免非 ASCII 标签被归一为空字符串后错误合并。
- `v0.8.16` 新增 `.ets`（ArkTS / HarmonyOS）代码文件识别，并通过 TypeScript parser 抽取。
- `v0.8.16` 在所有 semantic-extraction chunk 都失败时以非零状态退出，不再用退出码 0 写入静默空图。
- `v0.8.16` 新增 `graphify install --project`，支持把 skill 安装到当前仓库内；各平台子命令也支持相同的 `--project` 标志。
- `v0.8.17` 修复 Go、Rust、Elixir 以及共用 generic resolver 的 Ruby、C#、Java、Kotlin、Scala 调用解析大小写问题，避免 `Authorize` 错配到 `authorize` 一类幻觉边；PHP 保留大小写不敏感解析。
- `v0.8.17` 在 graph-build 阶段丢弃不同语言族之间的 INFERRED `calls` 边，并更新 skill prompt，明确禁止生成跨语言调用边。

**破坏性变更**：没有明确标注 breaking change。但 `v0.8.16` 的非零退出行为会改变自动化脚本对 semantic extraction 失败的感知；`v0.8.17` 的跨语言 INFERRED `calls` 边清理会改变旧图中的调用关系可信度，旧图中跨语言推断调用边应被视为需要重新生成或复核的低可信结果。

**迁移说明**：

- 使用 Graphify 建图或更新图谱时，如果命令返回非零退出码，应优先检查 LLM provider、API Key、网络、文件类型解析和 semantic extraction 日志，而不是接受空图。
- 如果目标是安装项目级 Graphify skill，应使用 `graphify install --project` 或对应平台子命令的 `--project`，避免误装到用户主目录。
- 对依赖调用关系的影响分析或架构说明，遇到旧图中的 INFERRED 跨语言 `calls` 边时，应重新运行 `graphify update .` 或用源代码/局部 query 交叉验证后再采信。

**对 agent harness workflow 的影响分析**：本地扫描命中 `agents/AGENTS.project.md` 的 Graphify 小节，已有 `graphify query/path/explain`、`graphify update .`、项目级安装和 semantic extraction 失败处理规则。根据 `v0.8.17` release notes，本次最小化补充 Graphify 调用边可信度规则：跨语言 INFERRED `calls` 边不能单独作为事实依据，应重新建图或回到源码验证。根目录 `AGENTS.md`、`agents/AGENTS.global.md` 和现有 `skills/**/SKILL.md` 没有 Graphify 专属使用规则，未修改。
