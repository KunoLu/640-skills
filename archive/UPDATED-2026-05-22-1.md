## Trellis

### v0.6.0-beta.20 -> v0.6.0-beta.21

本次 `ENTRYPOINT.md` 基线为 `v0.6.0-beta.20`，版本通道策略为 `same-prerelease-channel`。当前版本是 `0.6.0-beta` 通道，因此只比较同一 prerelease 通道内更高 beta 序号。GitHub Tags 显示 `v0.6.0-beta.21` 高于 `v0.6.0-beta.20`，本次比较终点为 `v0.6.0-beta.21`。

Release 汇总：GitHub Releases 仍为空，Tags 中 `v0.6.0-beta.21` 的 tag message 仅记录 `0.6.0-beta.21`。补充检查官方 docs 子模块、GitHub compare、具体 commit diff、migration manifest 和 npm 包后，确认本次 beta patch 的实际变更是 Codex 配置兼容性修复：`trellis init` / `trellis update` 不再向生成的 `.codex/config.toml` 写入 `[features.multi_agent_v2]` block，移除了 `enabled`、`max_concurrent_threads_per_session`、`min_wait_timeout_ms`、`default_wait_timeout_ms`、`max_wait_timeout_ms` 等字段。原因是 Codex CLI 在 `0.130` 到 `0.131` 之间调整了 `features` 反序列化；结构化 table 形式只被 `0.131+` 接受，在 `0.130` 及更早版本，包括 Codex desktop app 内置的 Codex CLI，会触发 `data did not match any variant of untagged enum FeatureToml in features.multi_agent_v2`，导致整个 config 加载失败并阻塞 Codex 启动。`v0.6.0-beta.21` 改为使用 Codex 自身的 `multi_agent_v2` 默认值，如需调优应放到用户级 `~/.codex/config.toml`。

补充依据：官方 docs 子模块从 `7434c6a` 更新到 `b7cba11`，新增 `changelog/v0.6.0-beta.21.mdx` 和 `zh/changelog/v0.6.0-beta.21.mdx`；GitHub compare `v0.6.0-beta.20..v0.6.0-beta.21` 包含 3 个提交、7 个文件变更，主要涉及 `.codex/config.toml`、`packages/cli/src/templates/codex/config.toml`、`packages/cli/test/templates/codex.test.ts`、`packages/cli/src/migrations/manifests/0.6.0-beta.21.json`、docs-site 子模块和 package 版本号；具体 commit diff 显示模板删除 `[features.multi_agent_v2]` 配置块并新增防回归测试；migration manifest 标记 `breaking: false`、`recommendMigrate: false`、`migrations: []`；npm 包 `@mindfoldhq/trellis@0.6.0-beta.21` 已发布，tarball 中的 `dist/templates/codex/config.toml` 和 `dist/migrations/manifests/0.6.0-beta.21.json` 与源码结论一致，`package.json` 依赖 `@mindfoldhq/trellis-core@0.6.0-beta.21`。

破坏性变更：官方 manifest 标记非 breaking，且无需 migration command。对 Codex 0.130 及 Codex desktop app 内置 CLI 来说，这是启动兼容性修复；对 Codex 0.131+ 来说，影响是项目级 Trellis 生成配置不再强制设置 `multi_agent_v2` 并发和 wait timeout，改由 Codex 默认值或用户级配置控制。

迁移说明：存量 Trellis 项目升级到 `v0.6.0-beta.21` 后应运行 `trellis update`，以重新生成不含 `[features.multi_agent_v2]` block 的 `.codex/config.toml`。不需要额外 migration command；如确实需要调整 `multi_agent_v2`，应在用户级 `~/.codex/config.toml` 中配置，而不是依赖 Trellis 写入项目级 `.codex/config.toml`。本次每日自动化仍不得修改 `ENTRYPOINT.md` 当前版本号。

对 agent harness workflow 的影响分析：本仓库根目录没有 `.codex/config.toml` 模板，也不直接维护 Trellis 生成的 Codex project config，因此无需修改模板文件；但这不等于无需修改 Skill 规则。本次变更直接涉及 Trellis Channel 与 Codex 内置 multi-agent 的边界，`skills/trellis-channel/SKILL.md` 已更新为通用规则：明确不要在项目级 `.codex/config.toml` 写入 `[features.multi_agent_v2]`，要求 Trellis 生成或更新 Codex project config 时不生成该 block，并要求旧项目优先通过 `trellis update` 重新生成配置。自动化判断中的问题是只检查了“是否存在同名模板文件”，没有继续扫描本仓库已有 AGENTS/Skill 中是否包含 release 涉及的概念、命令或配置项；后续流程已补强为必须做本地规则影响扫描，并要求 release 触发的 AGENTS、`agents/AGENTS.global.md`、`agents/AGENTS.project.md` 和 Skill 修改都沉淀为长期通用规则，避免把具体版本号写入长期执行规则。当前仓库不存在 `.trellis/` 和 `.trellis/workflow.md`，因此仍未执行 Trellis 阶段。

依据：https://github.com/mindfold-ai/trellis/tags；https://github.com/mindfold-ai/Trellis/compare/v0.6.0-beta.20...v0.6.0-beta.21；https://github.com/mindfold-ai/Trellis/commit/0ebae43；https://www.npmjs.com/package/@mindfoldhq/trellis/v/0.6.0-beta.21
