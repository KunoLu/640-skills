Kuno Workflow 模板说明

本仓库维护 Codex 全局规则、项目级规则模板、工作流 Skill、onboard 自动化和静态说明文档。当前主流程收敛为 Codex + GitNexus + Trellis + Chrome DevTools MCP + Playwright + Maestro，并通过 SBTD 把规格、行为、测试和领域语言串成一条可验证链路；API、Web 和 Mobile / Hybrid 测试都以 BDD .feature 作为行为 SOT，shadcn/ui 项目按需使用 shadcn Skill 处理组件、registry、preset 和 CLI 工作流，公开网站、落地页和文档站按需进入 bundled seo-geo 搜索可见性检查。Codex plugin / connector、remote plugins、ChatGPT-hosted MCP 和 tool_search 是 Agent 侧工具发现和授权能力，必须先确认当前会话实际暴露 callable tool。rtk 和 caveman 是上下文 / token 效率层，不是验证工具：前者压缩 terminal 输出，但报告型测试先评估缓存与文件写入风险；后者压缩 Agent 回复且不自动开启。

SDD BDD TDD DDD Web + Mobile 验证 shadcn/ui SEO / GEO Tool Discovery Token 效率层
Trellis 任务阶段、PRD、design、implement、check、finish。
GitNexus 索引有效时做影响分析；PDG、taint、trace 和多分支查询需显式 opt-in。
Tool Discovery tool_search / plugin / connector 先确认 callable tool；catalog 只作为候选信号。
Playwright CLI 负责 Web E2E 和回归，MCP 负责探索和 locator 辅助。
Maestro 负责 Android、iOS、RN、Flutter、Hybrid App E2E；flow 资产落到 maestro/flow。
shadcn shadcn/ui 项目的组件、registry、preset、docs / diff 和 CLI 工作流。
seo-geo bundled Skill；公开 Web 资产需要搜索可见性、schema、meta、robots / sitemap 检查时才启用。
rtk / caveman rtk 压缩命令输出，但报告型测试先评估缓存与文件写入风险；caveman 安装后不自动启用，达到长任务阈值时只建议用户切换。

Workflow

当前模板主线

模板以项目事实为优先级，只有在存在强证据时才启用可选工具。普通修改保持最小、可验证、可回滚；复杂任务通过 Trellis 和相关 Skill 管理阶段、文档和验证。若已确认当前目录是项目根目录且存在项目级 AGENTS.md，但没有 .trellis/，普通项目操作只提示用户执行 trellis init -u your-name；例外是 onboard init / reset，在 Trellis CLI 已可用且用户确认 username 和 platform flags 后可主动执行 trellis init -u <username> ... --yes --skip-existing。

1. 需求读取规则、lessons 短入口，并按需读取 index / topic。
2. SBTD规格、行为、测试、领域语言对齐。
3. 影响GitNexus 可用时做影响分析。
4. 实现按项目规范和 Skill 边界改动。
5. 验证项目测试、BDD、Web、Mobile、SEO/GEO。
6. 风险发布就绪、Channel preflight、剩余风险。
7. 同步仅在用户输入 sync / 同步时写入本地生效路径。
AGENTS
常驻路由、触发条件、硬性安全边界和最终报告要求。
Skills
详细流程、命令参数、检查清单和专项判断按场景延迟加载。

Installer CLI

交互式安装入口

install.sh 面向 macOS / Linux，install.ps1 面向 Windows PowerShell。两个入口都把 source-root 定义为完整的 kuno-workflow-onboard-skills 目录，而不是仓库根目录；默认值是当前执行目录下的 ./kuno-workflow-onboard-skills。如果缺少 SKILL.md、REFERENCE.md、scripts/onboard.py、templates/ 或 assets/external-skills/stable/MANIFEST.json，安装会直接停止。

平台与 CLI 前置门
--platform codex、claude、kimi、oh-my-pi 或 omp。正常 init/reset 会先执行 check-agent-cli，并确保 npm、全局 Trellis 与 GitNexus 可用；--init-projects project-only 模式只记录平台上下文，不执行任何全局检测或安装。
多项目参数
--projects-root /abs/one,/abs/two / -ProjectsRoot "C:\one,C:\two" 接受英语逗号分隔的多个绝对目录。--init-projects / -InitProjects 可独立执行逐项目 AGENTS、.gitignore、Trellis、Playwright 和 React Bits 检查配置。
Agent npm 映射
codex → @openai/codex@latest
claude → @anthropic-ai/claude-code@latest
kimi → @moonshot-ai/kimi-code@latest
omp → @oh-my-pi/pi-coding-agent@latest。
Source Root
./install.sh --source-root /absolute/path/to/kuno-workflow-onboard-skills
.\install.ps1 -SourceRoot C:\absolute\path\to\kuno-workflow-onboard-skills
Skills
正常 init/reset 强制把 13 个 bundled Skills 和 15 个 external Skills 安装到全局目录，不再提供 project/none scope。两个根安装器从 check 结果中的 group=referenced 获取 canonical 名单并调用 --source auto，不再各自维护重复数组；caveman 和 React Bits 等原有单一作用域保持不变。
External stable fallback
auto 先按上游仓库整组 clone 和验证，任一 Skill 不兼容时整组回退 Onboard 内置 stable set；upstream / stable 是严格模式。全部 Skill 先暂存验证，再用临时 rollback backup 事务替换，canonical commit 成功后才删除 legacy 目录。
Trellis Init
全局 Trellis CLI 为必需工具；每个项目分别检查 .trellis/、执行 --yes --skip-existing 初始化并检测 .trellis/tasks/00-bootstrap-guidelines，一个项目需要 bootstrap 不会阻止其余项目继续检查。
MCP
MCP 仍由用户选择：Codex 使用用户级配置，Claude 固定 --scope user，Kimi 保持 CLI 默认行为，Oh My Pi 固定写入全局 ~/.omp/agent/mcp.json；project-only 模式完全跳过 MCP。

SBTD

四个驱动开发概念

SBTD 是本模板对 SDD、BDD、TDD、DDD 的组合简称。它不是新框架，而是用于约束 Codex 工作流的协作顺序：先明确意图和语言，再固化可观察行为，最后用测试推动实现和回归。

SDD

Specification-Driven Development。用 PRD、design、implement、验收标准和长期规则说明要做什么、为什么做、怎么验证。

BDD

Behavior-Driven Development。用户可见行为默认需要持久场景，分仓或跨端链路先做上下文完整性 gate；gherkin-bdd 携带 sync / 同步 时，全量扫描当前工作树与 features/，多仓先确认其他仓库更新状态再同步。

TDD

Test-Driven Development。适用于 bug 修复、核心逻辑、高风险改动和回归敏感路径，用红测、绿码、重构推进。

DDD

Domain-Driven Design。通过统一语言、bounded context、CONTEXT 和 ADR 降低业务术语和模型边界的不确定性。

Boundaries

工具职责边界

Codex tool_search / plugin / connector、Chrome DevTools MCP、Playwright CLI、Playwright MCP、Maestro CLI、Maestro MCP、shadcn、web-ui-autotest-generator 和 seo-geo 不互相替代。rtk 与 caveman 只负责压缩命令或对话输出；unit / API / Playwright / Maestro 报告型测试要先评估 rtk 缓存或回放是否会跳过文件写入。模板要求在最终输出中显式报告相关状态，避免把候选工具、授权能力、诊断、探索、可重复测试和搜索可见性检查混在一起。

工具 主责 边界
Codex tool_search / Plugin / Connector 发现延迟加载工具、remote / local plugin、connector 和 ChatGPT-hosted MCP 能力。 Catalog 或 marketplace 展示不等于已授权 / 已可调用；安装需用户明确请求，session auth / OAuth / cookies / tokens 不写入项目。
Chrome DevTools MCP 真实 Chrome 中的 console、network、storage、performance trace、screenshot 诊断。 提供现场证据，不作为 CI 或 E2E 通过依据。
Playwright CLI 项目内 Web E2E、Web 回归和 CI gate。 需要项目级安装；缺失时先询问用户，拒绝后只可降级为诊断。
Playwright MCP Agentic Web 探索、可访问性快照、locator 辅助。 不替代 playwright test。
Maestro CLI Android、iOS、React Native、Flutter、Hybrid App E2E 和可选 Web smoke。 Web 只适合 smoke，不作为 Web 回归主责。
Maestro MCP 设备检查、view hierarchy、截图和 flow 辅助。 依赖 Java 17+ 和 Maestro CLI；当前 Agent / IDE 的 MCP 配置需包含 JAVA_HOME / PATH env，MCP 缺失但 CLI 可用时继续 maestro test。
shadcn shadcn/ui 项目的组件、registry、preset、CLI、docs / diff 和组件组合规则。 不替代通用 UI/UX 设计判断、impeccable 视觉打磨或 React Bits Free / 付费 tier 判定。
web-ui-autotest-generator 生成和审计 repo-resident Playwright 测试资产、选择器和覆盖率。 执行底座仍是项目内 Playwright CLI。
seo-geo 公开网站、落地页、文档站、产品页、营销页的 SEO/GEO、schema、meta、robots / sitemap 和 AI 搜索可见性专项检查。 不替代 Chrome DevTools MCP、Playwright CLI、项目发布检查或内容评审；不用于内部后台、API、CLI、移动 App。
maestro-mobile-e2e 从 BDD 场景生成和维护 repo-resident Maestro Mobile / Hybrid flow，并约束报告路径。 不替代 BDD、项目验证或 Maestro CLI。
rtk 用户级全局 CLI，用于压缩 terminal 命令输出，降低上下文占用；缺失时先说明作用并询问是否协助安装。 不替代测试 runner；报告型 unit / API / Playwright / Maestro 命令先评估缓存与文件写入风险，必要时使用原生命令或 fallback-native。
caveman 用户级全局 Agent Skill，用于压缩 Agent 回复和长任务状态更新；缺失时先说明作用并询问是否协助安装；达到全局阈值时只建议用户后续切换。 不替代项目 Skill、BDD、TDD、验证、GitNexus、Trellis 或最终报告；安装后不自动开启，最终报告保持完整。

Validation

最终验证工具栈

最终验证按风险从项目原生命令开始，再叠加 BDD、Web、Mobile 和发布就绪检查。无法执行时必须说明尝试命令、失败原因、替代检查和剩余风险。

项目原生验证

优先运行项目级 AGENTS、README、package scripts、Makefile 或 CI 中定义的 lint、typecheck、static analysis、unit、integration、build；覆盖 Node、Python、Go、Dart、Java、Kotlin、C++、Swift 和 Objective-C。

行为和测试追踪

用户可见行为检查 BDD 场景和测试追踪；跨仓链路记录 full-stack、contract-backed、mock-backed、app-mocked、smoke-only 或 blocked。

Web 验证

Chrome DevTools MCP 诊断现场问题，Playwright CLI 执行可重复 Web 回归，Playwright MCP 辅助探索。

Mobile 验证

Java 17+ 通过后使用 Maestro CLI 执行移动 flow；需要设备级资产时由 maestro-mobile-e2e 从 BDD 生成 maestro/flow/*.yml。

测试资产

只有需要把 Web UI 回归固化进仓库时，才调用 web-ui-autotest-generator。

SEO / GEO

公开 Web 资产需要搜索可见性、schema、meta、robots / sitemap 或 AI 搜索引用检查时，才调用 seo-geo。

发布风险

生产路径、外部集成、部署敏感变更和高 reasoning 多 worker 并发进入风险评估；高风险 review 可做 Channel preflight，并记录用量风险。

shadcn/ui

shadcn Skill 使用边界

shadcn 是 optional external Skill，只在 shadcn/ui 项目、组件 registry、preset 或 CLI 工作流需要时启用。

启用条件
项目存在 components.json，或用户要求初始化 / 维护 shadcn/ui，执行 init/add/search/view/docs/diff/info/migrate/preset，使用 preset code、registry item、第三方 / 私有 / 付费 registry 或 shadcn MCP 配置。
实现顺序
UI/UX 任务中先用 ui-ux-pro-max 明确产品方向、信息架构、可访问性和设计系统约束，再用 shadcn 处理组件来源、CLI、registry 和具体实现规则。
组件规则
添加或更新组件前先检查 components.json、shadcn info、已安装组件和项目别名；涉及组件 API 时先查 shadcn docs，更新已有组件先用 --dry-run / --diff。
跳过条件
非 shadcn/ui 项目且用户没有要求引入 shadcn；通用 UI 设计判断、视觉 polish、后端、测试、文档或非 React UI 栈任务；React Bits Free / 付费 tier、付费 Skill 安装或 key 可用性判定。

React Bits

React Bits tier 选择边界

React Bits 不是 shadcn/ui 的必装依赖。安装和 reset 默认保持 shadcn/ui only；只有检测到目标项目是 React + shadcn/ui（存在 components.json），且任务需要更强视觉表达、动画组件、blocks 或 landing sections 时，才询问用户是否启用 React Bits。

默认选择
先说明 shadcn/ui 提供常规应用组件，React Bits Free / 付费 tier 只是可选增强。
确认选项
询问用户继续 shadcn/ui only、安装 React Bits Free，或使用已有付费 Starter / Pro / Ultimate。
Free
只有在本工作流已有明确免费 source / registry / 安装命令时才安装；未配置时说明暂不可自动安装。
Paid
Starter / Pro / Ultimate 必须由用户确认，且当前环境能读取 REACTBITS_LICENSE_KEY；不打印、不输出、不提交该 key。
Reset
保留检测到的既有 React Bits Free、Starter、Pro 或 Ultimate tier / registry，不用默认免费版覆盖。

SEO / GEO

公开 Web 搜索可见性检查

seo-geo 是 bundled Skill，只在公开网站、落地页、文档站、产品页、营销页、公开博客或公开 README 页面需要搜索可见性检查时启用。

启用条件
用户要求 SEO、GEO、AI search visibility、schema、JSON-LD、meta tags、robots.txt、sitemap.xml、canonical、关键词研究或发布前 crawl / indexing 检查。
跳过条件
内部后台、登录后页面、API、CLI、移动 App、纯后端、测试资产、文档内部重排或只需要 Web 运行时诊断 / Playwright 回归。
URL Gate
没有公网 URL 或 preview URL 时，只做源码 / HTML 静态检查；报告 SEO/GEO: static-only 或 blocked。
Credentials
基础 audit 不要求 DataForSEO；DataForSEO login / password 只作为关键词、SERP、backlink、domain overview 增强分析的可选凭据，不能写入仓库或报告。

关键词量、SERP、AI 搜索可见性和平台抓取规则具有时效性，必须用当前可用来源核对。最终输出或 Trellis check summary 必须报告 SEO/GEO: audited / static-only / blocked / skipped / not-needed。

Cross Repo Testing

跨仓测试模式和报告闭环

API、Web E2E、Mobile E2E、Hybrid E2E 或发布前 smoke 进入正式验证时，先判定链路事实是否完整。mock 只能基于 contract、schema、真实响应样例、既有 fixture 或用户确认；mock-backed 不能冒充 full-stack 通过。

测试模式
full-stack / contract-backed / mock-backed / app-mocked / backend-only / smoke-only / blocked。
默认报告目录
API 正式快照: tests/api/reports/；API 临时输出: tests/api/reports/.api-current/；Playwright 临时 HTML: tests/e2e/reports/.playwright-html-current/；Playwright 正式快照: tests/e2e/reports/html/；Maestro: .maestro/reports/；unit 需要本地证据时使用 tests/unit/reports/。
API URI 覆盖矩阵
API / integration Markdown 汇总必须把每条覆盖范围描述映射到具体 method + URI path，并记录测试脚本 / case、期望状态码或副作用、关联 feature / contract / schema；缺 URI 时标记 blocked 或 missing-uri。
Playwright Report
playwright-report-{feature_file_name}-{branch_slug}-{YYYY_mm_dd}-{HH_MM_SS}.html；branch_slug 取当前分支，/、空格和特殊字符替换为 _；smoke 使用 smoke，多 feature 优先 suite 名，否则 multi-feature。
rtk Gate
unit / API / Playwright / Maestro 报告型测试先记录 rtk: used / skipped-for-report / fallback-native / not-available / not-needed；缺报、旧报、空报或 cache hit / replay 时原生命令重跑。
最终报告
调试轮次可以保留多份带业务名、分支名和时间戳的本地快照；API、Playwright 和 Maestro 的正式报告 stem 必须包含 branch_slug，detached HEAD 使用 detached-{short_sha}，非 git 环境使用 unknown-branch。只要 Playwright 或 Maestro 产生 runner 原生报告，或 API / integration / unit runner 生成了本轮要保留的报告，无论最终是否全绿，都先生成该次运行的命名报告，再进入下一次可能清空输出的运行。正式验证范围不能由 runner 是否已经产出报告倒推决定；API stdout-only 必须捕获 api-report-*-{branch_slug}-*.txt / .json raw report，Playwright --reporter=list 和 Maestro stdout-only 都只能算诊断，收尾前必须补正式 reporter 或标记 blocked。coverage/、test-results/、固定 junit.xml 和 current 目录都不是正式快照。
Markdown 汇总
Playwright 的 .md 必须与命名 HTML 同 stem，不能用 results.json / junit.xml / 默认 index.html 的 stem；中文汇总记录运行 case、关联 BDD feature、总轮次、失败 case、原因、修复、定点重跑、影响范围重跑和最终全量重跑；API 汇总额外记录 URI 覆盖矩阵。

失败修复后先重跑失败 case / spec / flow，再跑受影响子集，最后跑计划范围内全量验证。fail-fast 停在首个失败时，修复后必须继续跑未覆盖测试或重跑全量。

Install Gates

检测、安装和 fallback

模板不默认假设工具存在。CLI、MCP、plugin、connector 或用户级全局 Skill 缺失时，先按证据检测，再根据用户确认安装、配置或降级；降级不能冒充完整验证。scripts/onboard.py 只报告 MCP 状态，根安装脚本才会在用户确认后执行平台 MCP 配置。

Codex plugin / connector
使用 tool_search、当前工具列表或 MCP 可见性确认 callable tool；catalog / marketplace / 版本展示只作为候选信号，session auth 材料不写入项目。
Playwright CLI
检测 package.json、Playwright 配置、E2E 目录和脚本。需要 Web 回归但缺失时询问是否安装到项目 devDependency。
Playwright MCP
只作为 MCP 可见性检查和探索能力；不可见时不阻塞 Playwright CLI。
Java 17+
Maestro 前先运行 java --version，失败再用 java -version。当前 JDK 满足 17+ 时优先使用当前 JDK；否则先扫描本机已有 17+ JDK。只有本机没有可用 JDK 且用户确认后，才引导安装 OpenJDK Temurin 21。
Maestro CLI / MCP
Java 通过后检查 CLI，CLI 可用后再检查 MCP。根安装脚本可把 command、args、JAVA_HOME 和 PATH 写入选定平台；MCP 缺失或 env 未配置但 CLI 可用时继续 maestro test。
Chrome DevTools MCP
由 Agent 或 IDE 配置提供，只负责诊断和证据收集；根安装脚本可为选定平台添加 chrome-devtools-mcp。
Trellis Project Setup
onboard init / reset 要先确认 Trellis CLI 可用；缺少 .trellis/ 时使用用户确认的 --trellis-user 和 --trellis-platform 执行初始化。只检查 .trellis/tasks/00-bootstrap-guidelines；命中时以 bootstrap-required 非零状态阻止误报完成，并必须继续按 trellis-workflow 完成 bootstrap task。
External Skills source policy
默认 auto 先整组验证上游，只有获取或源结构验证失败时才延迟加载 stable；有效上游不依赖 stable manifest。stable 完整性错误和目标侧 staging、权限、磁盘、commit、rollback 错误都直接失败，不触发 fallback。
External Skills stable set
assets/external-skills/stable/MANIFEST.json 记录 stable set、精确上游 commit、subpath、tree SHA-256 和许可证/NOTICE。所有 manifest、source subpath 和 license 路径必须被声明根目录包含；拒绝绝对路径、.. 和 symlink 逃逸。快照保持上游原样且不得手改；只有显式 promote-external-skills-stable 才能整组更新。
External Skills transaction
全部目标先暂存验证，再事务替换，canonical 成功后才删除 legacy。commit 失败会恢复旧目标；若恢复不完整，唯一 rollback 备份会保留并返回路径，供人工恢复。
mattpocock Skills
external Skill 使用上游 canonical 名称；to-prd / to-issues 作为 legacy alias 迁移到 to-spec / to-tickets，canonical 安装成功后再备份和删除本地旧目录。
shadcn
作为 referenced external Skill 检查存在性；用户选择安装后从 shadcn-ui/ui 的 skills/shadcn 拉取，macOS / Linux / Windows 都走同一 Python installer 逻辑。
React Bits
tier 选择只在目标项目被检测为 React + shadcn/ui 时作为条件 manual guidance 输出；普通 onboarding 不询问、不安装 React Bits。
seo-geo
作为 bundled Skill 随模板安装；缺失且任务不以搜索可见性为主时标记 skipped，缺少 URL 时标记 static-only 或 blocked。
rtk / caveman
rtk 缺失时询问是否安装全局 CLI；报告型测试可能因缓存 / 回放跳过文件写入，必要时直接使用原生命令；caveman 缺失时询问是否安装用户级全局 Skill，macOS / Linux 使用 curl ... install.sh | bash，Windows 使用 irm ... install.ps1 | iex，安装后不自动启用，只在 3 次以上状态更新、5 个以上重复摘要、上下文压力或自动化 / review / 验证排障重复轮次中建议用户后续切换。
状态报告
最终输出要列明各工具是 run、blocked、skipped、not-needed、available、installed 或对应模板状态。

Repository

源文件和同步规则

本仓库是配置摘录和模板源，不是真实业务项目。普通修改只更新仓库源文件；只有用户输入 sync 或 同步 时，才同步允许列表中的全局规则和 Skill 到本地生效路径；Skill 必须按目录整体同步，包含 kuno-workflow-onboard-skills/ 自身及其 stable External Skills 资产。sync 还会在本机实际使用路径 /Users/lusonglin/.agent/skills/ 上以 --source auto 执行 mattpocock legacy migration，删除 legacy to-prd / to-issues 并安装 canonical to-spec / to-tickets；普通 sync 不默认触碰 /Users/lusonglin/.codex/skills/ 下的同名目录。

Maintenance

README 同步规范

后续任何模板内容更新，如果影响工作流、工具职责、安装检测、SBTD、验证策略、忽略规则、同步流程或用户可见路径，必须同时评估并更新 README.md 和 README.html。如果判断无需更新，最终输出要说明原因。

当前文档与仓库模板源对齐：SBTD 负责开发方法，Codex tool_search / plugin / connector 负责 Agent 侧工具发现和授权边界，Chrome DevTools MCP / Playwright / Maestro 负责分层验证，shadcn 只在 shadcn/ui 组件、registry、preset 和 CLI 工作流中启用，web-ui-autotest-generator 和 maestro-mobile-e2e 只在需要沉淀对应 E2E 测试资产时启用，bundled seo-geo 只在公开 Web 搜索可见性检查时启用，rtk / caveman 只作为上下文效率层，报告型测试需先评估 rtk 文件写入风险。
