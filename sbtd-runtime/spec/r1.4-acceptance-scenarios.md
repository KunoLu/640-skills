# R1.4 安全、审计边界与版本兼容验收

源仓不生成 `.feature`。场景正文为中文，关键字保持英文。本文件只覆盖 R1.4 验收收口：把 §16.1／§16.2 验收矩阵与 R1 适用的导出安全钉到可执行测试，并如实声明 R1 不做的事。不覆盖 R2 Dashboard／JPEG／PDF／HTTP 导出服务；`/api/v1/exports*` 仍是 `v2.1.0-rc.2`。

每条场景标注对应测试。`sbtd-runtime/tests/test_r1_acceptance.py` 是 R1.4 新增的锁定套件；其余测试名引用既有套件（R1.1 facade、R1.2a event store、R1.2c history import、R1.3 stats/snapshot/CSV、R1.0 golden contracts），本文件不重复它们的断言。

## 审计边界

观察是显式可选能力；关闭或未经授权时，运行时连审计文件都不创建。

### Scenario: 观察开关关闭不产生审计库

Given runtime home 的 config.json 观察开关为关闭或文件不可读
When 打开 EventStore 或执行 facade 已注册写操作
Then EventStore.open 抛出 StoreError
And 不创建 audit.db，也不创建 spool
And facade 写操作的业务副作用与旧 helper 一致，审计面为零

对应测试：`test_r1_acceptance.AuditBoundaryTests.test_observation_off_creates_no_audit_files`；`test_event_store.EventStoreTests.test_switch_off_creates_no_store_or_spool`；`test_facade_registration.FacadeRegistrationTests.test_switch_off_matches_direct_helper_and_writes_no_audit`；`test_history_import.*.test_observation_off_creates_no_database`（AC-01、AC-03）。

### Scenario: 未注册根、相邻目录与 symlink 被拒绝

Given 未注册的项目根、注册根的相邻目录诱饵、或含 symlink 的根／runtime home
When 调用 facade 或打开 EventStore
Then 调用被拒绝并给出原因
And 诱饵目录不被读取
And 不创建任何审计文件

对应测试：`test_facade_registration.FacadeRegistrationTests.test_unregistered_and_sibling_bait_are_not_read`、`test_symlink_root_and_runtime_home_are_refused`、`test_intermediate_symlink_cannot_redirect_root_or_home`；`test_event_store.EventStoreTests.test_unconfirmed_and_symlink_home_create_nothing`；`test_history_import.*.test_escape_paths_and_symlinks_are_refused`（AC-04）。

### Scenario: 观察路径不改写 task.md

Given 一个已存在 task.md 状态表与历史记录的任务
When 历史导入或查询读取该任务
Then task.md 的字节不被改写
And 任务 mode／status／history 仍由 task.md 拥有，审计库不反向驱动

对应测试：`test_history_import.*.test_times_status_and_identity_come_only_from_the_table`、`test_repeat_import_only_confirms`；`test_history_read.HistoryReadTests`（task_history 复用 replay，不读不改 task.md）（AC-01）。

### Scenario: 完全只读调用不落任何文件

Given 只读上下文（list／inspect／preview 类调用，或 `EventStore.open(read_only=True)` 且库不存在）
When 执行调用
Then 不写审计文件、不写状态文件
And 只读 open 在不存在的库上报 StoreError，而不是创建空库

对应测试：`test_facade_registration.FacadeRegistrationTests.test_read_only_context_writes_nothing`；`test_event_store.EventStoreTests.test_read_only_open_does_not_create_or_append`；`test_r1_acceptance.AuditBoundaryTests.test_read_only_open_never_creates_a_store`（AC-03）。

## 去重与冲突

### Scenario: 同来源键同内容只确认

Given 一条已入库事件
When 用相同 `(source_id, source_event_id)` 与相同规范化内容再次 append
Then 返回 duplicate 确认
And replay 计数不增加

对应测试：`test_r1_acceptance.DedupConflictTests.test_same_key_same_content_only_confirms`；`test_event_store.EventStoreTests.test_replay_confirms_same_content_without_counting_twice`；`test_history_import.*.test_repeat_import_only_confirms`（AC-06）。

### Scenario: 同来源键内容冲突保留先接受者

Given 一条已入库事件
When 用相同来源键但不同内容再次 append
Then 返回 conflict（对应 OpenAPI 409 语义）
And 先接受的事件字节不被覆盖
And replay 仍是先接受的内容

对应测试：`test_r1_acceptance.DedupConflictTests.test_conflicting_content_keeps_the_first_event`；`test_event_store.EventStoreTests.test_same_source_key_with_different_content_conflicts`；`test_golden_contracts.GoldenContractTests.test_same_source_id_with_different_content_conflicts`（AC-07）。

## 版本兼容

三个版本针独立演进：事件 schema 1.0、QueryScope `schema_version` `"1.0"`、CSV `export_schema_version` 1.1。未知未来版本如实拒绝，不静默降级。

### Scenario: 事件 schema_version 必须是 1.0

Given `contracts/event.schema.json`
When 检查契约
Then `$id` 是 `urn:sbtd:runtime:event:1.0`
And `schema_version` 属性是 const `"1.0"` 且在 required 中
And 未来版本事件入库时以 schema-rejected 拒绝

对应测试：`test_r1_acceptance.VersionPinTests.test_event_schema_is_pinned_at_1_0`；`test_event_store.EventStoreTests.test_invalid_event_is_rejected_and_unlinked_stays_unlinked`。

### Scenario: QueryScope schema_version 必须是 1.0

Given 一个 QueryScope
When `schema_version` 缺失、是 `"0.9"`、或是未来版本 `"2.0"`
Then normalize_scope 抛出 QueryScopeError
And 错误指明 schema_version 字段
And 不替换成默认版本、不降级解释

对应测试：`test_r1_acceptance.QueryScopeVersionTests`（test_future_schema_version_is_rejected_honestly、test_older_schema_version_is_rejected）；`test_stats_query.NormalizeScopeTests.test_missing_schema_version_is_rejected`；OpenAPI QueryScope 的 `schema_version: const "1.0"` 由 `test_r1_acceptance.OpenApiPinTests.test_query_scope_const_matches_library`。

### Scenario: CSV export_schema_version 是 1.1 且 reasoning_tokens 是最后一列

Given #137 已并入的 CSV 合同
When 检查 `csv_export` 与 OpenAPI 导出下载操作
Then `CSV_SCHEMA_VERSION == "1.1"`
And `COLUMNS[-1] == "reasoning_tokens"`，首列是 `export_schema_version`
And OpenAPI `x-sbtd-csv-schema-version` 是 `"1.1"` 且 `x-sbtd-csv-columns` 与 `COLUMNS` 逐项一致
And reasoning_tokens 是 output_tokens 子集、绝不回加；宿主未报告时单元格留空，绝不填 0

对应测试：`test_r1_acceptance.CsvContractPinTests`；`test_csv_export.CsvExportTests.test_reasoning_tokens_is_appended_as_the_last_column`、`test_reasoning_tokens_is_a_subset_not_added_to_output`、`test_unreported_reasoning_tokens_stays_empty_not_zero`、`test_bom_and_fixed_header`。

### Scenario: 导出作业接口保持 rc.2 且不阻塞 rc.1

Given OpenAPI 的 `/api/v1/exports*` 三个操作
When 检查发布标记
Then 三者都是 `x-sbtd-release: v2.1.0-rc.2` 且 `x-sbtd-rc1-blocking: false`
And R1.4 不改变该标记

对应测试：`test_r1_acceptance.OpenApiPinTests.test_exports_stay_rc2_and_not_rc1_blocking`；`test_golden_contracts.OpenApiDraftTests.test_exports_are_rc2_and_not_rc1_blocking`。

## 无远程业务控制端点

### Scenario: 库面没有写模式／状态远程控制操作

Given OpenAPI 全部路径与本包库面
When 检查操作与 scope
Then 不存在携带 `tasks:write`、`validation:run`、`migration:apply`、`remote-command:execute` scope 的操作
And 本包是进程内库，不 import 任何 HTTP 服务框架
And info 保持 `x-sbtd-implementation: contract-only`

对应测试：`test_r1_acceptance.OpenApiPinTests.test_no_remote_business_control_operations`；`test_golden_contracts.OpenApiDraftTests.test_draft_lists_prd_routes_and_no_remote_command`；`test_golden_contracts.GoldenContractTests.test_runtime_package_does_not_import_a_server`（AC-32 的 R1 库面部分；HTTP 层的 CORS／Origin／CSRF 执行属 R2，见报告 deferred 节）。

## 诚实缺口

### Scenario: codex smoke 状态如实标记

Given `contracts/capability-matrix.json`
When 读取 smoke 状态
Then codex 的 smoke 状态是真实结果（pass／unsupported／pending 之一），parser fixture 不算 smoke 证据
And unsupported 宿主不把指标返回成 0

对应测试：`test_golden_contracts.CapabilityMatrixTests.test_completion_gate_encodes_the_adr_fallback_gate`；`test_golden_contracts.GoldenContractTests.test_unsupported_host_does_not_unsupport_the_metric`（AC-18）。

### Scenario: 快照是进程内对象，保留期望如实陈述

Given R1.3 的 SnapshotStore
When 进程退出
Then 快照随之消失；没有落盘 snapshots/ 目录
And §10.4 的 24 小时临时快照保留期是期望而非当前实现，报告与文档如实写明差异
And 过期快照报 gone，不冒用旧 id

对应测试：`test_report_snapshot.SnapshotStoreTests.test_expired_snapshot_is_gone_and_never_recycled`；文档 `docs/install-and-use.md` 与 `docs/r1.4-acceptance-report.md` 的缺口节。

### Scenario: R1 没有 HTTP 服务与 Dashboard

Given `sbtd-runtime/` 包
When 使用者需要统计或导出
Then 通过 PYTHONPATH 导入库模块完成采集、追溯、分级、去重、查询、固定快照与完整 CSV（§20.3 需求一完成）
And 没有可启动的 HTTP 服务、没有 Dashboard；OpenAPI 中非 library 标记的操作是 R2 契约而非 R1 实现

对应测试：`test_golden_contracts.GoldenContractTests.test_runtime_package_does_not_import_a_server`；`docs/install-and-use.md`。
