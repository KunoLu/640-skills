# R1.2c task 历史与验证产物导入

源仓不生成 `.feature`。场景正文为中文，关键字保持英文。本文件只覆盖“已有 task.md 状态事件 + 已有验证产物 → R1.0 事件 → R1.2a 事件库”。不覆盖 R1.2b 宿主适配器、R1.3 查询 API、HTTP 或 Dashboard。

导入来源类型是 `artifact-imported`。事件 schema 没有 `artifact` 对象。验证产物用已有的 `validation`、`external_refs`、`correlation` 表达；扩展值只放标量。不新增载荷字段。

## 只读扫描计划

`build_scan_plan` 只记录调用方点名的项目根和来源路径，`approved` 恒为 false。它不列出目录、不读文件、不打开事件库。`approve_scan_plan` 是单独的批准动作。未批准的计划调用 `import_plan` 必须拒绝，且不追加事件。

来源路径必须是项目根内的相对路径。绝对路径、`..`、符号链接一律拒绝。未点名的目录、sibling 和 HOME 不会被扫描。

### Scenario: 未批准的计划不导入

Given 调用方点名了一个 task.md 路径
When 建立扫描计划且没有批准
Then 计划 `approved` 为 false
And 计划里只有被点名的路径
And 导入被拒绝
And 事件库仍为空

### Scenario: 计划不扫描未点名的目录

Given 项目根内另有一个未点名的目录，其中放着 task.md
When 建立扫描计划
Then 该目录不出现在计划中
And 建立计划的过程不读取文件内容

## task.md 状态历史

解析复用 `TaskDocument.parse`（`markdown-it-py` 定位 `## 状态事件`）。不手写一套表格扫描，不改 task.md。

每一行状态事件变成一条观察事件：`done → planned` 为 `task.reopened`，其余为 `task.state_changed`。`at` 为 `unknown` 或无法按 schema 证明的时间时，`occurred_at` 为 null。`recorded_at` 是本次导入的观察时间，不回填到 `occurred_at`。frontmatter 的 `created_at` 单独不产生 `task.created`。`task_uid` 保持 null，除非调用方显式传入；不从路径哈希造任务身份。`workflow.mode_at_event` 为 `unknown`：frontmatter 里的当前模式不能代表历史每一行。reason／evidence 单元格不复制进事件。

观察等级是 `declared`，证据状态是 `present`：这是文件里写下的状态，不是一次被观察的执行。

### Scenario: 有时区的时间原样保留，未知时间为 null

Given 状态表里一行是带时区的时间，另一行 `at` 为 `unknown`
When 批准后导入
Then 前者 `occurred_at` 等于该单元格
And 后者 `occurred_at` 为 null
And 两行的 `recorded_at` 都不是那两个历史时间
And task.md 的字节不变

### Scenario: 重开与普通状态变化分开

Given 一行是 `done → planned`，另一行是 `planned → in-progress`
When 导入
Then 前者是 `task.reopened`
And 后者是 `task.state_changed`
And 没有 `task.created`

## 验证产物

只接受调用方点名的 validation-evidence envelope。校验复用 `validate_validation_evidence.validate_v2`，用例解析复用它的 `parse_junit` / `parse_playwright`。不复制 XML 解析，不读 HTML 标题。

`validation.result = passed` 只在三件事同时成立时出现：`validate_v2` 没有报错、envelope 的 `e2eMode` 能直接映射到事件 schema 的 `narrow` / `full-stack` / `contract-backed`、解析出的用例里至少有一条 `passed` 且没有 `failed`。`mock-backed` 等其余模式不改写成这三档，也不记成通过。校验失败时结果是 `unknown` 或没有 `validation` 对象，观察等级保持 `declared`。HTML 标题里的 passed 不产生事件。

报告关系：`external_refs` 指向报告 sha256（`system=validation-evidence`，`object_type=report`），`correlation.operation_id` 指向 envelope 的 `runId`（放得进 128 字符时）。

### Scenario: 校验通过的 envelope 记为通过

Given 一个 `validate_v2` 能够接受的 playwright envelope，`e2eMode` 为 `full-stack`
When 批准后导入
Then 产生 `validation.finished`
And `validation.result` 为 `passed`
And `provenance.observation_level` 为 `artifact-verified`
And `provenance.source_kind` 为 `artifact-imported`
And `external_refs` 含该报告的 sha256
And 事件里没有 `artifact` 对象

### Scenario: HTML 标题不是通过

Given 文件内容是 HTML，且 title 为 passed
When 把它当作验证 envelope 导入
Then 不产生事件
And 没有任何 `validation.result = passed`

### Scenario: 对不上的 e2e 范围不记成通过

Given envelope 能通过校验，但 `e2eMode` 是 `mock-backed`
When 导入
Then 没有任何 `validation.result = passed`
And 证据状态可以是 `validated`，因为校验器确实跑过

## 开关与重放

观察开关关闭时，打开事件库失败，不创建 `audit.db` 或 `spool`。同一计划导入两次，第二次只确认，重放条数不变。
