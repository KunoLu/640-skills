# R1.2b Codex／OMP 宿主来源适配器

源仓不生成 `.feature`。场景正文为中文，关键字保持英文。本文件不覆盖 R1.2c 历史导入、R1.3 查询 API 或 HTTP 服务。事件存储语义见 `r1.2a-event-store-scenarios.md`；本文件只覆盖“宿主记录 → R1.0 事件 → 事件库”的翻译与回执。

## 扩展值规范化（extensions.py）

扩展值的权威约束是 `contracts/event.schema.json`：最多 8 个键，值只能是 string（≤256）、number、boolean、null。适配器在构造事件前规范化宿主数据，丢弃策略如下，且每个被丢弃的键都进入结构化回执的 `dropped` 清单（键名 + 原因）：

1. 嵌套对象压平成点连接键（`{"a": {"b": 1}}` → `a.b`）。
2. 数组整体丢弃，原因 `dropped-array`。数组不压平：下标键会消耗键数且顺序不稳定。
3. 字符串超过 256 字符丢弃，原因 `dropped-too-long`。不截断：半截字符串会被误读为完整值。
4. 非有限数值（NaN、±Infinity）丢弃，原因 `dropped-non-finite`。
5. 其他非标量值（bytes、自定义对象等）丢弃，原因 `dropped-unsupported`。
6. 压平后的键命中 #132 秘密键匹配（大小写、`-`／`_`／camelCase 规范化后的后缀或分段匹配，如 `github_token`、`x-api-key`、`authToken`、`client_secret`、`cookies`；`token_count`、`input_tokens` 不算）时丢弃，原因 `dropped-secret`。事件库的整事件拒绝仍是第二道防线。
7. 前 6 步之后仍超过 8 个键时，按声明的 priority 顺序保留，其余键按字母序排在后面，第 9 个起丢弃，原因 `dropped-over-limit`。即：priority 列表里的键先留，priority 之外字母序小的先留，被丢的是“priority 尾部之后、字母序尾部”的键。

### Scenario: 嵌套对象压平成点连接键

Given 宿主数据是 `{"args": {"count": 3, "ok": true}}`
When 规范化扩展值
Then 得到 `{"args.count": 3, "args.ok": true}`
And 没有键被丢弃

### Scenario: 数组与超长字符串被丢弃并点名

Given 宿主数据含数组值和 300 字符字符串
When 规范化扩展值
Then 这两个键不出现
And 回执 `dropped` 记录键名与原因 `dropped-array`、`dropped-too-long`

### Scenario: 秘密键在入库前被丢弃

Given 宿主数据含 `apiKey`、`x-api-key`、`authToken`、`cookies` 与 `token_count`
When 规范化扩展值
Then 前四个键以 `dropped-secret` 丢弃
And `token_count` 保留

### Scenario: 超过 8 键按声明策略丢弃

Given 规范化后有 10 个标量键，priority 声明了其中 2 个
When 应用键数上限
Then 保留 8 个：先是 2 个 priority 键，再是其余键按字母序的前 6 个
And 被丢的 2 个以 `dropped-over-limit` 记录
And 结果通过事件 schema 的 maxProperties 校验

## OMP 适配器（omp_adapter.py）

来源是 omp 会话 JSONL 文件（`~/.omp/agent/sessions/<cwd-slug>/<file>.jsonl`），适配器只读调用方显式给出的路径。parser_version 为 `omp-session-jsonl-1`。

### Scenario: toolCall 记录映射为 invocation.started

Given 一条 assistant 消息含 `{"type": "toolCall", "id": ..., "name": "bash"}` 项
When 适配器解析该会话文件
Then 产出 `invocation.started` 事件
And component 是 `tool:bash`、kind 为 `tool`
And occurred_at 取记录时间戳
And correlation.invocation_id 取 toolCall 的 id
And provenance.source_kind 是 `host-observed`、observation_level 是 `execution-observed`
And host 是 `omp` 与记录中的 runtime.version

### Scenario: read 一个 skill:// 路径记为 skill.loaded

Given toolCall 的 name 是 `read` 且 arguments.path 以 `skill://` 开头
When 适配器解析
Then 产出 `skill.loaded` 事件
And component 是 `skill:<名>`、kind 为 `skill`
And 该事件只陈述宿主读入了 skill 资源

### Scenario: toolResult 映射为 invocation.finished 并计算时长

Given 同一 toolCallId 先有 toolCall、后有 toolResult 且 isError 为 false
When 适配器解析
Then 产出 `invocation.finished`，state 从 `running` 到 `succeeded`
And measurement.duration_ms 是两条记录时间戳之差、duration_basis 为 `wall`

### Scenario: isError 的 toolResult 记为失败

Given toolResult 的 isError 为 true
When 适配器解析
Then `invocation.finished` 的 state.current 是 `failed`

### Scenario: 端到端入库、重复 ingest 只确认

Given 观察已开启且事件库已确认打开
When 适配器对同一文件 ingest 两次
Then 第一次回执 accepted 等于事件数
And 第二次全部 duplicate
And replay 计数不变
And checkpoint 记录了 source_id、segment、offset 与 parser_version

### Scenario: 未知记录与坏行不崩且计数

Given 文件含未知 type 记录与一条不完整 JSON 尾行
When 适配器解析
Then 该尾行与未知类型被跳过并计入回执
And 其他事件正常产出

### Scenario: 观察开关关闭时适配器不写库

Given 观察开关关闭
When 适配器尝试 ingest
Then 打开事件库被拒绝
And 没有 audit.db 或 spool

## Codex 适配器（codex_adapter.py）

来源是 `codex exec --json` 的 JSONL。parser_version 为 `codex-exec-jsonl-1`。本仓库不安装不运行 codex；字段形状以公开 exec JSONL 格式为准，真实 smoke 由另一 bot 用 `codex@0.163.0` 按 `sbtd-runtime/docs/host-adapters.md` 的指令执行。

### Scenario: command_execution 项映射为 invocation 事件

Given 一行 `item.started` 与一行 `item.completed`，item.type 都是 `command_execution`、共享 item.id
When 适配器解析
Then 产出一对 `invocation.started` / `invocation.finished`
And component 是 `tool:command_execution`
And 完成行的 exit_code 进入扩展标量
And correlation.invocation_id 取 item.id

### Scenario: mcp_tool_call 映射为 mcp 组件

Given item.type 是 `mcp_tool_call`，含 server 与 tool
When 适配器解析
Then component kind 是 `mcp`，component_id 含 server 与 tool

### Scenario: 完成状态映射

Given item.completed 的 status 分别是 completed、failed、declined
When 适配器解析
Then state.current 分别是 `succeeded`、`failed`、`declined`

### Scenario: 文件模式不伪造发生时间

Given 以保存文件方式 ingest
When 适配器解析
Then 事件 occurred_at 为 null
And recorded_at 是入库时间

### Scenario: 未知 item 类型与非 item 行跳过

Given 流含 `thread.started`、`turn.completed`、`item.updated` 与未知 item.type
When 适配器解析
Then 不产生 invocation 事件的部分被跳过并计数
And 不产生错误

## 结构化回执

### Scenario: 回执陈述一次 ingest 的真实结果

Given 一次适配器 ingest
When 运行结束
Then 回执含 source_id、host_kind、host_version、parser_version、读取记录数、跳过数、产出事件数
And 含事件库 append 的 accepted/duplicate/conflict/rejected 计数
And 含被丢弃扩展键及原因清单
And 回执不是宿主能力证明；capability matrix 的 smoke 状态只由真实 smoke 更新
