# R1.3 统计 API、快照、数据集与 CSV

源仓不生成 `.feature`。场景正文为中文，关键字保持英文。本文件只覆盖 R1.3：QueryScope 规范化、统计 query／timeseries、任务历史读取、ReportSnapshot 与 dataset cursor、全量 CSV 序列化。不覆盖 R1.4 安全收口、HTTP 服务、Dashboard、JPEG／PDF；`/api/v1/exports*` 仍是 `v2.1.0-rc.2`。

三条硬门贯穿全部场景：区间一律半开 `[from, to)`；query／timeseries／dataset 各页／CSV 共享同一 `snapshot_id`；缺失数据不编造（不填 0，0 个可判定样本不是 100%）。

## QueryScope 规范化

无效输入明确报错并指明字段，不替换成默认范围。`schema_version` 必须是 `"1.0"`；`range.from`／`range.to` 必须是带时区的 ISO 8601 且 `from < to`；`timezone` 必须是有效 IANA 名；`metrics` 里的每个 id 必须在指标目录中。空 filters 数组表示该维度不过滤。

### Scenario: 无效指标被拒绝并指明字段

Given 一个 QueryScope 的 metrics 含有目录外的 id
When 规范化
Then 抛出 QueryScopeError
And 错误指明 metrics 字段与该 id
And 不返回任何指标值

### Scenario: 空区间被拒绝

Given from 等于 to
When 规范化
Then 抛出 QueryScopeError
And 不产生默认窗口

## 半开时间窗

窗口归属规则复用 `contract_eval._time_class`：`start <= occurred_at < end`。本包不重写这套规则。

### Scenario: 右端点事件在窗外

Given 一个事件的 occurred_at 恰好等于 to
When 按该 scope 查询
Then 该事件不计入任何指标
And 它也不出现在任何 timeseries 桶里

### Scenario: 左端点事件在窗内

Given 一个事件的 occurred_at 恰好等于 from
When 按该 scope 查询
Then 该事件计入

### Scenario: 东京时区与 UTC 表示同一窗口结果一致

Given 同一组事件
When 一次用 `2026-10-15T15:00:00Z` 起止、一次用等价的 `+09:00` 东京起止查询
Then 两次指标值完全一致

### Scenario: DST 民事日按真实时刻处理

Given golden 的 dst_fixture（America/New_York 2026-11-01，25 小时民事日）
When 用该民事日起止做 timeseries
Then 桶边界是真实时刻
And 窗口长度是 25 小时而不是 24 小时

Given 范围内没有任何机器观察到的 step.finished
When 查询 steps.success_rate_observed
Then value 为 null
And sample_status 为 no-decidable-sample
And 不是 0，也不是 1

### Scenario: 缺失 token 不填 0

Given usage 记录缺少 cache_read_tokens
When 查询 usage.tokens 并导出 CSV
Then 指标里该字段为 null
And CSV 单元格为空字符串，不是 0

## 共享 ReportSnapshot

### Scenario: query、timeseries、dataset、CSV 共享同一快照

Given 相同 QueryScope 与相同接收水位
When 依次执行 query、timeseries、dataset 翻页与 CSV 序列化
Then 四者引用同一 snapshot_id
And 快照只创建一次

### Scenario: 水位变化后不复用旧快照

Given 已有快照之后又接收到新事件
When 用相同 QueryScope 再查询
Then 得到新的 snapshot_id
And 旧快照内容不变

### Scenario: 跨快照 cursor 被拒绝

Given 快照 A 的 cursor
When 用它向快照 B 翻页
Then 报错，不返回混合页

### Scenario: 快照过期不冒用旧 id

Given 一个已过期的快照
When 再次以相同条件创建
Then 新快照使用新 snapshot_id
And 读取旧 id 报 SnapshotGone

## 数据集 cursor 分页

明细数据族按（数据族序，record_id）稳定排序。cursor 是不透明字符串，只编码 snapshot_id 与 offset。默认每页 100，最大 1000。

### Scenario: 全范围翻页不缺不重

Given golden 数据集的快照
When 用小页 limit 遍历全部 dataset 页
Then 所有页的 record 键集合无重复
And 总数等于 dataset_manifest 各族合计
And 最后一页 next_cursor 为 null

### Scenario: 坏 cursor 明确报错

Given 一个无法解码或 offset 越界的 cursor
When 翻页
Then 抛出 CursorError
And 不返回空页冒充成功

## CSV 数据集

固定列见 PRD §13.8。UTF-8 BOM 开头；标准 CSV 引号转义；null 留空；数值不带千分位和货币符号；用户可控文本以 `= + - @` 或前导控制字符开头时按 `csv-text-escape-v1` 加 `'` 前缀；合法负数值列不转义。`record_type` 覆盖 §13.8 数据族；本包能从事件推导的族产生行，`artifact` 族当前无来源（事件 schema 没有 artifact 对象），manifest 记 0 行。结构化指标值（如分布）以紧凑 JSON 放在 `metric_value` 列。

### Scenario: CSV 遍历完整筛选范围

Given 一个快照
When 序列化 CSV
Then 明细族行数等于 dataset_manifest 各族合计
And 不受 dataset 分页 limit 影响
And metadata 行记录每族行数与过滤范围

### Scenario: 公式注入被转义

Given 某 actor_alias 以 `=` 开头
When 导出 CSV
Then 该单元格以 `'` 开头
And 负数 duration_ms 保持数值不带前缀

### Scenario: CSV 以 BOM 开头且列固定

Given 任一快照
When 序列化 CSV
Then 首字节是 UTF-8 BOM
And 表头等于 §13.8 固定列集

## 任务历史读取

读取复用 `EventStore.replay()`，不重扫文件，不改 append／dedup。`task_history` 返回该任务的状态／模式事件，按接收序排列；`occurred_at` 为 null 的历史事件保留在时间不可定位集合，不塞进窗口。

### Scenario: 任务历史来自事件库

Given golden 事件追加进事件库
When 读取 task_leaf 的历史
Then 得到该任务的 task.\* 与 mode.\* 事件
And 顺序与 replay 一致
And task.md 不被读取或改写

### Scenario: 历史列表半开窗口过滤

Given 一个事件的 occurred_at 等于窗口 to
When 用该窗口调用 list_events
Then 该事件不在结果中
