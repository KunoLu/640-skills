# R2.2 原生 E2E 与导出对账

沿用中文场景／English Gherkin keywords；不新增 runner。自动化：
`tests/runtime_e2e.py`、`tests/test_export_reconciliation.py`、`tests/test_serve_signals.py`
（路径相对于 `sbtd-runtime/`）。AC-33／45／51／62 平台部分；性能归 PR-4。

```gherkin
Feature: 原生启动、导出与退出
  Scenario: 原生平台完成同一快照的导出
    Given 本地观察数据已通过真实 EventStore 写入隔离 runtime home
    And 固定版本的可选 renderer 已尝试安装
    When 前台 serve 启动并通过一次性 ticket 文件完成配对
    Then health、catalog 和 statistics API 可用
    And 同一快照的 HTML 和 CSV 可下载且摘要与大小匹配
    And renderer 可用时 JPEG 和 PDF 必须真实生成并下载
    And renderer 不可用时报告记录 unavailable 和原因并验证 API 拒绝
    And 可用 renderer 的字体就绪且 CJK 字体实际产生报告标题字形

  Scenario: Windows 控制信号正常释放实例
    Given 前台 serve 已启动并持有实例锁
    When Windows 收到 CTRL_BREAK 或 POSIX 收到 SIGINT
    Then 服务正常退出且退出码为零
    And 实例锁移除且监听端口关闭

  Scenario: 四格式关键数值与逻辑 Panel 一致
    Given 四个导出固定同一快照
    When 对比 HTML 正文、CSV metric 行与 JPEG 和 PDF 的实际 renderer 输入
    Then 任务数与步骤成功率一致
    And manifest 的每个逻辑 Panel 均出现且无额外或重复 Panel
    And CSV 对应 metric 与数据族元数据及实际明细行数一致
    And 已有 pdftotext 可用时 PDF 正文中的 Panel、CJK 与关键值也一致
```

证据边界：JPEG 输入结构／数值不是 pixel OCR；PDF 缺抽取工具时仅源文档对账。
无 browser 环境的单元测试沿用既有 worker stub 并明确标注，不替代原生 runner。
Windows POSIX 0600 位不能作为 NTFS ACL 证明；CI 使用隔离临时目录。
本地 POSIX 的 SIGBREAK 编号模拟只检验 uvicorn 清理链，不冒充 Windows。
用户 Mac 视觉／字体确认与 JPEG/PDF 人工视觉验收仍待 D9 真机补证。
