# R2.0c 临时 ReportSnapshot 落盘场景

依据：D13、PRD §10.4、ADR 0003。沿用项目 Markdown 场景，不新增 Gherkin runner。语言：中文描述＋英文关键词。测试 seam：SnapshotStore、真实 serve；Mock Strategy: none（写入故障注入除外）。

## Scenario: 创建告知有效期且重启不改变快照

Given 一个 runtime home 和真实已采集数据
When 创建快照并重启服务
Then 创建响应告知 expires_at 为创建后 24 小时
And 原 snapshot_id 在 TTL 内仍解析为相同数据、摘要和分页 cursor
And 重启或复用不延长 expires_at

对应：test_snapshot_persistence 的 restart/default expiry 用例；真实 serve restart smoke。

## Scenario Outline: 半成品与不支持的格式不成为快照

Given 磁盘上存在 <异常> 的快照文件
When 启动服务并读取该 snapshot_id
Then 不返回有效快照
And 不替换原始审计库或将坏文件冒充空快照

Examples:

| 异常 |
|---|
| 截断写入 |
| 缺 checksum |
| 错误 format_version |
| 内容与 checksum 不一致 |
| 重复字段或非法 payload |

对应：test_snapshot_persistence 的 corruption 用例。

## Scenario: 写入失败不可发布半成品

Given 已存在一个有效快照
When 新快照在文件 fsync 或原子发布前失败
Then 创建失败明确可见
And 原快照仍可读取，新快照不作为有效快照返回
And 遗留临时文件不会被 startup 当作快照

对应：test_snapshot_persistence 的 atomic failure 用例。

## Scenario: 启动清扫严格限制所有权

Given snapshots/ 有已过期和未过期快照、未知文件与链接
And exports/、audit.db、配置及源任务／报告／handoff 存在
When 启动 SnapshotStore
Then 只删除 snapshots/ 内本扩展有效且已过期的无引用快照
And 未过期快照与其他目录内容不变
And 不递归、不跟随链接；损坏文件保留且不可读

对应：test_snapshot_persistence 的 startup sweep scope/path safety 用例；授权依据 §10.4 / D13，非 AC-61。

## Scenario: 在途引用覆盖有效期直到最后释放

Given 一个快照有两个服务端引用
When TTL 到期并清扫，随后只释放一个引用
Then 原快照仍可读且文件保留
When 最后引用释放并清扫
Then 原快照不再可读且文件可回收
And 新查询不得复用旧 snapshot_id

对应：test_snapshot_persistence 的 pin protection 用例。R2.0b UI PinRegistry 固定 ID；R2.1a 按 ADR 0003 调用后端 pin/release。

## Scenario: 恢复引用先于启动清扫

Given 作业所有者提供一个已过期快照的恢复引用 ID
When 以该引用启动 SnapshotStore
Then startup sweep 不删除该快照，读取仍成功
And 释放恢复引用后正常清扫

对应：test_snapshot_persistence 的 restored pins 用例；不宣称导出作业已实现。

## Scenario: 快照文件最小权限

Given 一个隔离 runtime home
When 创建快照
Then POSIX home/snapshots 目录权限为 0700，正式与临时文件为 0600
And symlink/junction 越界路径被拒绝

对应：test_snapshot_persistence 的 permissions/path safety 用例；Windows ACL 不由 Linux 测试证明。
