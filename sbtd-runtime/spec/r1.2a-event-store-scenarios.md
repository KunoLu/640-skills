# R1.2a 事件库、去重、spool、checkpoint 与质量记录

源仓不生成 `.feature`。场景正文为中文，关键字保持英文。本文件不覆盖 R1.2b 宿主适配器、R1.2c 历史导入或 R1.3 查询 API。

## Scenario: 观察开关关闭时不建立事件库

Given 观察开关关闭、缺失或不可读
When 确认打开事件库
Then 打开被拒绝
And 运行时目录没有 `audit.db` 或 spool

## Scenario: 相同来源事件重放不重复计数

Given 观察已开启且事件库已确认打开
And 一条符合 R1.0 事件契约的观察已经接受
When 同一来源键和同一规范化内容再提交两次
Then 后两次只确认
And 重放仍只有一条已接受事件

## Scenario: 相同来源键但内容不同被拒绝覆盖

Given 某来源事件 ID 已经接受
When 同一来源键带着不同规范化内容再次提交
Then 结果为冲突
And 重放仍是先接受的那条

## Scenario: 乱序到达都保留且按入库顺序重放

Given 两条发生时间不同的新事件
When 较晚发生的事件先入库，较早发生的事件后入库
Then 重放按入库顺序包含两条
And 后到的较早事件不覆盖先到的较晚事件

## Scenario: 截断的待入库尾部不补造事件

Given 一批待入库事件在提交前尾部被截断
When 重新打开事件库
Then 只有完整前缀被接受
And 被截断的事件不出现在重放中
And 质量记录标出截断

## Scenario: 损坏的事件库不被换成空库

Given 已有事件的 `audit.db` 被截断或损坏
When 再次打开事件库
Then 打开被拒绝
And 损坏文件不被替换成可重放为空的新库

## Scenario: 崩溃后从 spool 恢复且不重复计数

Given 待入库批次已经落盘，进程在数据库提交前退出
When 重新打开事件库
Then 该批次被接受一次
And 再次打开后重放计数不变

## Scenario: 部分失败不把未提交事件报成已接受

Given 同一批有两条可接受事件
When 第一条已经提交，第二条提交前失败
Then 重放只有第一条
And 失败结果不表示两条都已接受
And 再次打开后第二条才被接受一次

## Scenario: 带前缀或驼峰的敏感扩展名不入库

Given 观察已开启且事件库已确认打开
When 扩展名是 github_token、x-api-key、X-Api-Key、authToken 或 client_secret
Then 这些事件被拒绝
And 敏感值不出现在重放或运行时文件中

## Scenario: token 计数字段仍入库

Given 观察已开启且事件库已确认打开
When 扩展名是 token_count、input_tokens 或 tokens
Then 事件被接受
And 重放仍包含该计数值
