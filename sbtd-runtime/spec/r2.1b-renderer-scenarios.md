# R2.1b：固定报告的 JPEG／PDF 导出

范围：D3/D4/D16、PRD §13.5–13.7、AC-42/58，以及 AC-51 的四格式事件明细屏蔽一致性回归（完整 AC-51 验收仍归 R2.2）。#153 合并后 HTTP 接受 html/csv/jpeg/pdf。场景由 renderer 单元／真实浏览器测试与 integration 测试追踪；依赖故障及浏览器替身为用户要求的 mock-backed 证据，真实浏览器另行运行，缺依赖明确 skip。单仓上下文 complete，无外部业务服务。

```gherkin
Feature: 受控浏览器生成固定快照报告
  Scenario: 缺少可选依赖不影响原有格式
    Given 未安装 Playwright 或专用 Chromium
    When 查询导出能力
    Then JPEG 和 PDF 不可用且有原因
    And HTML 和 CSV 仍可导出

  Scenario: HTTP 接受固定快照的 JPEG 和 PDF
    Given 已配对 session、有效快照与可用 renderer
    When 通过 HTTP 请求 jpeg 或 pdf
    Then 返回 202 且 data 仅包含 export_id
    And 轮询至 ready 后可下载 image/jpeg 或 application/pdf 文件
    And 原有认证、CSRF、Host／Origin、请求校验与幂等规则不变

  Scenario: HTTP 在受理前拒绝超限 JPEG
    Given 固定报告在 1x 仍超过生效尺寸上限
    When 通过 HTTP 请求 jpeg
    Then 返回 422 且 body 恰含 detail、max_edge_px、max_total_pixels
    And detail 为 EXPORT_IMAGE_SIZE_LIMIT，两项上限为当次生效值
    And 不创建作业或文件、不遗留快照引用

  Scenario: HTTP 在受理时通知 JPEG 降级
    Given 固定报告在 2x 超限而 1x 完整且符合上限
    When 通过 HTTP 请求 jpeg
    Then 202 的 meta.warnings 包含且仅出现一次 EXPORT_SCALE_DOWNGRADED:1x
    And data 仍仅包含 export_id
    And 作业使用预检的同一静态报告、呈现状态、生效上限和 1x 比例
    And 生成时若该比例不再安全则失败，不静默改比例或截断
    And 保留期内，相同幂等请求在服务重启前后均返回同一作业和原有降级告警，不重新预检

  Scenario: 导出能力沿用访问控制
    Given 未配对 session 或不合法的 Host／Origin
    When 查询导出能力
    Then 未认证返回 401，非法 Host／Origin 返回 403
    And 已认证合法请求中 JPEG／PDF 的 http_available 与 renderer 可用性一致，不可用时附原因

  Scenario: 四格式不泄漏被屏蔽事件明细
    Given 同一快照含 exportable 为 false 或非 local-metadata 的事件
    When 在库面导出 HTML、CSV、JPEG 和 PDF
    Then 事件明细屏蔽集合和计数一致
    And HTML、CSV、图像源文档及 PDF 文本不包含被屏蔽的明细数据
    And 派生任务、运行及汇总的既有语义不变

  Scenario: 每作业独立且禁止外联
    Given 报告中测试注入外部图像、fetch 和 file 访问探针
    When 受控浏览器渲染报告
    Then 请求被拒绝且不读取用户浏览器登录态
    And 每作业使用新的临时 profile 并在结束后删除
    And 同时最多运行一个 JPEG 或 PDF 作业

  Scenario: 长图预检不截断
    Given 标准 1440 CSS px 宽度和当前主题的报告
    When 生成 JPEG
    Then 等待字体与布局完成并关闭动画后输出完整不透明长图
    And 优先使用 2x 和质量 90
    But 2x 超过单边 32000 px 或 80000000 像素时仅在内容完整且宽度不低于 1440 CSS px 时降到 1x
    And 截图前向库调用方发出 EXPORT_SCALE_DOWNGRADED:1x，manifest 保留同一固定字符串
    And 建议尺寸上限可由模块常量配置，实测后冻结；配置对独立 worker 生效
    And 1x 仍超限时以 EXPORT_IMAGE_SIZE_LIMIT 安全失败，不截断、不分包、不发布半成品

  Scenario: 接受作业前可独立检查报告布局
    Given 固定快照、呈现状态与当前配置的尺寸上限
    When 库调用方在接受作业前请求 JPEG 或 PDF 预检
    Then 在隔离浏览器内等待字体和布局，不截图、不生成 PDF、不创建导出作业
    And JPEG 返回可用的 2x 或 1x 比例及告警，PDF 返回空比例
    And JPEG 降级告警为 EXPORT_SCALE_DOWNGRADED:1x
    And 超限错误携带当前生效的 max_edge_px 和 max_total_pixels
    And 成功或失败都清理临时 profile，生成时仍重新检查尺寸

  Scenario: PDF 保留可搜索文字与长表
    Given 含中文、日本語のテキスト・カタカナ、English 和跨页表格的报告
    When 生成 PDF
    Then 输出 A3 横向、10mm 页边距并保留背景
    And 所有 Panel 有序出现、长表重复表头且不横向裁切
    And 页脚包含标题、范围、短 snapshot_id 和页码，实际字号不低于 8pt
    And 中日英文字及平假名／片假名可搜索且 CJK 字体嵌入

  Scenario: 取消和超时清理本作业
    Given 浏览器正在预检或生成报告
    When Store 关闭、作业取消、超时或浏览器失败
    Then 停止本作业子进程并删除临时 profile
    And 不发布半成品、不泄漏路径且释放快照引用

  Scenario: 图像和文档复用现有产物生命周期
    Given JPEG 或 PDF 已 ready
    When 重复下载、重启恢复或执行到期清扫
    Then 摘要和过期时间保持不变
    And 仅由现有 ExportStore 管理 exports 内产物及 manifest
```
