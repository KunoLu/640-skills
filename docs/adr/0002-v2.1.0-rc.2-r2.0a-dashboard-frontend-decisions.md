# ADR 0002：v2.1.0-rc.2 R2.0a Dashboard 前端决策（产物体积预算、npm 审计基线、`#ticket` URL 风险）

> 状态：accepted
> 日期：2026-10-19
> 范围：`v2.1.0-rc.2` R2.0a **PR-1**（前端骨架＋Panel manifest＋重建一致 CI）。PR-2（`serve` 与访问控制 D5–D8 实现）不得变更本文决策；任何变更单独提出。
> 依据：grill-r1.md 锁定决定 D1、D2、D7、D14、D17；PRD v0.2 §10.2、§12.3、§13.4、§19.3；ADR 0001 §5。

## 1. 产物体积预算（D1 配套）

### 背景

D1 锁定前端构建产物入仓 `sbtd-runtime/dashboard/static/`，使 Python 侧 `serve` 零 npm 依赖即可发页。入仓产物若无预算约束，依赖膨胀会把仓库 diff 与评审面无限拉大；§13.4 同时要求离线 HTML 导出自包含，产物体积直接决定内联成本。

### 决策

产物体积预算固定为（机器可读事实源：`sbtd-runtime/dashboard/artifact-budget.json`，由 `check_artifacts.py` 与 CI 强制执行）：

| 预算 | 值 | 基线实测（2026-10-19，vite 6.4.4 精确钉版） |
|---|---|---|
| `static/` 全部文件总字节 | ≤ **524,288 字节（512 KiB）** | 241,853 字节 |
| 单个资产文件 | ≤ **409,600 字节（400 KiB）** | 236,927 字节（`assets/index-*.js`） |

基线余量约 2.2×。超出预算即 CI 失败；提高预算须修改 `artifact-budget.json` 并修订本 ADR。

### 理由

512 KiB 总量覆盖 React 19 运行时（约 233 KB 未压缩）加一倍以上的应用代码增长空间，同时保持产物可被 §13.4 离线 HTML 内联。单文件预算防止出现不可审的巨型 bundle。

## 2. npm 审计基线（D2 配套）

### 背景

D2 锁定 Vite 精确钉版＋lockfile 入仓＋CI `npm ci`＋依赖审计。审计若无固定基线，「当时没细看」会随时间变成默许。

### 决策

- 钉版（`sbtd-runtime/dashboard/package.json` 精确版本，`package-lock.json` 入仓）：`vite 6.4.4`、`@vitejs/plugin-react 4.7.0`、`typescript 5.9.3`、`react 19.3.1`、`react-dom 19.3.1`、`@types/react 19.3.0`、`@types/react-dom 19.3.0`。
- **审计基线：CI 跑 `npm audit --audit-level=high`，high／critical 漏洞数必须为 0。** 2026-10-19 基线实测：`found 0 vulnerabilities`。
- 选择 vite 6.4.4 而非 5.4.x 的直接原因：vite 5.4.21 在该基线下带 1 个 high（path traversal／`server.fs.deny` 绕过等开发服务器面）与 1 个 moderate（esbuild dev server）；vite 6.4.4 清零，且 `@vitejs/plugin-react 4.7.0` 声明兼容 `^6.0.0`。
- 基线被上游新披露打破时：升级钉版并重跑审计；无法清零时须修订本 ADR 记录豁免与理由，不得静默放过。

### 理由

审计基线写成「0 个 high/critical＋钉版清单」后，任何漂移都是显式事件：要么 lockfile 变化触发评审，要么审计失败阻塞 CI。

## 3. `#ticket` URL 出现在浏览器启动命令行参数中的风险（D7 配套）

> 本节为完整风险文本（风险、缓解、残余风险）。**文本在 PR-1 结案；缓解措施的代码实现（终端不打印 ticket、短时一次性 ticket、读后即毁）属 PR-2**，验收归属见 `ai/tasks/v2.1.0-rc.2-r2.0a-dashboard/task.md`「拆分决定」。

### 风险

D7 锁定：启动时自动打开带一次性 ticket 的 URL fragment（`#ticket=…`）。操作系统层面，启动浏览器进程的**命令行参数**包含该完整 URL；同机其他进程（同 UID 通常即可读，如 Linux `/proc/<pid>/cmdline`，macOS／Windows 的等价进程枚举）可在浏览器进程存活期间读到 ticket。fragment 不进 HTTP 请求与服务器访问日志，但**命令行参数不受 fragment 语义保护**。

### 缓解（PR-2 实现）

1. **终端永不打印含 ticket 的 URL**：ticket 只经自动打开的浏览器 fragment 传递，不落终端回滚缓冲区与 shell 历史（D7）。
2. **ticket 短时且一次性**：与本次 `serve` 进程绑定，短时过期；配对换取 session 后立即销毁（读后即毁），被旁观窃取后的可用窗口极短且用后即废（D7；ADR 0001 §5）。
3. **日志不记 ticket 值**：服务器日志只记配对成功事件，不记 ticket 本身（grill-r1.md Q3c-A）。
4. fragment 不进入 HTTP 请求，页面配对成功后立即从地址栏与浏览器历史移除（§10.2 明文允许的路径）。
5. 无浏览器环境（SSH 等）走备用路径：ticket 写 `SBTD_RUNTIME_HOME` 下 0600 临时文件由用户手动配对，不经命令行（Q3c-B 保留）。

### 残余风险（如实记录，不消除）

- 从浏览器进程启动到前端完成配对并销毁 ticket 之间存在一个**不可消除的时间窗**；窗口内同机可枚举进程参数的进程能读到 ticket。缓解 2 把窃取后的可利用性压缩到「窗口内＋未被使用」，但不能归零。
- 长期 session Bearer 不进入 URL／日志／导出（ADR 0001 §5），因此本风险面仅限一次性 ticket，不扩散到长期凭证。
- 该风险为 D7 已锁定交付路径的固有属性；若未来要消除，须改用不经命令行的交付通道（如 Q3c-B 文件配对为默认），属独立决策。

### R2.2 PR-2 验证注记（2026-10-23）

- 既有决定与风险文本不变。本轮测试在未修改生产代码时通过，为既成实现的 characterization；不是新的交付通道或安全契约。
- 缓解 1／3：`sbtd-runtime/tests/test_serve.py:313` 的 `PairingTests.test_pair_once_only_and_ticket_never_in_output` 启动真实 serve 子进程，以既有 `--no-open`／0600 文件 seam 取得临时 ticket，完成成功配对、重复／错误配对与 Bearer 鉴权读取；捕获 stdout、stderr、导入 serve 前启用的 Python DEBUG 日志及 runtime home 下日志文件，断言 ticket、错误 ticket、session Bearer／CSRF 不出现，且无 `#ticket=` URL。DEBUG marker 验证 stderr 与日志文件捕获有效；断言失败也不回显凭证值。
- AC-56 关联证据：`sbtd-runtime/tests/test_renderer_integration.py:1017` 的 `HostOriginSecurityTests.test_rejected_origins_cannot_pair_read_or_create_exports` 经真实 loopback HTTP 验证外部域名 Host、Host 错端口、Origin 错端口、跨 Origin 在配对／私有 GET／createExport POST 均返回 403，仅有通用拒绝体、无 CORS allow header、无 export job／文件；被拒配对不消耗合法 ticket。
- 证据边界：本轮为 Linux backend-only，未执行真实浏览器自动打开、进程参数枚举或跨平台验证。`--no-open` 证据不宣称消除浏览器启动路径风险；从浏览器启动到配对销毁之间，同机有权限枚举进程参数者仍可能读取 ticket，存在不可消除的时间窗。macOS／Windows 与用户 Mac 证据由 R2.2 PR-3 承担。
