# ADR 0003：R2.0c ReportSnapshot 落盘格式与保留

> 状态：accepted
> 日期：2026-10-20
> 范围：plan.md R2.0c、grill D13 / Q6c-A / R1e、PRD §10.4。仅新增本决策，不改变 ADR 0001/0002、OpenAPI、Panel manifest 或 PRD。

## 1. 文件格式

路径为 `$SBTD_RUNTIME_HOME/snapshots/snap_<32 个小写十六进制字符>.json`，ID 由随机 UUID4 生成，不接受任意路径。目录 0700、文件 0600（沿用 runtime POSIX 约定；Windows ACL 的平台证据仍属 R2.2）。拒绝 symlink/junction 路径及非普通文件；不通过清扫递归遍历目录。

文件为 UTF-8 JSON object，恰有三个字段：

- `format_version`：整数 **1**，不得按 boolean 或未知版本解读。
- `checksum`：字符串 `sha256:<64 个小写十六进制字符>`。
- `snapshot`：Snapshot 的全部数据字段，包含 public_view、raw_scope、dataset、rows、dataset_fingerprint；不存 Python datetime `expires_instant`（由 `expires_at` 重建）。不使用 pickle 或动态类型反序列化。

校验和算法固定 **SHA-256**，输入为 `snapshot` canonical JSON 的 UTF-8 字节：`json.dumps(payload, ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False)`。外层 envelope 不参与 hash；读取必须先校验准确版本、结构及 checksum，再构建 Snapshot；文件 ID 必须与 payload ID 一致。重复 JSON key、非有限数、缺字段、截断、checksum 缺失／不匹配、未知版本均拒读，不作为有效快照。SHA-256 检测意外损坏，不承诺抵御同机管理员重写文件与 checksum。

## 2. 原子发布与恢复

写入同一 snapshots/ 下唯一 `.snapshot-*.tmp`（0600），完整写入后 flush、fsync 文件，再 `os.replace` 原子发布最终文件；POSIX 上 fsync snapshots/ 目录。只有完成写路径后才向调用者返回成功、加入可复用内存索引。I/O 错误向上抛出，不假报保存成功。失败清理只删除本次创建的 temp；进程被杀遗留 temp 不可被读取成快照，启动不将 temp 自动升级为正式文件。

启动枚举仅 snapshots/ 的合法文件名，验证后装载并清扫已过期且无引用的快照（完整载荷的启动驻留方式已由 §6 修订）。损坏／未来版本／未知文件／遗留 temp／链接／嵌套目录原样保留；拒读结果为 SnapshotNotFound，不静默重建同 ID。原始 audit.db 不变，可重新查询生成新 ID。未来版本拒读而非自动降级或迁移；回滚旧实现不删除新文件，但旧内存实现无法读取它们。

## 3. TTL 与引用

默认 TTL **86400 秒（24h）**，绝对 UTC `created_at` / `expires_at` 写入 payload。读取重启不续期；创建／复用返回 expires_at，statistics/query 与 timeseries 使用现有开放 Envelope data 返回该字段，既有 public_view 字段不变。过期不得复用旧 ID。已装载的过期 ID 返回 SnapshotGone；清扫删除后跨重启无永久 tombstone，返回 SnapshotNotFound。

`SnapshotStore(home, ..., pinned_snapshot_ids=...)` 必须在 startup sweep 之前安装恢复引用。`pin(snapshot_id)` 先检查仍可读，再持引用并返回快照；`release(snapshot_id)` 释放一个引用，最后引用释放后恢复正常 TTL。多引用计数；过期但仍被引用时 get/dataset_page 继续可读，sweep 不删除。pin/release/sweep 在同一 store 内串行化；serve 实例锁保证单 runtime writer，不支持多个独立服务同时管理同一目录。

R2.0b 的前端 PinRegistry 仅固定取数 ID，不会跨 HTTP 自动创建磁盘保活。R2.1a 作业接收该固定 ID 时，须在开始取数前调用共享后端 store.pin，并在完成／取消／失败的 finally 中 release。若 R2.1a 支持作业重启恢复，先从自己的作业事实源恢复所有引用，再作为 pinned_snapshot_ids 注入 SnapshotStore，最后开放请求；进程内 pin 本身不是持久作业记录。本任务不实现 exports、作业恢复或新 API。

## 4. 清理授权边界

§4／§5 按 rc.2 计划第 4 项、PRD §10.4（[#156](https://github.com/KunoLu/640-skills/pull/156)）及用户 2026-10-21 12:58 +08:00 决定修订，以下为 R2.2 待实现的清扫与配额规则。

自动清扫授权来自 **PRD §10.4 临时 ReportSnapshot／导出临时副本行 + 用户锁定 D13 与上述磁盘上限决定**，独立于 AC-61。Query & Snapshot 负责 snapshots/ 内有效快照，Export 负责 exports/ 内有效导出及其 manifest；共享配额不合并两者的数据所有权，不能用 AC-61 宣称本项通过。

**计量范围。** 仅在已验证归属、非 symlink／junction 的 `$SBTD_RUNTIME_HOME/snapshots/` 与 `exports/` 内计量。实际布局是扁平文件：`snapshots/snap_<32 个小写十六进制字符>.json`；`exports/exp_<32 个小写十六进制字符>.bin` 与同 ID 的 `.json` manifest，不是每个 export 一个子目录。分别枚举两目录的直接子项，以不跟随链接的 `lstat` 判型，将每个普通文件的 `st_size` 相加为共享已占用字节数 U；不采用 manifest 自报字节数或文件系统分配块数，不按 inode 去重。有效、过期、被引用、损坏、未知／未来版本文件、孤立 `.bin`／`.json` 和所有临时普通文件（含在途写入）均计入。symlink／junction、其他非普通项及目录本身不计入，亦不跟随、不打开设备或 FIFO；实际布局无嵌套产物，意外子目录不递归，其内部文件不纳入该扁平存储配额，也不删除。计量失败不得把未知占用当作零并继续新建。

**可删除集合。** 删除前复核目录身份、普通文件身份与所有权；硬链接多引用、链接／reparse point 或身份变化均不删。

- 快照：仅合法文件名、当前版本／结构／checksum／ID 均有效，已到 `expires_at` 且后端 pin／引用计数为零者。
- 导出：仅同 ID 的 `.bin` + `.json` 成对校验通过，manifest 为 ready、版本／checksum／产物摘要与字节数有效，已到原始 `expires_at` 且无在途作业／读取引用者。只删除这两个已验证文件；不得把缺 manifest 的孤立产物当作过期 ready 导出，也不递归删除所谓 export 目录。
- 残留 temp：仅 snapshots/ 的 `.snapshot-*.tmp` 与 exports/ 的 `.export-*.tmp` 普通文件。取得单 writer 实例锁、恢复引用且尚未开放新写入时，既有匹配 temp 才可判为前一进程残留；运行期间由当前进程登记每次 temp 创建至 rename／失败清理完成的在途所有权，登记／发布／清扫串行化，仅不在该在途集合且可确认属于上述写路径的 temp 才是残留。不凭 mtime、年龄或“不是 ready”猜测；归属或在途状态不能确认则保留并计量。匹配且已确认归属的半写 temp 是可识别的写入残留，不要求通过成品 JSON 校验；不把任意坏文件改判为 temp。

**执行顺序与准入。** 保留 §2 的启动清扫；本节的已确认残留 temp 清理取代 §2 原有“遗留 temp 原样保留”，不改变 temp 永不自动升级、坏文件／未来版本保留的规则。启动及每次新建快照或导出前复用同一规则，不加后台定时器：

1. 校验两个自有目录与单 writer 所有权，先安装恢复引用并保护当前在途写入；清扫与引用／写入状态变化协调，不能只依赖两个互不协调的 store 锁。
2. 清掉已验证、过期且无引用的 ready 导出对，再清掉已验证、过期且未 pin／无引用的快照，再清掉上述可确认的残留 temp。删除失败的文件保留，其实际剩余字节仍计入；不因容量压力扩大删除集合。
3. 清扫完成后重新枚举计量 U，以 §5 的共享上限 L 判定：`5 × U >= 4 × L` 时预警（达到 80%，含仍超限情形）；`U > L` 时拒绝本次新建，明确错误包含当前已占用字节数与上限。错误码字符串、HTTP 状态及错误体由独立 contract PR 定义，本 ADR 不发明；预警呈现渠道归 R2.2 实现，本节只固定触发阈值与时点。
4. 仅通过上述准入后才开始本次新建／接受新导出作业；拒绝时不创建该次文件或作业。该判定针对清扫后的现有占用，不是对尚未生成产物大小的预留，也不承诺写入期间绝不瞬时越限；下一次新建仍须先清扫再判定，不以越限为由回删未过期数据。已有 ID 复用／幂等回放不是新建，不在此重定义其契约优先级。

**永不自动删除。** 未过期或仍被 pin／引用的快照，在途、未过期或仍被引用的导出，损坏／未知／未来版本成品，归属不明文件，symlink／junction、其他非普通项与意外目录均保留；普通文件仍按上述范围计量。清扫不触及 snapshots/、exports/ 以外任何位置，包括 audit.db、registry/config、spool、数据库备份、浏览器下载副本、源 task.md、报告与 handoff；不递归、不跟随链接。Export 清理仍须独立验收，不能用快照验收或 AC-61 替代。

## 5. 验证与权衡

沿用标准库 JSON/hashlib/tempfile/os，无新依赖、后台定时器或数据库迁移；新增唯一配置面 **`SBTD_RUNTIME_DISK_QUOTA_BYTES`**，与存储根 `SBTD_RUNTIME_HOME` 同属 runtime 环境变量族，作用于 snapshots/ + exports/ 的共享字节上限，不作用于 audit.db 或整个 runtime home。

`serve` 启动时读取一次，在清扫／接收请求前完成解析，进程内不热更新。未设置时取默认 **2,000,000,000 字节**：PRD 的“2 GB”采用十进制 GB（10^9），不暗换为 2 GiB（2,147,483,648 字节）。设置时仅接受 ASCII 十进制数字串 `[0-9]+`，按字节解析为正整数（允许前导零）；不接受单位后缀、小数、指数、正负号或任何空白。空串、格式非法、零或负数均明确报配置错误并拒绝启动，不静默回退默认值、不解释为无限额；错误说明变量名与合法格式，不回显原始值。无法精确表示的值同样拒绝，不能截断／溢出。

SnapshotStore 仍要求显式 runtime home，测试使用独立 TemporaryDirectory，不写用户 HOME。启动验证装载有效快照并沿用内存复用索引；本次只决定磁盘准入与清扫规则，不新增内存淘汰策略（启动完整载荷驻留与内存淘汰策略已由 §6 修订）。启动必扫，每次新建前再扫，仍可显式调用；没有定时器，不承诺服务运行期间恰好 24h 即物理回收。未知／损坏文件计入而不删可能持续阻止新建，这是保护未知数据的取舍，不允许自动清空来恢复服务。默认容量的实测校准与全部实现归 R2.2；本次 ADR 修订不表示现有 runtime 已执行配额。

既有永久测试覆盖重启后原 ID／数据／cursor、有效期返回、三类损坏及 checksum 篡改、fsync/rename 故障不发布半成品、过期清扫仅自有目录、pin 与恢复引用、0700/0600、路径／链接拒绝。R2.2 须补齐共享计量（含 manifest、坏文件与在途 temp）、80%／恰等上限／超过上限、配置解析与启动拒绝、两类创建前清扫顺序、在途 temp／引用保护、孤立产物保留、删除失败后重计量及越界路径不删除的验证；真实 serve smoke 独立于单测。平台范围仅实际执行环境，跨平台断电耐久性与 Windows ACL 不冒充已验证。

### 6.1 完整缓存与轻量索引

- 内存完整快照缓存最多保留 **8 份完整快照**，按最近成功访问排序；成功创建／发布或读取后更新 LRU，超额时逐出最久没用的项。操作结束后完整缓存不超过上限，失败不发布半个缓存项。
- 逐出只断开缓存的内存引用，**绝不删除磁盘文件**，不释放磁盘配额，也不能作为删除未过期文件的理由。
- 完整缓存与轻量索引分离。索引仅保存 ID、`expires_at`、`query_hash`、`dataset_fingerprint` 等复用／清扫必需字段，不持有 `dataset`、`rows`、`public_view` 或另一份完整载荷。
- 启动只建立这个小的内存索引：仍逐个打开合法文件并完整校验，每次处理完不保留完整载荷；完整缓存启动为空。不跳过 checksum，不承诺减少启动磁盘读取总量，不新增磁盘 manifest。
- 上限是**条数**，不是字节或 RSS 上限。轻量索引和 `_gone` 不计入 8 条，仍可能随 ID 数增长；单个大快照、校验中的临时对象、在途读者及返回副本也会占内存，进程总内存不承诺恒定。
- 上限可通过内部正整数参数覆盖，仅供隔离测试；**不是产品可配置项**。不加环境变量、CLI 或配置文件，`serve` 固定使用默认值 8；将来公开配置须另作决策。

### 6.2 冷读、安全检查与复用

- `get`、`dataset_page`、`pin` 及复用遇到缓存未命中时，从磁盘按受控 ID 路径重新加载；执行现有目录／普通文件／所有权／链接检查、同一 fd 身份复核、版本／结构／checksum／ID 校验，全部通过才入缓存。不能因不在 LRU 就返回 404 或 410。
- 热读保留现有文件身份检查；文件变化仍需重新校验，缺失或损坏时失效完整缓存与校验项，拒绝返回旧载荷，不删除坏文件。
- `_validated` 随完整缓存项一起逐出，不能留下“文件身份命中但完整对象不存在”的条目，也不另建第二份完整快照缓存。
- 复用按 `query_hash`／`dataset_fingerprint` 从轻量索引找未过期候选，再读盘核验；淘汰不能迫使同一查询生成新 ID 或多占磁盘。新建仍在 temp 写入、fsync、原子发布成功后登记索引与完整缓存，I/O 失败沿原错误路径返回。

### 6.3 不变的生命周期、清扫与并发

- 24 小时过期仍从原 `created_at` 起算；重启、缓存命中、逐出或重载均不延长 `expires_at`。分页与 cursor、原 ID 的数据／导出、404、410、pin 及 507 磁盘配额语义全部不变。
- 有效且未过期的被逐出快照仍可读；已知过期且未 pin 返回 410，缺失／坏文件返回 404；沿用进程内 `_gone`，不新增跨重启永久 tombstone。过期快照不参与查询复用。
- pin 保护磁盘生命周期，不要求完整快照常驻内存；被 pin 的载荷也可逐出，重载后仍可跨过期读取。引用计数、恢复引用先于启动清扫、最后 release 后恢复正常 TTL 判断的顺序不变；前端固定 ID 不等于后端 pin。
- **现有 sweep 已会删除已验证、过期、未 pin 的快照文件并移出内存，即这些过期快照已被逐出；本节新增的是未过期快照的条数上限。** sweep 改为遍历轻量索引，而非仅遍历 LRU；先按过期时间与 pin 筛候选，删除前仍完整校验并复核文件身份。
- 清扫冷快照使用临时对象，不污染 LRU；成功删除后同步移除索引、完整缓存、校验项并保留原 Gone 语义。删除失败保留候选；坏文件、未知版本、未知文件和链接不因内存压力被删除，仍沿用 §4 的计量／保留规则。
- 启动及新建准入前清扫的时机不变，不加后台定时器，不承诺恰好第 24 小时物理删除。共享磁盘配额、80% 预警与 507 拒绝规则不变。
- 沿用现有共享锁协调索引、LRU、校验、pin／release、发布与 sweep。读者已持有的对象不因淘汰被清空或原地改写；`get` 深拷贝完整快照、分页深拷贝返回页的隔离不变，不借此移除 `deepcopy`。

### 6.4 风险、验证与回退

- 8 条可能导致多标签页／多查询反复冷读，共享锁内冷读可能增加等待；不通过跳过安全校验或另设锁来掩盖该取舍。释放 Python 引用不等于 RSS 立即下降。
- 实现 PR 须覆盖小容量 LRU、超过 8 份的重启索引／冷读、原 ID 与分页／cursor／导出一致性、复用不增文件、冷／热读安全拒绝、TTL／pin／release、冷快照清扫与删除失败、507 以及并发读者隔离；本轮文档验证不替代这些实现证据。
- 磁盘格式与 checksum 不变，不迁移既有文件。回退代码可继续读取现有快照文件并恢复全量驻留；**不删除快照**，不以回退为由清空磁盘数据。
