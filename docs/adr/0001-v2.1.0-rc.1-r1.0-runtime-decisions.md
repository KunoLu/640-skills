# ADR 0001：v2.1.0-rc.1 R1.0 Runtime 决策

> 状态：accepted
> 日期：2026-10-16
> 范围：`v2.1.0-rc.1`（仅 R1 Runtime API）的 **R1.0 数据与权限契约**
> 确认：2026-10-16 群内投票一致，并经用户确认。同日用户选择「补上」，将 PRD §7.2「组件真实调用」纳入 Q4 rc.1 核心子集。
> 相关：[PRD v0.2](../prd/SBTD_Runtime_API_and_Local_Dashboard_PRD_v0.2.md) §19.3、§15、§7、§8.2、§10、§14.3、AC-56

本 ADR 只记录已经确认的 R1.0 决策。它不实现代码，不改 `task.md` 事实源，也不把 Dashboard／四格式导出提前纳入 `v2.1.0-rc.1`（PRD §15.0）。§19.3 里 renderer 包分发、长图／CSV 规模、OMP 视觉复用仍按原表时机固定，不在本文结案。

## 1. Q1 代码放置：独立可选 runtime 扩展

### 背景

PRD §19.3 将「代码放置／打包」列为 R1.0 必须用 ADR 固定的事项，默认建议是：独立可选 runtime 扩展，兼容原 scripts，避免大范围移动既有文件。§15.1 的 R1.0 是数据与权限契约；§15.2 把 ADR 列为 R1.0 产物。§1.1 约定既有 onboard／TaskStore／TaskRouter 脚本在 `sbtd-workflow-onboard/scripts/`，仓库根没有实现这些脚本的 `scripts/`。§1.3、§3.3 已将观察与 HTTP 服务定义为可选、显式启动的能力，建议入口是 `sbtd-runtime serve`，且不得伪装成任务 journal 或后台调度。§4.2 要求现有脚本导入保持兼容；具体 Python 模块路径仍由后续实现 ADR 固定，本文不提前拆内部包结构。

### 决策

**A。** 新增顶层目录 `sbtd-runtime/`，作为独立可选 runtime 扩展。公开入口为 `sbtd-runtime serve`。兼容既有 `sbtd-workflow-onboard/scripts/`，不移动既有文件。

### 理由

rc.1 只交付 R1。把可选 HTTP／采集扩展放进既有 onboard 脚本树，会把「显式启动的观察服务」和「安装／任务状态机」绑在同一目录，增加误装、误调度和路径约定破坏的面。独立顶层目录保住 §1.1 的路径约定和 §4.3 的关闭观察后原工作流等价。不新开仓库，是因为契约、Gate 和验收仍属于 640-skills `v2.1.0`，拆仓会把 R1.0 的单一事实源拆开。

### 否决的备选

| 备选 | 否决原因 |
|---|---|
| **B。** 并入 `sbtd-workflow-onboard/scripts/`，随 onboard 发布 | 混淆 onboard 边界、diff 难审 |
| **C。** 独立仓库／包，rc.1 只留接口 | rc.1 无法交付可验收 API |

## 2. Q2 本地服务框架：Starlette + uvicorn

### 背景

PRD §14.3 建议 HTTP 层为轻量 ASGI，候选曾写 FastAPI，并要求通过 ADR 定案；协议用版本化 JSON Schema／OpenAPI，统计由确定性代码计算。§19.3「本地服务框架」的默认建议是 Python 轻量 ASGI + 类型化 DTO，固定时机为 R1.0。§9.1 要求本地 HTTP、`/api/v1` 与 OpenAPI。§10.2 与 AC-56 要求 loopback、Host／Origin、会话鉴权和 CSRF，框架必须能承载这些控制，而不是只提供 JSON 路由。

### 决策

**B。** HTTP 层使用 Starlette + uvicorn。DTO 使用 dataclass 与 jsonschema，不引入 pydantic 作为协议类型源。版本约束：`starlette>=1.8,<2`、`uvicorn>=0.54,<0.56`。CI Python 为 **3.12.10**。

2026-10-16 投票所引 Researchy 核验，与同日 PyPI JSON 复核一致：Starlette 1.8.0 要求 `Python>=3.11`；uvicorn 0.54.0 存在；FastAPI 0.143.2 仍为 0.x，且依赖 `pydantic>=2.9.0`。3.12.10 满足 Starlette 1.8 的 Python 下限；本 ADR 不把该复核写成已跑通的 CI。

### 理由

§14.3 要的是轻量 ASGI 和单一 schema，不是再维护一套 pydantic 模型。Starlette 1.8 已覆盖路由、中间件和请求校验所需的 ASGI 面，uvicorn 0.54 作为同代服务器即可。把上限收在 `<2` 与 `<0.56`，是为了 rc.1 不跟着未验收的大版本漂移。CI 固定 3.12.10，避免「Python>=3.11」在矩阵里被理解成任意解释器都已验收。

### 否决的备选

| 备选 | 否决原因 |
|---|---|
| **A。** 纯标准库 `http.server` + asyncio | 难承载鉴权／CSRF |
| **C。** FastAPI 0.143.x + pydantic | 仍为 0.x，有破坏性变化风险，pydantic 过重 |

## 3. Q3 运行时家目录与 registry

### 背景

PRD §10.1 建议独立、可配置的 `SBTD_RUNTIME_HOME`，默认用户 HOME 下 `.sbtd-runtime/`，其中 `registry.json` 保存项目／主体／设备映射，且为用户私有；该目录不同于项目 `.sbtd/` 和 OMP／Codex 私有目录，不覆盖已有 HOME 资产。§19.3「身份和项目映射文件」的默认建议是用户私有 registry，不默认写项目 tracked 文件，固定时机为 R1.0。§0.2、§5 仍以 `task.md` 为任务 mode／status 事实源；registry 不是第二任务库。

### 决策

**A。** 使用 `SBTD_RUNTIME_HOME`。默认路径为 `~/.sbtd-runtime/registry.json`。该文件属于用户私有数据，不写入项目 tracked 文件。

### 理由

项目仓库里的 tracked registry 会把本机项目映射和主体别名推进 Git，和 §10.3 的敏感信息最小化、§2.2 的不默认建立身份相冲突。放在可配置的用户目录，才能同时满足「多项目索引」和「不改业务仓库」。默认文件名沿用 §10.1，避免 R1.0 再发明一套布局。

### 否决的备选

| 备选 | 否决原因 |
|---|---|
| **B。** 项目 `.sbtd/` 下并 gitignore | 易误入仓库，身份信息不应进项目 |
| **C。** 在 A 上加项目级可选覆盖 | rc.1 不需要，增加泄漏面 |

## 4. Q4 rc.1 指标只做核心子集

### 背景

PRD §7.2 第一阶段最小采集集要求端到端覆盖：task 状态变化、执行轮次起止、步骤起止、组件真实调用、Gate 适用性和结论、测试执行及证据状态、采集健康。组件真实调用指 Skill 与 Tool 的实际调用统计。模型 token／费用是条件性字段：来源提供则采集，不能因此阻止主功能验收，但缺失必须可见，且不得填 0。§8.2 要求每个指标具备 `metric_id`、中文名称、单位、粒度、过滤、分母、空值策略、版本和来源要求，并列出完整目录。§19.3「精确指标 schema」写明以本文目录为初版，字段与计算代码同版本发布，时机为 R1.0–3。§15.0 规定 `v2.1.0-rc.1` 只验收 R1，不能用未实现指标的 0 或 mock 数字充当完成。

2026-10-16 投票先点名：task 状态、执行轮次、步骤、Gate、测试证据、采集健康。同日用户选择「补上」，把 §7.2「组件真实调用」加入该核心子集。token／费用不升为必做项。

### 决策

**B，并经同日用户确认补入组件真实调用。** `v2.1.0-rc.1` 必做指标为核心子集：task 状态、执行轮次、步骤、组件真实调用、Gate、测试证据、采集健康。组件真实调用是 Skill 与 Tool 的实际调用统计，不再标 `unsupported`。§8.2 其余未纳入核心子集的指标保留在 schema 中，并标 `unsupported`。未实现指标不得返回 0、空成功率或「未观察到」来冒充已计算。

对照 §8.2 时按类别划界，不另造 `metric_id` 允许清单；具体 ID 仍以 §8.2 表为准。组件真实调用对应表中 Skill／Tool 实际调用的行，不是「已安装」或「已载入」。载入不等于调用（§0.3、AC-09）。

token／费用仍是条件性字段，不在必做子集。按 §7.2、§8.2 与 §8.3：来源提供则采集；缺失必须可见标注，不填 0，也不显示成「免费」。缺 token／费用不阻断 rc.1 主功能验收。

### 理由

R1.0 要固定名词、分母和 schema 边界，但 rc.1 不把 §8.2 全目录都变成阻塞验收的计算。核心子集覆盖 §7.2 主路径里已经点名并经同日补入的类别，使 R1.4 可以在没有 UI 时验收任务、轮次、步骤、Skill／Tool 实际调用、Gate、测试证据和采集健康。其余指标留在 schema 里，是为了满足 §19.3「字段与计算代码同版本」：字段可以先存在，计算未实现时必须显式 `unsupported`，而不是从协议里消失后再破坏兼容。token／费用保持条件性，避免把用量完整性做成 rc.1 阻塞项，同时不许用 0 掩盖缺失。

### 影响

- 组件真实调用进入 rc.1 必做子集。验收不能再把它排除，也不能整类标 `unsupported`。
- 单一宿主拿不到结构化事件时，只影响该宿主的 capability matrix（见 Q6），不把该类别从必做子集删除。
- §8.2 未纳入核心子集的行仍标 `unsupported`，不得从 schema 删除，不得用 0 冒充已计算。
- token／费用不进入必做子集；缺失可见且不为 0。提供了来源字段时按 PRD 采集，不用「字段不存在」吞掉已有值。

### 验收

- 核心子集的查询与 schema 支持标记必须包含组件真实调用。Skill／Tool 实际调用不得以 `unsupported` 作为 rc.1 的类别结论。
- 宿主证据不在本节用 parser fixture 代替。`codex@0.163.0` 与 `omp@18.11.1` 的分宿主真实 smoke 见 Q6。
- token／费用样本：有来源则保留；缺失必须可见标注，数值不为 0。该缺口不单独否决其余核心子集。

### 否决的备选

| 备选 | 否决原因 |
|---|---|
| **A。** §8.2 全目录一次做齐 | 验收面过大，strict Gate 难以逐项证明 |
| **C。** 在 B 上加条件性 token／费用字段 | rc.1 不纳入；token／费用仍按 PRD 为条件性字段，缺失可见 |

## 5. Q5 本地会话与凭证

### 背景

PRD §10.2 要求服务只绑定 loopback，禁止默认绑定 `0.0.0.0`；Host／Origin 白名单拒绝外部域名和 DNS rebinding；浏览器用短时一次性配对凭证换本地会话，长期 token 不得进入 URL、浏览器历史、日志或导出；API 使用会话／Bearer，修改配置、refresh、export 使用 CSRF／Origin 防护。§19.1 将「本地 API 被恶意网页访问」的应对写为 loopback + Host/Origin + 鉴权 + CSRF + 最小 scope。AC-56 的验证方式是 CORS、Origin、CSRF、Host／DNS rebinding 测试。§10.1 的凭证与运行时状态属于 `SBTD_RUNTIME_HOME`，不是项目文件。

### 决策

**A。** 短时一次性配对凭证换取本地 session／Bearer。长期 token 只存放在 `~/.sbtd-runtime/`，Unix 权限 **0600**，不进入 URL 或日志。服务保持 loopback，并做 Host／Origin 校验与 CSRF。该组合用于满足 AC-56。

0600 是本决策对 Unix 权限的固定值。它不撤销 PRD §10.2 的 Windows ACL 要求，也不把 0600 解释成 Windows 上的唯一控制。

### 理由

长期 token 一旦出现在 URL 或日志，AC-56 的「外部网页不能读本地 API」就会在本机历史和诊断输出里失效。一次性配对再换会话，把浏览器持有的秘密限制在短时票据。文件放在用户运行时目录并收紧到 0600，避免项目仓库、导出包和进程参数成为第二份凭证存储。loopback 单独不够，§10.2 已写明不能因「请求来自本机」信任网页来源，所以 Host／Origin 与 CSRF 同为 R1.0 权限契约，而不是 R2 UI 完成后再补的测试。

### 否决的备选

| 备选 | 否决原因 |
|---|---|
| **B。** 固定 Bearer token 文件，不配对 | rc.2 需再改鉴权契约 |
| **C。** 仅 loopback + Origin，不鉴权 | 不满足 AC-56 |

## 6. Q6 验收宿主版本

### 背景

PRD §19.3「采集器版本矩阵」的默认建议是：对目标 Codex／OMP 实际版本做能力探测，并明示 unsupported。该表把固定时机写成 **R1.2**。§15.2 R1.2b 的产物是宿主 capability matrix 与结构化回执，完成门包括两宿主真实 smoke，以及不支持能力如实标记。§15.0 的 rc.1 完成门包含 R1 工作包，因此验收所依据的宿主版本需要在实现开始前写死，而不是等探测脚本跑完再解释。本文不修改 §19.3 表格单元格，只把投票结果固定为 R1.0 决策。

### 决策

**C。** 验收门禁固定为 `codex@0.163.0` + `omp@18.11.1`，写入 capability matrix。其他版本标 `unsupported`。另加 CI 最新版探测，只报告，不阻塞。

这两个版本号是 2026-10-16 投票确认的门禁针，不是本 ADR 对宿主发行包的独立执行证明。非门禁版本标 `unsupported` 不取消 Q4 对组件真实调用的必做要求；门禁版本若拿不到结构化调用事件，只按下面的验收标记该宿主。

### 理由

rc.1 若接受「当前最新版」作为隐式门禁，能力矩阵会随宿主发布漂移，R1.4 无法判断失败来自产品还是来自未声明的宿主版本。固定一对版本，其他版本一律 `unsupported`，符合 §15.2b「不支持能力如实标记」。CI 探测最新版只报告、不阻塞，保留漂移可见性，同时不把未投票的版本升格为验收门禁。相对 §19.3 表内的 R1.2 时机，本次是提前在 R1.0 固定门禁版本；R1.2b 仍负责真实 smoke 与矩阵产物，不把探测本身变成第二套通过标准。组件真实调用的通过标准是分宿主真实 smoke，不是共享 parser fixture：PRD §7.1 不预设 Codex 与 OMP 的 hook／日志字段相同。

### 验收

`codex@0.163.0` 与 `omp@18.11.1` 分别验收。不得用一个宿主的字段形状、日志样本或 parser fixture 代替另一个宿主。

| 宿主 | 真实 smoke |
|---|---|
| `codex@0.163.0` | 通过条件：真实 smoke 采到 Skill／Tool 调用事件（Skill 或 Tool 至少一种）。parser fixture 不能代替。未满足时仅该宿主标 unsupported。 |
| `omp@18.11.1` | 通过条件：真实 smoke 采到 Skill／Tool 调用事件（Skill 或 Tool 至少一种）。parser fixture 不能代替。字段以该宿主实际 hook／日志为准，不假定与 Codex 相同。未满足时仅该宿主标 unsupported。 |

某宿主的上述固定版本拿不到结构化调用事件时，仅该宿主在 capability matrix 标 `unsupported`。不把另一宿主、非该项能力或 Q4 的指标类别一并标成 `unsupported`。未跑该宿主真实 smoke、或只用 parser fixture，都不能当作「拿不到结构化事件」的证据。

兜底完成门：至少一个上述宿主在真实 smoke 中采到 Skill 或 Tool 调用事件，组件真实调用才算 rc.1 完成。若两个宿主都只能标 `unsupported`，R1 完成门不通过，须回到用户重新决策，不得放行。

### 否决的备选

| 备选 | 否决原因 |
|---|---|
| **A。** 只固定基线，无最新版探测 | 无法感知上游变化 |
| **B。** 每次对最新版探测，不固定 | Codex 更新频繁，门禁持续漂移 |

## 7. 本 ADR 不改变的边界

- `task.md` 仍是任务 mode／status／history 的事实源。registry、指标投影和会话凭证都不是任务状态机。
- 关闭观察或未启动 `sbtd-runtime serve` 时，既有 SBTD 工作流仍可用。本文不新增开机自启或 daemon。
- R2 的 Dashboard、导出、renderer 与 OMP 视觉复用不在 `v2.1.0-rc.1` 完成门内。
- 事件去重、SQLite WAL、spool 与历史导入仍以 PRD §5–§10 为准。本文只固定家目录、registry 归属、rc.1 指标支持范围和凭证落点，不另写一套存储设计。
